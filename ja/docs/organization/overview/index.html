組織

組織は、Casdoor がユーザーとアプリケーションを管理する単位です。組織にサインインしたユーザーは、再度サインインせずにその組織のすべてのアプリケーションを開くことができます。

application や provider で選択した組織により、どのユーザーがアプリケーションにサインインできるか、およびプロバイダーがどこで利用可能かが決定されます。

Casdoor 管理コンソールの User Management > Organizations で組織を編集します。編集ページには Basic、Password type、Account items、Advanced のタブがあります。このページでは一般的な設定について説明します。このセクションの他のページでは、account page、password complexity、password obfuscator、theme、MFA items、groups、および監査ログの records について扱います。LDAP も組織ごとに設定します。LDAP を参照してください。

組織のサインインページ​

ユーザーは通常、アプリケーションを通じてサインインします。/login/<organization-name> にある組織のサインインページでもサインインできます。例えばデモサイトでは: https://door.casdoor.com/login/casbin です。

ユーザーがこの URL を通じてサインインすると、Casdoor は組織を記憶します。セッションが期限切れになると、Casdoor は同じ組織のサインインページにユーザーを戻します。

組織名​

Casdoor が内部的にこれらの名前を使用するため、組織の名前を admin または app にすることはできません。これらのいずれかに作成またはリネームしようとすると、the organization name: <name> is reserved エラーが発生して失敗します。

ダークテーマでのロゴ​

Basic タブで Enable dark logo をオンにすると、ダークテーマ用のロゴである Logo dark を設定できます。ページには黒い背景でのプレビューが表示されます。Casdoor は、コンソールがダークテーマを使用している場合、Casdoor 管理コンソールのサイドバーにこのロゴを表示します。Logo dark が空の場合、Casdoor は Logo を表示します。Enable dark logo をオフにすると Logo dark はクリアされます。

サインインページとサインアップページは組織のロゴを使用しません。それらはアプリケーションのロゴを表示します。Application terminology を参照してください。

言語​

Basic タブの Languages は、組織のアプリケーションのサインインおよびサインアップページの言語セレクタを、リストされている言語に制限します。Casdoor 管理コンソールのヘッダーにある言語セレクタも、組織のメンバーに対して同じ言語を表示します。Languages に 1 つの言語のみがリストされている場合、サインインおよびサインアップページはその言語に切り替わり、セレクタが非表示になります。これらのページでいずれの場合もセレクタを非表示にするには、アプリケーションのサインインまたはサインアップ項目で Languages 項目を非表示にしてください。

パスワード保存​

Password type は、Casdoor が組織のユーザーのパスワードを保存するアルゴリズムを設定します。新しい組織は bcrypt を使用します。

名前アルゴリズム説明Typical use
plain—Passwords stored in cleartext. Not recommended for production.—
saltSHA-256SHA-256 is a cryptographic hash function that produces a 256-bit value.—
md5-saltMD5MD5 is a widely used but cryptographically weak hash (128-bit).Discuz!
bcryptbcryptbcrypt hashes and salts passwords securely. Default for new organizations.Spring Boot, WordPress
pbkdf2-saltSHA-256 and PBKDF2PBKDF2 is a key derivation function resistant to dictionary and rainbow-table attacks. Use when importing users via the Keycloak syncer.Keycloak
sha512-saltSHA-512SHA-512 of the password and the salt, stored as a hexadecimal string.—
argon2idArgon2idArgon2id with the default parameters of the alexedwards/argon2id library. The hash carries its own salt. To check an imported hash, Casdoor also accepts a hash of the password followed by the salt of the user or the organization, as some systems add a pepper this way.—
pbkdf2-djangoPBKDF2 with SHA-256The Django format pbkdf2_sha256$<iterations>$<salt>$<hash>. Casdoor hashes new passwords with 260000 iterations and reads the iterations and the salt from the stored hash.Django

パスワードのソルト​

アルゴリズム salt、sha512-salt、md5-salt、pbkdf2-salt、pbkdf2-django はソルトを使用します。Password salt はソルトの出所を制御します:

Password saltSaltUse it when
SetAll users of the organization share this saltYou need hashes that are compatible with another system
EmptyCasdoor generates a random salt for each user and stores it with the password hashYou set up a new organization. This is the recommended setting, because it limits the use of precomputed hash tables

永続的なアバター​

ユーザーが GitHub や Google などの OAuth プロバイダーを通じてサインインすると、Casdoor はプロバイダーでのアバターの URL を保存します。その後、プロバイダーがその URL を変更または削除した場合、アバターは壊れます。

Use permanent avatar をオンにすると、Casdoor はアバターをダウンロードし、自身の storage provider にアップロードします。これにより URL は安定したままになります。Casdoor は、アバターが新規または変更された場合にのみアップロードします。

メールをユーザー名として使用​

Use Email as username をオンにすると、別のユーザー名なしでユーザーを登録できます。その場合:

  • サインアップ時、ユーザー名フィールドが非表示の場合、メールアドレスがユーザー名になります。
  • ユーザーがメールアドレスを変更すると、ユーザー名もそれとともに変更されます。

ソフト削除​

デフォルトでは、ユーザーを削除するとデータベースからユーザーが削除されます。

Soft deletion をオンにすると、ユーザーの削除はユーザーを「削除済み」とマークするだけになります:

  • ユーザーはユーザーリストに残り、Is deleted が選択され、Deleted time が表示されます。
  • ユーザーはもうサインインできなくなり、Casdoor はユーザーのトークンとセッションを即座に取り消します。
  • ユーザーを復元するには、ユーザーの編集ページで Is deleted をクリアします。
  • ユーザーを完全に削除するには、2回目にユーザーを削除します。

Casdoorがユーザーのトークンを失効させる場合​

以下の場合、Casdoorはすべてのアプリケーションにおけるユーザーの全トークンを有効期限切れにします：

  • ユーザーが削除された、またはソフト削除された。
  • 管理者がユーザーに対して Is forbidden をオンにする。Casdoorはまた、ユーザーのセッションも終了させます。詳細は Forbid or delete a user を参照してください。
  • POST /api/set-password を通じてユーザーのパスワードが変更される。これにはアカウントページ、ユーザー編集ページ、およびパスワード紛失ページが含まれます。

その後、ユーザーのアプリケーションでは再度サインインが必要になります。

アプリケーション間のサインイン​

Basic タブで、Enable exclusive signin across applications は、組織のユーザーがすべてのアプリケーションにわたって保持するブラウザセッションの数を制限します。スイッチがオンのときに表示される Max sessions でその数を設定します。空欄または1の場合は、現在のセッションのみを保持します。Casdoorは、ユーザーが別の組織の共有アプリケーションを通じてサインインする場合でも、ユーザー自身の組織の設定を適用します。詳細は Exclusive sign-in を参照してください。

管理コンソールの無効化​

Basic タブで Disable console をオンにすると、Casdoorを組織の一般ユーザー向けのアイデンティティプロバイダーとしてのみ使用できます。一般ユーザーがCasdoor管理コンソールにサインインしようとすると、HTTP 403、タイトル Unauthorized、テキスト "The Casdoor console is disabled for the regular users of this organization"、および Logout ボタンが表示されるページが見られます。

この設定は以下に影響しません：

  • アプリケーションのサインインページ、およびOAuth 2.0とOpenID Connect (OIDC) フロー。ユーザーは従来どおりアプリケーションにサインインできます。
  • 組織管理者とグローバル管理者。彼らはコンソールを使用できます。
  • MFA設定ページ (/mfa/setup)。これにより、ユーザーは必要なMFA方法を設定し続けることができます。
注意

Disable console の強制はコンソールフロントエンドでのみ行われます。Casdoor APIは、ユーザー自身の権限に基づき利用可能なままです。

新規アプリケーションのデフォルト値​

Advanced タブの2つの設定は、組織内で後に作成されるアプリケーションのトークン設定を埋めます。既存のアプリケーションは変更されません。

SettingDescription
Default token format (defaultTokenFormat)JWT, JWT-Empty, JWT-Custom, or JWT-Standard. Casdoor uses it for a new application that has no Token format. Empty means JWT
Default token fields (defaultTokenFields)Token fields が未設定の新規アプリケーションに対するクレーム。オプションはアプリケーションの Token fields と同じであり、他の値を入力することも可能です。空欄の場合はフィールドなしを意味します

コンソールの新規アプリケーションフォームでは、アプリケーションの両方のフィールドが空のままになるため、これらのデフォルト値が使用されます。Dynamic Client Registration を通じて作成されたアプリケーションにも適用されます。トークン形式については Tokens を参照してください。

トークンとレコードの保持期間​

Advanced タブの2つの設定は、Casdoorが組織のデータをどのくらいの期間保持するかを制御します。クリーンアップジョブは起動時と、その後毎日サーバー時刻の00:00にこれらを適用します。

SettingDescription
Token retention days (tokenRetentionDays)Casdoor deletes an expired token of the organization once it has been expired for longer than this number of days. 0 or empty means 30 days
Record retention days (recordRetentionDays)この日数より古い組織の records（監査ログエントリ）をCasdoorが削除します。0または空欄の場合はレコードを永久に保持し、これがデフォルトです

built-in 組織の Record retention days は、組織を持たない、または所有者が anonymous である古いレコードにも適用されます。

信頼済みデータベースホスト​

built-in 以外の組織の database syncers と Casbin adapters はインターネットアドレス上のデータベースにのみ接続でき、シンクはCasdoor自体のデータベースサーバーに接続することはできません。Advanced タブにある Trusted database hosts (trustedDbHosts) は、リストに記載されたホストに対してこれらの制限を解除します。

host または host:port エントリのカンマ区切りリストを入力します。例：10.0.0.5,db.internal:3306。ポートなしのエントリはすべてのポートに一致します。Casdoorは大文字小文字を区別せずにホスト名を比較し、IPv6アドレスの角括弧は無視します。

Trusted database hosts を変更できるのはグローバル管理者のみです。それ以外の変更はCasdoorによって無視されます。信頼されたホスト上であっても、シンクがCasdoor自体のデータベースを使用することはありません。

LDAPパスワードとRADIUS​

Advanced タブの2つのスイッチは、組織のユーザー向けに組み込みサーバーの機能を有効にします。変更できるのはグローバル管理者のみであり、どちらもデフォルトでオフです。

SettingDescription
Enable LDAP password (enableLdapPassword)組み込みLDAPサーバー は、例えばSamba向けに、ユーザーのパスワード属性 userPassword と sambaNTPassword を返します。オフの場合、LDAP attributes に記載されていてもサーバーはこれらを絶対に返しませんでした。オンにすると確認を求められます：サーバーはパスワードハッシュ、または組織が平文で保存している場合は平文パスワードを公開するようになり、NTハッシュだけでサインイン可能になります（pass-the-hash）
Enable RADIUS (enableRadius)The built-in RADIUS server accepts authentication and accounting requests for the users of the organization. When it is off, the server rejects Access-Request packets and doesn't answer Accounting-Request packets. After an upgrade, turn it on for organizations that already use RADIUS

管理コンソールのナビゲーション​

2つの設定により、組織メンバーがCasdoor管理コンソールのナビゲーションで見られるページが制御されます：

SettingApplies toDefault
Admin navbar items (navItems)AdministratorsAll pages
User navbar items (userNavItems)Regular usersNo pages. Regular users see only their own account pages

各ツリーでページを選択します。例えば Applications, Providers, Resources, Keys, Products, Orders, Webhooks などです。

一般ユーザーがCasdoorホームページ (/) を開くと、Casdoorはユーザーが見ることができる以下のページのうち最初のものへリダイレクトします：

  1. Apps (/apps)
  2. Shortcuts (/shortcuts)
  3. アカウントページ (/account)

認証アプリにおけるイシューアー名​

Casdoorは、時間ベースのワンタイムパスワード（TOTP）のイシューアーとして、組織の表示名、または表示名がない場合は名前を使用します。複数のエントリーを持つユーザーは、これによってアカウントを認識できます。
