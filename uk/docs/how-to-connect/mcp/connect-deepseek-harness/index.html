Підключення DeepSeek Harness до Casdoor

Цей посібник пояснює, як підключити DeepSeek Harness (dsh), відкритий агентний фреймворк від DeepSeek, до Casdoor. dsh входить до Casdoor як AI-агент, а MCP-сервери вашої організації в Casdoor стають інструментами dsh. Кожен виклик інструменту проходить через шлюз Casdoor MCP від імені агента, який діє від імені авторизованого користувача, тому Casdoor визначає, які інструменти може викликати dsh, і записує кожен виклик.

Усе налаштовується через веб-сторінки: Marketplace Casdoor з одного боку, сторінка плагіна та сторінка Casdoor всередині dsh з іншого. Ви не редагуєте cordis.patch.yml чи будь-які інші файли конфігурації.

Комерційна редакція

DeepSeek Harness — це платна інтеграція з Marketplace. Вона потребує ліцензії Casdoor Commercial або Enterprise edition: без неї Casdoor не встановить її і не видасть плагін, шлюз MCP не буде обслуговувати інструменти, а плагін видалить MCP-сервери Casdoor із dsh. Див. тарифи.

Результати навчання​

  • Встановіть DeepSeek Harness із Marketplace, що створить відповідну програму та агента в Casdoor.
  • Встановіть плагін Casdoor зі сторінки плагінів dsh.
  • Увійдіть у Casdoor через dsh і виберіть MCP-сервери, які він може використовувати.
  • Визначте, які інструменти може викликати dsh, і знайдіть кожен виклик у Casdoor.

Що потрібно​

  • Інстанс Casdoor із ліцензією Commercial або Enterprise edition. У продакшені використовуйте HTTPS.
  • Адміністратор організації, користувачі якої використовують dsh.
  • Принаймі один MCP-сервер у LLM AI > MCP Servers цієї організації з синхронізованими інструментами. Див. Розміщення MCP-серверів за шлюзом Casdoor MCP.
  • DeepSeek Harness 0.2, запущений командою dsh web (або npx @deepseek-ai/dsh web), у браузері на тому самому комп'ютері.

Встановлення DeepSeek Harness у Casdoor​

  1. У адміністративній консолі Casdoor перейдіть до Identity > Marketplace і знайдіть DeepSeek Harness. Картка позначена як Commercial edition.

  2. Натисніть Install і заповніть форму:

    • Organization: організація користувачів, які використовують dsh.
    • Name: назва програми та агента, за замовчуванням deepseek-harness.
    • DeepSeek Harness address: адреса, за якою ви відкриваєте dsh, без кінцевого слешу. Локальний dsh web має адресу http://127.0.0.1:3080; будь-який порт для 127.0.0.1 або localhost працює з ним, тому dsh, запущений з іншим параметром --port, також зможе увійти.

  3. Натисніть Install. Casdoor відкриває встановлену інтеграцію в розділі Identity > Integrations, з програмою, агентом, ID клієнта та URL перенаправлення <address>/casdoor/callback.

  4. У розділі Downloads завантажте плагін, casdoor-dsh-plugin-1.0.1.tgz. Він призначений для ваших власних розгорток; не поширюйте його.

Встановлення плагіна у DeepSeek Harness​

  1. У dsh відкрийте Plugins у бічній панелі та натисніть Add plugin.

  2. Введіть повний шлях до завантаженого файлу, наприклад C:\Users\me\Downloads\casdoor-dsh-plugin-1.0.1.tgz або /home/me/Downloads/casdoor-dsh-plugin-1.0.1.tgz, і натисніть Install.

  3. Натисніть Enable now. Casdoor з'явиться у списку Installed plugins і буде увімкнено.

Без використання веб-сторінки встановіть його з терміналу та перезапустіть dsh web:

dsh plugin --profile web add /home/me/Downloads/casdoor-dsh-plugin-1.0.1.tgz

Підключення dsh до Casdoor​

  1. Поверніться до встановленої інтеграції в Casdoor і прокрутіть вниз до розділу Open the connection link. На цьому кроці перелічено адресу Casdoor, ID клієнта та секрет клієнта, а також посилання, що містить усі три значення.

  2. Скопіюйте посилання та відкрийте його в браузері, де запущено dsh. Якщо dsh працює на іншому порту, ніж той, з яким ви встановили, змініть порт на початку посилання. Відкриється сторінка Casdoor у dsh із заповненими полями. Також можна відкрити /casdoor/ у dsh і ввести їх вручну.

  3. Натисніть Save and sign in і увійдіть до Casdoor зі своїм обліковим записом. Casdoor поверне вас назад до dsh.

  4. На сторінці відображається версія ліцензії, увійдений обліковий запис та MCP-сервери вашої організації з дозволеними інструментами. Увімкнутий сервер показує статус Connected, коли dsh отримає його інструменти; вимкніть сервер, щоб забрати його інструменти у dsh.

Використання інструментів​

Попросіть dsh виконати дію, яку робить один із інструментів. Агент викликає інструмент через шлюз Casdoor MCP, і виклик з'являється у списку Called tools з його назвою, наприклад mcp__casdoor-factory-erp__get_order.

Керування викликами в Casdoor​

Визначення інструментів, які dsh може викликати​

На сторінці редагування MCP-сервера прапорець Is allowed для інструменту блокує його для всіх клієнтів. Для більш детального контролю увімкніть Tool permissions на сервері: тоді кожен виклик потребуватиме дозволу, у якому Resource type має значення MCP tool.

  1. Перейдіть до Authorization > Permissions і додайте дозвіл.
  2. Встановіть Resource type як MCP tool, а Resources — як <server>/<tool>, <server>/* або *.
  3. Додайте користувачів, групи або ролі, які можуть викликати інструменти, та додайте агента DeepSeek Harness у розділі Agents.

Коли dsh діє від імені користувача, і користувач, і агент повинні мати дозвіл на інструмент, тому dsh ніколи не отримує більше прав, ніж користувач, від імені якого він діє. Дозвіл зі статусом Deny має пріоритет. dsh показує відхилений виклик як помилку інструменту, наприклад the user: built-in/admin has no permission to call the tool: whoami.

Пошук кожного виклику​

Увімкніть Record MCP tool calls на вкладці Security організації. Після цього кожен виклик з'явиться в розділі Tool calls внизу сторінки редагування MCP-сервера разом із даними про користувача, агента, інструмент, аргументи, результат та ID трасування. Використовуйте пошук за ID трасування, щоб знайти конкретний виклик.

Налаштуйте Identity header MCP-сервера, наприклад X-Casdoor-Identity, щоб надсилати MCP-серверу короткоживучий JWT, який містить дані про користувача, його групи та ролі, агента та ID трасування. MCP-сервер перевіряє цей токен за допомогою JWKS Casdoor.

Зупинка dsh​

Перейдіть до LLM AI > Agents, відкрийте DeepSeek Harness і увімкніть Is forbidden. Шлюз відмовить агенту у наступному виклику. Щоб зупинити лише одного користувача, забороніть його обліковий запис або видаліть його токени в розділі Auditing > Tokens.

Де плагін зберігає свої дані​

Плагін зберігає підключення (адресу Casdoor, client ID, client secret), сесію (access і refresh токени та авторизованого користувача) та вимкнені вами сервери як записи у файлі облікових даних dsh .credentials.yaml у домашній директорії dsh (~/.dsh за замовчуванням). Жодних даних не додається до конфігурації dsh. Натискання Disconnect на сторінці Casdoor видаляє підключення та сесію.

Плагін запитує у Casdoor ліцензію та список MCP-серверів кожні 10 хвилин і оновлює токен за допомогою refresh token перед його закінченням.

Видалити​

  • У dsh вимкніть або видаліть плагін Casdoor на сторінці Plugins. Його MCP-сервери будуть видалені з dsh.
  • У Casdoor видаліть інтеграцію в розділі Identity > Integrations. Casdoor видалить додаток та агента. Щоб заблокувати токени, які вже є у dsh, видаліть їх у розділі Auditing > Tokens.

Усунення несправностей​

Ліцензія показує Community​

Casdoor, до якого підключається dsh, не має ліцензії Commercial або Enterprise edition, або термін дії ліцензії закінчився. Додайте ліцензію до Casdoor, потім натисніть Refresh на сторінці Casdoor у dsh.

Casdoor повідомляє, що redirect URI не дозволено​

dsh працює за адресою, яка не перелічена у додатку, наприклад, за реверс-проксі або на іншому імені хоста. Додайте <that address>/casdoor/callback до Redirect URLs додатка deepseek-harness. Адреси петльового інтерфейсу (127.0.0.1, localhost) на будь-якому порту не потребують змін.

Сторінка Casdoor у dsh повертає помилку 401​

Браузер ще не виконав вхід у dsh. Відкрийте dsh за адресою, яку виводить команда dsh web, включаючи частину ?token=, потім знову відкрийте сторінку Casdoor.

Сервер залишається у стані Connecting​

dsh не зміг отримати список інструментів через шлюз. Перевірте, чи має сервер інструменти з увімкненим прапорцем Is allowed, та чи може Casdoor отримати доступ до вихідного MCP-сервера. Шлюз звертається лише до публічних адрес, якщо у приватному розгортанні не встановлено mcpGatewayAllowIntranet = true у файлі conf/app.conf.
