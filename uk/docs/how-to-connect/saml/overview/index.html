Casdoor як open-source провайдер ідентифікації SAML 2.0 (IdP)

Casdoor є провайдером ідентифікації SAML 2.0 (IdP). Ця сторінка пояснює, що потрібно налаштувати в провайдері послуг (SP) та в Casdoor, а також які дані користувача містить SAML-відповідь. Для покрокових інструкцій щодо конкретних провайдерів послуг зверніться до інших сторінок цього розділу.

Налаштування провайдера послуг​

Зазвичай провайдер послуг запитує три значення: URL єдиного входу, issuer та публічний сертифікат IdP. Більшість провайдерів послуг зчитують усі три зі метаданих SAML IdP, через URL або із завантаженого файлу.

URL метаданих застосунку Casdoor має вигляд:

<casdoor-host>/api/saml/metadata?application=admin/<application-name>

Наприклад, для Casdoor за адресою https://door.casdoor.com та застосунку app-built-in:

https://door.casdoor.com/api/saml/metadata?application=admin/app-built-in

Щоб отримати цей URL в адмін-консолі Casdoor, відкрийте сторінку редагування застосунку, перейдіть на вкладку SAML і натисніть Copy SAML metadata URL. Щоб завантажити метадані як XML-файл, відкрийте URL у браузері.

Налаштування застосунку Casdoor​

На сторінці редагування застосунку задайте два поля:

FieldЗначення
Redirect URLsThe identifier of the service provider, which the SP calls the audience or the entity ID. Enter exactly the same value as in the SP
SAML reply URLURL служби споживача тверджень (ACS) провайдера послуг, який отримує та перевіряє SAML-відповідь. Залиште порожнім, щоб використовувати redirect binding

Прив'язка відповіді​

Casdoor може надсилати SAMLResponse через HTTP-запит POST або HTTP-запит GET. Оберіть варіант, який підтримує ваш провайдер послуг:

SAML reply URLBindingWhere Casdoor sends the response
SetPOSTTo the reply URL. The reply URL overrides the AssertionConsumerServiceURL of the SAMLRequest
EmptyGETTo the AssertionConsumerServiceURL that Casdoor reads from the SAMLRequest
примітка

Коли Casdoor сам входить користувачів до зовнішнього SAML IdP, такого як Azure AD, цей зовнішній IdP надсилає свою SAML-відповідь на ендпоінт /api/acs Casdoor. Цей ендпоінт приймає крос-доменні запити POST, тому що IdP на іншому домені може надіслати відповідь.

Ініціація входу з боку Casdoor (IdP-initiated SSO)​

При IdP-initiated SSO користувач починає сесію в Casdoor, а не в провайдері послуг. Casdoor надсилає SP SAML-відповідь, яку не запитували через AuthnRequest. Використовуйте це для посилань у порталах та закладок.

  1. На вкладці SAML застосунку задайте SAML reply URL як ACS URL провайдера послуг. Без цього вхід завершиться помилкою the SAML reply URL should not be empty for IdP-initiated SSO.

  2. Переконайтеся, що перший елемент у списку Redirect URLs — це entity ID провайдера послуг. Casdoor використовує його як аудиторію твердження.

  3. Збережіть застосунок. На вкладці SAML з'явиться поле IdP-initiated SSO URL:

    <casdoor-host>/login/saml/authorize/admin/<application-name>

  4. Натисніть Copy IdP-initiated SSO URL і надайте цей URL вашим користувачам.

Користувач, який відкриває цей URL, входить до Casdoor, і Casdoor надсилає SAML-відповідь на reply URL через HTTP-POST binding. Відповідь не містить атрибута InResponseTo, оскільки їй не передувало жодного запиту. Щоб передати RelayState провайдеру послуг, додайте його до URL як параметр запиту, наприклад ?RelayState=/dashboard.

Вихід користувачів з SP (єдиний вихід)​

Casdoor підтримує SAML Single Logout (SLO) в обох напрямках. Щоб увімкнути цю функцію, задайте SAML single logout URL на вкладці SAML застосунку як SingleLogoutService URL провайдера послуг.

Метадані застосунку оголошують SingleLogoutService Casdoor з прив'язками HTTP-Redirect та HTTP-POST за адресою:

<casdoor-backend-host>/api/saml/logout/admin/<application-name>

Кожне твердження містить SessionIndex у своєму AuthnStatement, який ідентифікує сесію Casdoor для входу.

SP-initiated logout​

Коли користувач виходить із системи на стороні SP, SP надсилає LogoutRequest до SingleLogoutService Casdoor за допомогою методів GET або POST у параметрі SAMLRequest з необов'язковим параметром RelayState:

  1. Casdoor перевіряє запит. Його Issuer має бути зазначений у Redirect URLs, він повинен містити NameID, а додаток повинен мати налаштований SAML single logout URL.
  2. Casdoor завершує сесії Casdoor, названі значеннями SessionIndex у запиті. Якщо SessionIndex відсутній, він завершує лише сесію браузера, яка надіслала запит, і лише якщо NameID належить її користувачу.
  3. Casdoor виводить користувача з інших додатків цих сесій за допомогою OIDC back-channel logout та SAML logout requests.
  4. Casdoor відповідає підписаним LogoutResponse через прив'язку запиту: перенаправленням на SAML single logout URL для GET або формою, яку браузер надсилає туди для POST.

IdP-initiated logout​

Коли користувач виходить із Casdoor через /api/logout або через /api/sso-logout, Casdoor надсилає підписаний LogoutRequest на SAML single logout URL кожного SAML-додатка, у який користувач входив у завершених сесіях. Те саме відбувається, коли Casdoor завершує сесії з інших причин, наприклад, коли користувачу заборонено вхід, або коли новий вхід перевищує ліміт сесій. Casdoor надсилає ці запити з сервера, як у випадку з OIDC back-channel logout, а не через браузер. Коли SP надсилає свій LogoutResponse на той самий кінцевий пункт SingleLogoutService, Casdoor перевіряє, що його Issuer є у Redirect URLs, а статус — Success.

Профіль користувача у відповіді​

За замовчуванням SAMLResponse містить три атрибути користувача:

Назва XML атрибутуПоле користувача
Електронна поштаелектронна пошта
Відображуване ім'яdisplayName
Ім'яname

Якщо провайдеру послуг потрібен лише NameID і не потрібні атрибути, увімкніть опцію Disable SAML attributes у додатку. Тоді Casdoor не включатиме атрибути у відповідь. Це дозволяє уникнути проблем з простором імен XML у провайдерах послуг, які суворо валідують відповідь.

Додавання SAML-атрибутів​

Якщо провайдеру послуг потрібні інші атрибути, додайте їх до таблиці SAML attributes у додатку. Значення може містити наступні змінні: $user.owner, $user.name, $user.displayName, $user.email, $user.id, $user.phone, $user.roles, $user.permissions та $user.groups.

Наприклад, наступні два рядки:

Ім'яФормат іменіValue
https://www.aliyun.com/SAML-Role/Attributes/RoleSessionNameНе визначено$user.name
https://www.aliyun.com/SAML-Role/Attributes/RoleНе визначеноacs:ram::1879818006829152:role/$user.roles,acs:ram::1879818006829152:saml-provider/testa

Створюють такі атрибути у відповіді:

<saml:Attribute Name="https://www.aliyun.com/SAML-Role/Attributes/RoleSessionName" NameFormat="urn:oasis:names:tc:SAML:2.0:attrname-format:unspecified">
    <saml:AttributeValue xsi:type="xs:string">admi122n@outlook.com</saml:AttributeValue>
</saml:Attribute>
<saml:Attribute Name="https://www.aliyun.com/SAML-Role/Attributes/Role" NameFormat="urn:oasis:names:tc:SAML:2.0:attrname-format:unspecified">
    <saml:AttributeValue xsi:type="xs:string"> acs:ram::1879818006829152:role/role1,acs:ram::1879818006829152:saml-provider/testa</saml:AttributeValue>
    <saml:AttributeValue xsi:type="xs:string"> acs:ram::1879818006829152:role/role2,acs:ram::1879818006829152:saml-provider/testa</saml:AttributeValue>
</saml:Attribute>

Управління підписом твердження​

Casdoor завжди підписує SAML-відповідь. Щоб також підписати твердження всередині відповіді, увімкніть опцію Enable SAML assertion signature у додатку. За замовчуванням ця опція вимкнена.

Версії 2.81.0–2.247.x завжди підписували також твердження. Деякі провайдери послуг, наприклад Sentry, відхиляють відповіді з підписаним твердженням, тому починаючи з версії 2.248.0, Casdoor підписує лише конверт відповіді, якщо опція не увімкнена. Підписана відповідь також забезпечує автентичність твердження.

Тестування з Go service provider​

gosaml2 — це реалізація SAML 2.0 для провайдерів послуг на Go. Наступна програма використовує її для тестування Casdoor як IdP.

Приклад припускає, що Casdoor працює за адресою http://localhost:7001/, а додатком є app-built-in організації built-in.

  1. Додайте http://localhost:6900/acs/example та http://localhost:6900/saml/acs/example до Redirect URLs додатка app-built-in.

  2. Запустіть програму:

    import (
        "crypto/x509"
        "fmt"
        "net/http"

        "io/ioutil"

        "encoding/base64"
        "encoding/xml"

        saml2 "github.com/russellhaering/gosaml2"
        "github.com/russellhaering/gosaml2/types"
        dsig "github.com/russellhaering/goxmldsig"
    )

    func main() {
        res, err := http.Get("http://localhost:7001/api/saml/metadata?application=admin/app-built-in")
        if err != nil {
            panic(err)
        }

        rawMetadata, err := ioutil.ReadAll(res.Body)
        if err != nil {
            panic(err)
        }

        metadata := &types.EntityDescriptor{}
        err = xml.Unmarshal(rawMetadata, metadata)
        if err != nil {
            panic(err)
        }

        certStore := dsig.MemoryX509CertificateStore{
            Roots: []*x509.Certificate{},
        }

        for _, kd := range metadata.IDPSSODescriptor.KeyDescriptors {
            for idx, xcert := range kd.KeyInfo.X509Data.X509Certificates {
                if xcert.Data == "" {
                    panic(fmt.Errorf("metadata certificate(%d) must not be empty", idx))
                }
                certData, err := base64.StdEncoding.DecodeString(xcert.Data)
                if err != nil {
                    panic(err)
                }

                idpCert, err := x509.ParseCertificate(certData)
                if err != nil {
                    panic(err)
                }

                certStore.Roots = append(certStore.Roots, idpCert)
            }
        }

        randomKeyStore := dsig.RandomKeyStoreForTest()

        sp := &saml2.SAMLServiceProvider{
            IdentityProviderSSOURL:      metadata.IDPSSODescriptor.SingleSignOnServices[0].Location,
            IdentityProviderIssuer:      metadata.EntityID,
            ServiceProviderIssuer:       "http://localhost:6900/acs/example",
            AssertionConsumerServiceURL: "http://localhost:6900/v1/_saml_callback",
            SignAuthnRequests:           true,
            AudienceURI:                 "http://localhost:6900/saml/acs/example",
            IDPCertificateStore:         &certStore,
            SPKeyStore:                  randomKeyStore,
        }

        http.HandleFunc("/v1/_saml_callback", func(rw http.ResponseWriter, req *http.Request) {
            err := req.ParseForm()
            if err != nil {
                rw.WriteHeader(http.StatusBadRequest)
                return
            }
            samlReponse := req.URL.Query().Get("SAMLResponse")
            assertionInfo, err := sp.RetrieveAssertionInfo(samlReponse)
            if err != nil {
                fmt.Println(err)
                rw.WriteHeader(http.StatusForbidden)
                return
            }
            fmt.Println(assertionInfo)
            if assertionInfo.WarningInfo.InvalidTime {
                fmt.Println("here12:", assertionInfo.WarningInfo.InvalidTime)
                rw.WriteHeader(http.StatusForbidden)
                return
            }

            if assertionInfo.WarningInfo.NotInAudience {
                fmt.Println(assertionInfo)
                fmt.Println("here13:", assertionInfo.WarningInfo.NotInAudience)
                rw.WriteHeader(http.StatusForbidden)
                return
            }

            fmt.Fprintf(rw, "NameID: %s\n", assertionInfo.NameID)

            fmt.Fprintf(rw, "Assertions:\n")

            for key, val := range assertionInfo.Values {
                fmt.Fprintf(rw, "  %s: %+v\n", key, val)
            }
            fmt.Println(assertionInfo.Values.Get("FirstName"))
            fmt.Fprintf(rw, "\n")

            fmt.Fprintf(rw, "Warnings:\n")
            fmt.Fprintf(rw, "%+v\n", assertionInfo.WarningInfo)
        })

        println("Visit this URL To Authenticate:")
        authURL, err := sp.BuildAuthURL("")
        if err != nil {
            panic(err)
        }

        println(authURL)

        println("Supply:")
        fmt.Printf("  SP ACS URL      : %s\n", sp.AssertionConsumerServiceURL)

        err = http.ListenAndServe(":6900", nil)
        if err != nil {
            panic(err)
        }
    }

    У консолі буде показано:

    Visit this URL To Authenticate:
    http://localhost:7001/login/saml/authorize/admin/app-built-in?SAMLRequest=lFVbk6K8Fv0rFvNo2QR...
    Supply:
      SP ACS URL      : http://localhost:6900/v1/_saml_callback

  3. Відкрийте URL. З'явиться сторінка входу Casdoor.

  4. Увійдіть. Програма виведе SAML-відповідь.
