Casdoor SDK でユーザーをサインインさせる

このガイドでは、Casdoor SDK を一覧にし、フロントエンド SDK とバックエンド SDK を使用して Web アプリケーションにユーザーをサインインさせる方法を説明します。例では casdoor-js-sdk と casdoor-go-sdk を使用しています。他の SDK も同じ手順に従います。

学習目標​

  • プラットフォームに適した SDK を選択する。
  • バックエンド SDK とフロントエンド SDK を設定する。
  • 認可コードをアクセストークンと交換し、トークンを検証する。
  • ユーザーをアプリケーションにサインインした状態に保つ。
  • SDK を通じてユーザーとアプリケーションを管理する。

必要なもの​

  • 稼働中の Casdoor インスタンス
  • Redirect URLs にアプリケーションのコールバック URL が含まれている Casdoor の アプリケーション
  • アプリケーションのクライアント ID とクライアント シークレット、およびその証明書の公開鍵

SDK について​

Casdoor SDK は OpenID Connect (OIDC) を基盤としており、ユーザー管理やファイルアップロードなどの Casdoor API の機能を追加します。標準的な OIDC クライアントよりもわずかにセットアップが必要ですが、完全な Casdoor API を利用できます。

  • フロントエンド SDK: Web フロントエンド、モバイルアプリ、デスクトップアプリ向けです。サインイン URL を構築し、UI 内でコールバックを処理します。
  • Backend SDKs: サーバー用です。認可コードの交換、トークンの検証、Casdoor API の呼び出しを行います。

アプリケーションにフロントエンドとバックエンドが分離されている場合は、UI でフロントエンド SDK を、サーバーでバックエンド SDK を使用します。例については casdoor-python-vue-sdk-example を参照してください。JSP や PHP アプリケーションのようにサーバー側でページをレンダリングする場合は、バックエンド SDK だけで十分であることがあります。

SDK の選択​

すべての公式 SDK は GitHub の casdoor オーガニゼーション にあります。

バックエンド SDK の設定​

バックエンドの起動時に、Casdoor のアドレスとアプリケーションの認証情報で SDK を初期化します。casdoor-go-sdk の場合:

var CasdoorEndpoint = "https://door.casdoor.com"
var ClientId = "541738959670d221d59d"
var ClientSecret = "66863369a64a5863827cf949bab70ed560ba24bf"
var CasdoorOrganization = "casbin"
var CasdoorApplication = "app-casnode"

//go:embed token_jwt_key.pem
var JwtPublicKey string

func init() {
    auth.InitConfig(CasdoorEndpoint, ClientId, ClientSecret, JwtPublicKey, CasdoorOrganization, CasdoorApplication)
}

InitConfig() は次のパラメータを受け取ります:

パラメータ必須説明
エンドポイントはいCasdoor Server URL, like https://door.casdoor.com or http://localhost:8000
clientIdはいCasdoorアプリケーションのクライアントID
clientSecretはいCasdoorアプリケーションのクライアントシークレット
jwtPublicKeyはいCasdoorアプリケーションの証明書の公開鍵
organizationNameはいCasdoor組織の名前
applicationNameいいえCasdoorアプリケーションの名前

jwtPublicKey の値を取得するには:

  1. Casdoor 管理コンソールで Certs ページを開きます。

  2. 証明書を開き、公開鍵をコピーまたはダウンロードします。

  3. アプリケーションの編集ページで、同じ証明書を Cert で選択します。

フロントエンド SDK の設定​

  1. casdoor-js-sdk を npm でインストールします:

    npm install casdoor-js-sdk

    または Yarn で:

    yarn add casdoor-js-sdk

  2. Setting.js などの共有ファイルにヘルパー関数を定義します:

    import Sdk from "casdoor-js-sdk";

    export function initCasdoorSdk(config) {
      CasdoorSdk = new Sdk(config);
    }

    export function getSignupUrl() {
      return CasdoorSdk.getSignupUrl();
    }

    export function getSigninUrl() {
      return CasdoorSdk.getSigninUrl();
    }

    export function getUserProfileUrl(userName, account) {
      return CasdoorSdk.getUserProfileUrl(userName, account);
    }

    export function getMyProfileUrl(account) {
      return CasdoorSdk.getMyProfileUrl(account);
    }

    export function getMyResourcesUrl(account) {
      return CasdoorSdk.getMyProfileUrl(account).replace("/account?", "/resources?");
    }

    export function signin() {
      return CasdoorSdk.signin(ServerUrl);
    }

    export function showMessage(type, text) {
      if (type === "") {
        return;
      } else if (type === "success") {
        message.success(text);
      } else if (type === "error") {
        message.error(text);
      }
    }

    export function goToLink(link) {
      window.location.href = link;
    }

  3. React の index.js や app.js などのフロントエンドのエントリーファイルで SDK を初期化します。最初の 4 つの設定にはバックエンド SDK と同じ値を使用します。redirectPath は、ログイン後に Casdoor がユーザーを戻すアプリケーションのパスです。

    const config = {
      serverUrl: "https://door.casdoor.com",
      clientId: "014ae4bd048734ca2dea",
      organizationName: "casbin",
      appName: "app-casnode",
      redirectPath: "/callback",
    };

    xxx.initCasdoorSdk(config);

  4. コールバックルートを処理します。この React の例では、コンポーネントが /callback を処理し、コードをバックエンドに転送します。JSP や PHP アプリケーションのように Casdoor が直接バックエンドへリダイレクトする場合は、この手順をスキップしてください。

    import React from "react";
    import {Button, Result, Spin} from "antd";
    import {withRouter} from "react-router-dom";
    import * as Setting from "./Setting";

    class AuthCallback extends React.Component {
      constructor(props) {
        super(props);
        this.state = {
          classes: props,
          msg: null,
        };
      }

      componentWillMount() {
        this.login();
      }

      login() {
        Setting.signin().then((res) => {
          if (res.status === "ok") {
            Setting.showMessage("success", `Logged in successfully`);
            Setting.goToLink("/");
          } else {
            this.setState({
              msg: res.msg,
            });
          }
        });
      }

      render() {
        return (
          <div style={{textAlign: "center"}}>
            {this.state.msg === null ? (
              <Spin
                size="large"
                tip="Signing in..."
                style={{paddingTop: "10%"}}
              />
            ) : (
              <div style={{display: "inline"}}>
                <Result
                  status="error"
                  title="Login Error"
                  subTitle={this.state.msg}
                  extra={[
                    <Button type="primary" key="details">
                      Details
                    </Button>,
                    <Button key="help">Help</Button>,
                  ]}
                />
              </div>
            )}
          </div>
        );
      }
    }

    export default withRouter(AuthCallback);

ログインおよび新規登録リンクの表示​

ユーザーに Sign in および Sign up ボタンまたはリンクを提供します。URL はフロントエンド SDK またはバックエンド SDK から取得します。Sign-in and sign-up URLs を参照してください。

アクセストークンの取得と検証​

ログインフローには 3 つのステップがあります:

  1. ユーザーがログインリンクをクリックすると、Casdoor のログインページに移動します。例えば:

    https://door.casdoor.com/login/oauth/authorize?client_id=014ae4bd048734ca2dea&response_type=code&redirect_uri=https%3A%2F%2Fforum.casbin.com%2Fcallback&scope=read&state=app-casnode

  2. ユーザーがユーザー名とパスワードを入力して Sign In をクリックするか、GitHub ボタンなどのプロバイダーボタンをクリックします。

  3. Casdoor は認可コードとともにユーザーをアプリケーションにリダイレクトします。例えば https://forum.casbin.com?code=xxx&state=yyy です。

その後、バックエンドは GetOAuthToken() を使用してコードをアクセストークンと交換し、ParseJwtToken() を使用してトークンを検証します:

// get code and state from the GET parameters of the redirected URL
code := c.Input().Get("code")
state := c.Input().Get("state")

// exchange the access token with code and state
token, err := auth.GetOAuthToken(code, state)
if err != nil {
    panic(err)
}

// verify the access token
claims, err := auth.ParseJwtToken(token.AccessToken)
if err != nil {
    panic(err)
}

ParseJwtToken() がエラーを返さない場合、トークンは有効であり、Casdoor によって発行されたことを意味します。ユーザーはログイン済みです。返された claims を使用してユーザーを識別します。完全な例については、Go で書かれたフォーラムである Casnode のログインハンドラー を参照してください。

ユーザーをログイン状態に保つ​

アプリケーションがユーザーをどのように記憶するかは、OIDC、OAuth 2.0、Casdoor の一部ではなく、独自の設計判断です。このセクションでは 2 つの一般的な方法を説明します。

ParseJwtToken() が返す claims は次の型を持っています:

type Claims struct {
    User
    AccessToken string `json:"accessToken"`
    jwt.RegisteredClaims
}
FieldDescription
UserThe user, with all profile fields. See User
AccessTokenThe access token string
jwt.RegisteredClaimsThe standard claims of a JSON Web Token (JWT)

Casdoor では、アクセストークンは ID トークンと同じユーザークレームを保持するため、ログイン中のユーザーに関する情報を保持します。ただし、両者は異なる tokenType クレームを持ち、場合によっては異なる aud を持つ別々のトークンです。Access token and ID token を参照してください。

サーバーサイドセッションの使用​

クレームを Web フレームワークのセッションに保存します。その方法は言語やフレームワークに依存します。Casnode は Beego フレームワークを使用し、c.SetSessionUser() でユーザーを保存します:

token, err := auth.GetOAuthToken(code, state)
if err != nil {
    panic(err)
}

claims, err := auth.ParseJwtToken(token.AccessToken)
if err != nil {
    panic(err)
}

claims.AccessToken = token.AccessToken
c.SetSessionUser(claims) // set session

JWT としてのアクセストークンの使用​

アクセストークンは JWT です。アプリケーションがセッションを JWT で保持している場合は、アクセストークンを直接使用します:

  1. アクセストークンをフロントエンドに送信し、ブラウザの localStorage などに保存します。
  2. すべてのリクエストでアクセストークンをバックエンドに送信します。
  3. バックエンドでは、ParseJwtToken() または独自関数でトークンを検証し、サインイン中のユーザー情報を取得します。

SDK を通じたユーザー管理​

バックエンド SDK は Casdoor API をラップしています。この部分は OIDC や OAuth 2.0 とは異なります。含まれる機能は以下の通りです:

FunctionDescription
GetUser(name string)Gets a user by username
GetUsers()Gets all users
AddUser()Adds a user
UpdateUser()Updates a user
DeleteUser()Deletes a user
CheckUserPassword(auth.User)ユーザーのパスワードをチェックします

SDK にエンドポイント用の関数が存在しない場合、Casdoor API を直接呼び出してください。

SDK を通じたアプリケーション管理​

FunctionDescription
AddApplication()Creates an application
GetApplication(name string)名前でアプリケーションを取得します
GetApplications()Gets all applications
UpdateApplication()Updates an application
DeleteApplication()Deletes an application

AddApplication() でアプリケーションを作成すると、Casdoor はデフォルトのサインアップ項目 (ID, Username, Display name, Password, Confirm password, Email, Phone, Agreement)、サインイン項目、およびサインイン方法を自動入力します。追加の設定なしに UI で動作するようになります。
