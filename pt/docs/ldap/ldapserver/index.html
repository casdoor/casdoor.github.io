Servidor LDAP

O Casdoor pode atuar como um servidor LDAP simples para sistemas (ex.: Nexus) que usam LDAP para autenticação. Ele suporta bind e search com Simple Authentication.

Porta​

O servidor LDAP escuta na porta 389 por padrão. Change it via ldapServerPort in conf/app.conf.

Comportamento​

  • As entradas de usuário seguem o estilo posixAccount e também carregam as classes de objeto Samba. Consulte Atributos de usuário.
  • Bind: O servidor analisa cn (nome de usuário) e ou (organização). dc é ignorado. Ele verifica o usuário com o Casdoor e concede acesso para operações subsequentes.
  • Search: O servidor verifica se o cliente tem permissão (do bind) e retorna os resultados de acordo.
informação

Apenas Simple Authentication é suportado.

Bind​

Use um DN neste formato: cn=<username>,ou=<organization>,dc=example,dc=com.

Exemplo: cn=admin,ou=built-in,dc=example,dc=com. Defina o DN do administrador neste formato, então faça o bind com esse DN e a senha do usuário. Em caso de sucesso, o cliente está autorizado para search. Se o DN não tiver ou, o Casdoor usa a organização built-in.

Os nomes dos atributos no DN não diferenciam maiúsculas de minúsculas, então CN=admin,OU=built-in também funciona. Espaços ao redor de nomes e valores são ignorados. Os valores continuam sendo case-sensitive: ou=Built-in é uma organização diferente de ou=built-in.

Um bind com uma senha correta ainda falha com invalidCredentials quando:

  • O usuário tem autenticação multifator (MFA) ativada. O erro diz "the user has MFA enabled and cannot bind with a password". Um bind LDAP não pode solicitar um segundo fator.
  • A organização do usuário tem Disable signin ativado.
  • O usuário precisa alterar a senha primeiro, ou configurar o MFA exigido pela organização. O usuário deve concluir isso na página de login do Casdoor antes que um bind LDAP funcione.

Buscar​

Após um bind bem-sucedido:

  • Um usuário (ex.: Alice em built-in): Base DN ou=built-in,dc=example,dc=com, filter cn=Alice.
  • Todos os usuários em uma org (ex.: built-in): Base DN ou=built-in,dc=example,dc=com, filter cn=*.
  • Todos os usuários em todas as orgs (se permitido): Base DN ou=*,dc=example,dc=com, filter cn=*.
  • Usuários em um grupo: Use um filtro com o ID do grupo do Casdoor, tal como (memberOf=<organization>/<group-name>).
  • Um usuário por ID POSIX: Use um filtro tal como (uidNumber=10001).

Os atributos Samba estão listados em Samba e clientes SMB.

Em memberOf, <group-organization> é a organização que possui o grupo, e <dc-parts> são as partes dc= do base DN da busca. Por exemplo, uma busca com base DN ou=my-org,dc=example,dc=com retorna memberOf: cn=dev,ou=my-org,dc=example,dc=com para o grupo my-org/dev. Se o base DN não tiver partes dc=, o valor é cn=<group-name>,ou=<group-organization>.

Todas as entradas carregam as classes de objeto posixAccount, que PAM e NSS requerem para autenticação Linux, e sambaSamAccount e sambaIdmapEntry.

A configuração LDAP attributes da organização pode limitar quais atributos são retornados. Consulte Filtragem de atributos do servidor LDAP.

Login em máquina Linux​

O servidor LDAP do Casdoor expõe entradas compatíveis com posixAccount, então hosts Linux podem autenticar usuários diretamente contra o Casdoor via ferramentas padrão como sssd, nss-ldap, ou pam_ldap.

Para configurar valores por usuário para loginShell e sshPublicKey, defina-os no campo Properties do usuário (mapa chave-valor):

{
  "loginShell": "/bin/zsh",
  "sshPublicKey": "ssh-ed25519 AAAA..."
}

Se loginShell não estiver definido, /bin/bash é usado. Se sshPublicKey estiver ausente, o atributo é omitido completamente da entrada LDAP.

Definir IDs de usuário e grupo POSIX​

Por padrão, o Casdoor deriva o uidNumber do nome de usuário e o gidNumber do grupo do nome do grupo. Os números permanecem os mesmos enquanto os nomes não mudarem. Para publicar números fixos, por exemplo, para corresponder à propriedade de arquivos em hosts existentes:

  1. Na página de edição do usuário, defina UID number. Deixe como 0 para manter o número derivado. Somente administradores podem ver e alterar este campo.
  2. Na página de edição do grupo, defina GID number. Deixe como 0 para manter o número derivado.

Se UID number não estiver na página de edição do usuário, adicione-o aos Account items da organização. A sincronização LDAP também pode preencher UID number. Consulte Sync POSIX IDs. Um sincronizador de banco de dados pode mapear uma coluna para o campo UidNumber.

Clientes Samba e SMB​

Cada entrada de usuário também é uma conta Samba (sambaSamAccount, sambaIdmapEntry), portanto, clientes SMB que leem contas do LDAP, como Synology DSM e TrueNAS, podem usar o Casdoor como seu diretório.

AttributeSource
sambaSIDUser property sambaSID. Otherwise <domain-sid>-<uidNumber>, where <domain-sid> is S-1-5-21- followed by three numbers derived from the organization name.
sambaPrimaryGroupSIDUser property sambaPrimaryGroupSID. Otherwise the same value as the derived sambaSID.
sambaAcctFlags[U ], or [DU ] when the user is forbidden or deleted
sambaPwdLastSetUnix time of the user's last password change, otherwise of the user's creation time. It's never 0, which Samba reads as "must change password at next logon".
sambaDomainNameOrganization name
sambaLMPasswordPlaceholder of 32 X characters. The LAN Manager hash isn't supported.

Você pode buscar por sambaSID, sambaPrimaryGroupSID, sambaAcctFlags, sambaDomainName e sambaPwdLastSet com termos de igualdade, por exemplo (sambaDomainName=built-in). Eles seguem as mesmas regras dos outros atributos computados em POSIX filters.

Para definir o SID ou hash NT de um usuário, adicione a chave sambaSID, sambaPrimaryGroupSID ou sambaNTPassword ao campo Properties do usuário.

Atributos de senha​

O servidor LDAP integrado retorna os atributos de senha userPassword e sambaNTPassword somente quando a organização tem Enable LDAP password ativado. Enquanto estiver desativado, esses atributos nunca serão retornados, mesmo quando o cliente solicitar ou a lista de LDAP attributes da organização os incluir.

Somente administradores globais podem ativar Enable LDAP password, na página de edição da organização. O Casdoor solicita confirmação primeiro.

perigo

Com Enable LDAP password ativado, todo cliente que pode buscar usuários da organização lê seus hashes de senha, ou as próprias senhas se a organização as armazenar em texto simples. Um hash NT pode ser usado para entrar diretamente em serviços SMB (pass-the-hash). Ative apenas quando uma integração como o Samba precisar.

  • userPassword: A senha armazenada com um prefixo para o Password type da organização: {sha256} para salt, {md5} para md5-salt, {pbkdf2} para pbkdf2-salt, e {<password-type>} para os outros tipos. Com plain, o valor é a própria senha.
  • sambaNTPassword: A propriedade do usuário sambaNTPassword em maiúsculas, se definida. Caso contrário, o Casdoor calcula o hash NT, mas somente quando o Password type da organização é plain. Para outros tipos de senha, defina a propriedade, ou o atributo será omitido.

Recursos no estilo RFC​

Root DSE (baseDN="")​

  • namingContexts: ldapsearch -x -H ldap://<casdoor-host>:389 -D "cn=admin,ou=built-in" -w <passwd> -b "" -s base "(objectClass=*)" namingContexts — retorna os DNs das organizações visíveis.
  • subschemaSubentry: ldapsearch -x -H ldap://<casdoor-host>:389 -D "cn=admin,ou=built-in" -w <passwd> -b "" -s base "(objectClass=*)" subschemaSubentry — retorna subschemaSubentry: cn=Subschema.

Schema​

Consultar objectClasses: ldapsearch -x -H ldap://<casdoor-host>:389 -D "cn=admin,ou=built-in" -w <passwd> -b "cn=Subschema" -s base "(objectClass=*)" objectClasses — retorna as definições de posixAccount, posixGroup, sambaSamAccount e sambaIdmapEntry.

Filtros POSIX​

  • (objectClass=posixAccount) — lista de usuários. (objectClass=sambaSamAccount) e (objectClass=sambaIdmapEntry) retornam a mesma lista.
  • (objectClass=posixGroup) — lista de grupos para uma org (por exemplo, -b "ou=<org>" "(objectClass=posixGroup)").

uidNumber, gidNumber, homeDirectory e os atributos Samba são calculados pelo servidor. Um termo de igualdade em um deles funciona sozinho ou dentro de &, por exemplo (&(objectClass=posixAccount)(uidNumber=10001)). Dentro de | ou !, ou como um termo de substring como (uidNumber=100*), faz a busca retornar nenhuma entrada.

Uma busca de grupo é aquela cujo filtro é (objectClass=posixGroup), ou um filtro & que o contém. O Casdoor verifica o resto do filtro contra cada entrada de grupo, então você pode combinar termos &, |, !, igualdade, presença e substring em cn, gidNumber, memberUid e objectClass. Os valores dos grupos são comparados sem distinguir maiúsculas/minúsculas. Exemplos:

  • (&(objectClass=posixGroup)(gidNumber=12345)) — o grupo com esse GID.
  • (&(objectClass=posixGroup)(cn=dev*)) — grupos cujo nome começa com dev.
  • (&(objectClass=posixGroup)(memberUid=alice)) — os grupos do usuário alice.

Cada entrada de grupo tem o DN cn=<group-name>,<base-dn> e estes atributos:

AttributeSource
cnGroup name
gidNumberThe group's GID number. When it's 0, a number derived from the group name.
memberUidUsername of each member
objectClassposixGroup
