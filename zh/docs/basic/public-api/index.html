调用 Casdoor API

本指南介绍如何对 Casdoor REST API 进行身份验证，并从您自己的应用、服务和脚本中调用它。

学习目标​

  • 选择适合您调用者的身份验证方法。
  • 在请求中发送访问令牌、客户端凭证或访问密钥。
  • 为没有用户的服务获取访问令牌。
  • 通过 API 将用户从所有会话中注销。
  • 允许您的前端源从浏览器调用 API。

所需条件​

  • 一个正在运行的 Casdoor 实例。示例中使用演示站点 https://door.casdoor.com。
  • Casdoor 中的一个应用，包含其客户端 ID 和客户端密钥

关于 Casdoor API​

Casdoor 管理控制台是一个调用 REST API 的 React 单页应用。您的代码可以调用相同的 API，因此控制台所做的所有操作都可以通过 HTTP 使用。API 有三种类型的调用者：

  • Casdoor前端
  • Casdoor SDK，例如 casdoor-go-sdk
  • 您自己的应用和脚本

API 参考文档是您 Casdoor 实例的 Swagger 页面，例如 https://door.casdoor.com/swagger。要重新生成 Swagger 文件，请参阅生成 Swagger 文件。

选择身份验证方法​

MethodThe request runs asUse it for
Access tokenThe user who signed in, or the application for a client credentials tokenApplications that act for a signed-in user, and services that hold a token
Client ID and client secretThe application, with the rights of an administrator of its organizationMachine-to-machine (M2M) calls from backend services, CLIs, and scheduled jobs
Access key and access secretThe organization, application, or user that the key belongs toScripts and integrations that need a long-lived credential
用户名和密码The userLocal demos and compatibility only

使用访问令牌进行身份验证​

访问令牌是您的应用在用户通过 OAuth 2.0 登录时接收到的内容。携带该令牌的请求将以该用户的权限运行。

获取令牌​

在 OAuth 2.0 授权码流程结束时，当应用使用 code 交换令牌时，您的应用会接收到令牌。请参阅 OAuth 2.0。管理员也可以在管理控制台的 Tokens 页面查看已签发的令牌，例如 https://door.casdoor.com/tokens。

以下 Go 处理程序使用 casdoor-go-sdk 交换代码并读取令牌：

func (c *ApiController) Signin() {
    code := c.Input().Get("code")
    state := c.Input().Get("state")

    token, err := casdoorsdk.GetOAuthToken(code, state)
    if err != nil {
        c.ResponseError(err.Error())
        return
    }

    claims, err := casdoorsdk.ParseJwtToken(token.AccessToken)
    if err != nil {
        c.ResponseError(err.Error())
        return
    }

    claims.AccessToken = token.AccessToken
    c.SetSessionClaims(claims)

    c.ResponseOk(claims)
}

发送令牌​

在 Authorization 标头中发送令牌：

curl https://door.casdoor.com/api/get-account \
  -H "Authorization: Bearer <access-token>"

或者，将其作为 access_token 查询参数发送：

https://door.casdoor.com/api/get-global-providers?access_token=<access-token>

建议优先使用标头。URL 中的令牌可能会最终出现在服务器日志和浏览器历史记录中。

使用客户端 ID 和客户端密钥进行身份验证​

在没有用户参与的情况下，对 M2M（机器对机器）调用使用应用的凭据。请求以应用的身份运行，拥有该应用所属组织管理员的权限。典型的调用者包括：

  • 在 Casdoor 中管理用户或权限的后端服务
  • CLI 工具、计划任务和同步脚本
  • 企业对企业 (B2B) 设置，其中每个客户组织都有自己的应用，并使用该应用的凭据管理其自己的用户

获取凭据​

  1. 在 Casdoor 管理控制台中，打开应用的编辑页面，例如 https://door.casdoor.com/applications/casbin/app-vue-python-example。
  2. 复制 Client ID 和 Client secret。

随每个请求发送凭据​

使用 HTTP Basic 认证发送凭据。值为 <client-id>:<client-secret> 的 Base64 编码：

curl https://door.casdoor.com/api/get-users?owner=<organization> \
  -u "<client-id>:<client-secret>"

或者，将它们作为查询参数发送：

https://door.casdoor.com/api/get-users?owner=<organization>&clientId=<client-id>&clientSecret=<client-secret>

将凭据交换为访问令牌​

为了避免在每个请求中发送客户端密钥，请使用 OAuth 2.0 客户端凭证授权将凭据交换为访问令牌。

  1. 向 https://<casdoor-host>/api/login/oauth/access_token 发送 POST 请求：

    {
        "grant_type": "client_credentials",
        "client_id": "<client-id>",
        "client_secret": "<client-secret>"
    }

  2. 从响应中读取访问令牌：

    {
        "access_token": "eyJhb...",
        "token_type": "Bearer",
        "expires_in": 10080,
        "scope": "openid"
    }

  3. 按照 发送令牌 中所述，使用令牌调用 API。

有关该授权的详细信息，请参阅 客户端凭证授权。

提示

在 B2B 产品中，为每个客户组织创建一个 Casdoor 应用。每个客户获得自己的客户端 ID 和客户端密钥，管理其自己的用户和权限，并且无法访问其他组织的数据。

使用访问密钥和访问密钥秘密进行身份验证​

访问密钥对是在 Keys 页面上创建的长期有效凭据。密钥属于一个组织、一个应用或一个用户，携带该密钥的请求将以所有者的权限运行。

创建密钥​

  1. 在 Casdoor 管理控制台中，打开 Keys 页面。
  2. 添加密钥并选择其 Type：Organization、Application 或 User。
  3. 保存密钥并复制访问密钥秘密。Casdoor 不会再次显示该秘密。

发送密钥​

将密钥对作为查询参数发送：

curl "https://door.casdoor.com/api/get-global-providers?accessKey=<access-key>&accessSecret=<access-secret>"

使用用户名和密码进行身份验证​

注意事项

请勿在生产环境中使用此方法。密码会在 URL 中传输，代理和服务器可能会记录它。请改用访问令牌、客户端凭据或访问密钥。

将用户 ID（格式为 <organization>/<username>）和密码作为查询参数发送。请求将以该用户的身份运行。

https://door.casdoor.com/api/get-account?username=<organization>/<username>&password=<password>

对于启用了多因素身份验证 (MFA) 的用户，Casdoor 会拒绝此方法。

设置响应语言​

Casdoor 本地化响应中的错误消息和其他文本。发送 Accept-Language 标头以选择语言：

curl https://door.casdoor.com/api/get-account \
  -H "Authorization: Bearer <access-token>" \
  -H "Accept-Language: fr"

支持的代码包括 en、zh、es、fr、de、ja 和 ko。完整列表请参阅 国际化。

读取错误响应​

每个 API 响应都是一个包含 status 字段的 JSON 对象。失败的请求会返回 "status": "error"，并在 msg 中返回本地化消息。

通过 POST /api/login 使用密码（包括 LDAP）登录失败以及多因素认证 (MFA) 步骤失败也会返回 code 字段。与 msg 不同，它不依赖于语言，因此你的代码可以基于它进行分支处理：

{
  "status": "error",
  "code": "wrong-password",
  "msg": "password or code is incorrect, you have 4 remaining chances",
  "sub": "",
  "name": "",
  "data": null,
  "data2": null,
  "data3": null
}
codeReason
user-not-foundThe user doesn't exist in the organization
account-disabled该用户被禁止登录，或者是一个尚未设置用户名和密码的访客用户
account-frozenThe user entered a wrong password or code too many times and must wait
wrong-passwordThe password is incorrect
password-expiredThe password has expired and must be reset
mfa-failedThe MFA passcode or recovery code is incorrect

其他错误会省略 code。Casdoor 还会将原因存储在登录记录的详情中。当 app.conf 中的 enableErrorMask2 为 true 时，响应既不包含 code，也不包含详细消息。

将所有会话中的用户登出​

/api/sso-logout 端点会将已认证的用户从所有应用中登出，或仅从当前会话中登出。

GET or POST /api/sso-logout?logoutAll=<true|false>
ParameterRequiredDescription
logoutAllNotrue, 1, or omitted: sign out of all sessions. Any other value, such as false: sign out of the current session only
logoutAll=true (default)logoutAll=false
SessionsDeletes all sessions of the user across all applicationsDeletes the current session only
Access tokensExpires all tokens issued to the userKeeps all tokens
登出通知包含用户的所有会话 ID 以及用户所有令牌的哈希值包含当前会话 ID 以及用户所有令牌的哈希值。令牌仍然有效

当用户在某一台设备上登出而在其他设备上保持登录状态时，请使用 logoutAll=false。

请求必须使用本页列出的某种方法进行身份验证，或使用会话 cookie 进行身份验证：

# Sign out of all sessions
curl -X POST https://door.casdoor.com/api/sso-logout \
  -H "Authorization: Bearer <access-token>"

# Sign out of the current session only
curl -X POST "https://door.casdoor.com/api/sso-logout?logoutAll=false" \
  -H "Authorization: Bearer <access-token>"

# Authenticate with the session cookie
curl -X POST https://door.casdoor.com/api/sso-logout \
  --cookie "casdoor_session_id=<session-id>"

成功的请求将返回：

{
  "status": "ok",
  "msg": "",
  "data": ""
}

从浏览器调用 API​

浏览器会对从前端到 Casdoor 的调用应用跨域资源共享 (CORS) 规则。Casdoor 会将请求的 Origin 标头与其信任的来源进行比较，如果匹配，则添加 Access-Control-Allow-* 标头。Casdoor 在两个级别上信任来源。

以下来源可以发送会话 cookie (Access-Control-Allow-Credentials: true)：

  • app.conf 中的 origin 值
  • Casdoor 服务器本身主机名上的任何来源
  • 当 Casdoor 自身运行在回环地址上时，允许回环来源，例如 http://localhost:3000
  • appleid.apple.com

以下来源获取不带凭据的 CORS 标头：

  • 你应用的 Redirect URLs 中的来源。通过动态客户端注册注册的客户端不计入在内
  • 任意端口下的 http://localhost、https://localhost、http://127.0.0.1、http://casdoor-authenticator 以及 *.chromiumapp.org
  • 对于 POST /api/login/oauth/access_token 和 POST /api/acs，允许任意来源

/api/userinfo 会响应任意来源，但仅对 origin 的值或 Casdoor 主机允许携带凭据。Casdoor 会以 HTTP 403 拒绝来自其他来源的请求。响应中带有 Vary: Origin，且 Origin: null 被视为无来源的请求。允许的方法是 GET、POST、OPTIONS 和 DELETE。

对于来自无凭据来源的非 GET、HEAD 或 OPTIONS 请求，如果仅通过会话 cookie 进行身份验证，则该请求将以匿名用户身份执行。SAML 登出请求 (/api/saml/logout/...) 是例外情况。Casdoor 还拒绝从此类来源关联提供商账户。

若要从另一个来源的前端调用 API：

  1. 在 Casdoor 管理控制台中，将前端的 URL 添加到应用的 Redirect URLs 中。
  2. 使用 Authorization 标头中的访问令牌对每个请求进行身份验证，而不是使用会话 cookie。
