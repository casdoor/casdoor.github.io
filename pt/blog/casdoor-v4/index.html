Casdoor v4: Um novo Console, um Marketplace e OAuth para Servidores MCP

30 de outubro de 2026 · Leitura de 6 min
Yang Luo
Casdoor Maintainer

O Casdoor v4.0 foi lançado em 1º de setembro. Dois meses e 25 releases depois, estamos na v4.25, então este é um bom momento para revisar o que mudou. Em resumo: o console administrativo foi reconstruído, a auto-hospedagem ficou muito menos complicada, agora existe um Marketplace para integrações e temas de login, e o Casdoor pode atuar como servidor de autorização para servidores MCP e agentes de IA.

Se você ainda não usou: o Casdoor é uma plataforma open-source de gestão de identidade e acesso (IAM) escrita em Go. É um provedor de identidade completo, não uma biblioteca ou um proxy de login. Os usuários residem no Casdoor, o Casdoor emite os tokens e seus aplicativos se comunicam com ele via OAuth 2.0, OpenID Connect, SAML 2.0, CAS, LDAP ou SCIM. A autorização é tratada pelo Apache Casbin, portanto modelos ACL, RBAC e ABAC funcionam. Ele é licenciado sob Apache-2.0 e está listado no CNCF Landscape.

Um console e páginas de login reconstruídos​

A v4.0 substituiu o console administrativo Ant Design por um novo construído com shadcn/ui, Tailwind e Vite (agora com React 19). Possui uma paleta de comandos, seleção de linhas em massa, validação de formulário inline, formulários em duas colunas e tabelas onde você pode ocultar colunas. Alternar idiomas não recarrega mais a página.

As páginas de login, cadastro e redefinição de senha também foram redesenhadas. O modo escuro funciona corretamente e as páginas são utilizáveis em um celular.

Se você estiver atualizando da v3, leia primeiro o guia de atualização vinculado ao README. O principal ponto de verificação é o caminho da compilação do frontend se você servir arquivos estáticos através de um CDN ou proxy reverso.

Mais fácil de hospedar​

Muito do trabalho da v4 veio de issues e threads do fórum de pessoas rodando o Casdoor elas mesmas:

  • Sem senha padrão. Na primeira visita, o Casdoor pede que você defina a senha admin, ou você pode defini-la com initAdminPassword.
  • Implantação em sub-caminho. Defina basePath para servir o Casdoor em https://example.com/auth/ em vez de seu próprio host.
  • Forward auth. O Casdoor tem um endpoint de forward auth para Traefik, Caddy e Nginx, permitindo colocar atrás dele aplicativos sem login próprio, com caminhos públicos e regras por site.
  • Tags Docker. As imagens agora também são taggeadas como X, X.Y e X.Y.Z, permitindo seguir uma versão major ou minor.
  • Helm. O chart foi movido para o repositório principal, é publicado no GHCR e no Artifact Hub a cada release, e pode manter organizações, aplicações e usuários como configuração. Veja Executando o Casdoor no Kubernetes.
  • Serviço Windows. O binário pode ser executado como um serviço do Windows.
  • Atualizações. A página de informações do sistema mostra a última release e pode atualizar um binário oficial com um clique.
  • Operações. Verificações de saúde do container, contadores Prometheus para sucesso e falha de login, logs de auditoria encaminhados para Syslog e suporte a Redis Cluster.

Marketplace​

O novo Marketplace permite que um administrador instale integrações de dentro do Casdoor: templates de aplicação, provedores de identidade e temas de login. Instalar um preenche a configuração para você, e desinstalar restaura o que estava lá antes.

Existem mais de 20 temas de login até agora. Você pode visualizar um tema na sua própria página de login antes de instalá-lo. Administradores de organização também podem personalizar as páginas de login com suas próprias fontes, imagens e HTML, dentro de uma allowlist que bloqueia formulários e scripts. A demonstração somente leitura em door.casdoor.com alterna entre os temas se você quiser vê-los.

OAuth para servidores MCP e agentes de IA​

A especificação MCP solicita que servidores MCP remotos usem OAuth, e os clientes MCP geralmente não sabem antecipadamente qual servidor de autorização encontrarão. O Casdoor agora cobre as peças necessárias para isso:

  • Fluxo de código de autorização OAuth 2.1 com PKCE e uma página de consentimento onde os usuários podem conceder apenas algumas das escopos solicitadas
  • Registro Dinâmico de Clientes (RFC 7591) e gerenciamento de clientes (RFC 7592)
  • Documentos de Metadados de ID de Cliente: um cliente MCP pode usar uma URL como seu client_id sem registrar-se primeiro
  • Autenticação de cliente private_key_jwt para clientes registrados dinamicamente
  • Indicadores de Recurso (RFC 8707) e Metadados de Recursos Protegidos (RFC 9728)
  • Troca de Token (RFC 8693), incluindo ID-JAGs para autorização gerenciada empresarial, para que o IdP de uma organização possa decidir quais agentes podem acessar quais servidores MCP

Aponte os metadados de recursos protegidos do seu servidor MCP para o Casdoor, e login, consentimento, emissão e validação de tokens são tratados para você. O Casdoor também executa seu próprio servidor MCP, permitindo que assistentes como Claude Code ou Cursor gerenciem usuários, aplicações e permissões através dele.

Outros trabalhos de protocolo​

  • Logout Único SAML e SSO iniciado pelo IdP
  • prompt=none OIDC, melhor conformidade para fluxo híbrido, prompt e max_age, e o parâmetro iss da RFC 9207
  • Revogação de token (RFC 7009), DPoP e o fluxo de autorização de dispositivo
  • Login por link mágico, verificações de histórico de senhas e passkeys compartilhados entre subdomínios irmãos
  • Login exclusivo com um número máximo de sessões por usuário

Experimente​

A maneira mais rápida de dar uma olhada:

docker run -p 8000:8000 casbin/casdoor-all-in-one

Em seguida, abra http://localhost:8000. A imagem inclui SQLite e dados de exemplo, então use-a para experimentar, não para produção. O guia de instalação cobre implantações reais.

Existem duas demonstrações online: demo.casdoor.com é editável e reinicia a cada cinco minutos, e door.casdoor.com é somente leitura.

Se você preferir não executar por conta própria, o Casdoor Cloud oferece uma instância dedicada e gerenciada a um preço fixo, sem taxas por usuário. Novas contas recebem $10 em crédito para testar.
