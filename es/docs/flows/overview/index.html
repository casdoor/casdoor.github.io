Flujos

Un flujo es una pequeña automatización sin código para una organización. En un disparador, como justo antes de que un usuario inicie sesión, Casdoor ejecuta los pasos del flujo uno por uno: las condiciones deciden si el flujo continúa, y las acciones hacen algo, como rechazar el inicio de sesión, solicitar autenticación multifactor (MFA), añadir una reclamación a los tokens o llamar a su propio servicio.

Resultados del aprendizaje​

  • Cree un flujo a partir de una plantilla.
  • Pruebe un flujo con un usuario sin cambiar nada.
  • Llame a su propio servicio desde un flujo y modifique el resultado según su respuesta.

Requisitos​

  • Una cuenta de administrador de la organización.

Crear un flujo​

  1. En la consola de administración de Casdoor, vaya a Identity > Flows y haga clic en Add.

    Casdoor crea un flujo deshabilitado y lo abre.

  2. Elija una plantilla en Start from a template, o añada pasos usted mismo con Condition y Action.

  3. Seleccione el Trigger y, opcionalmente, Only for these applications. Una lista vacía significa todas las aplicaciones de la organización.

  4. Compruebe los pasos, active Enabled y haga clic en Save.

Los pasos forman una cadena bajo el disparador. Una condición que no se cumple termina el flujo, por lo que los pasos posteriores a una condición solo se ejecutan cuando esta se cumple. Cada paso puede moverse hacia arriba o hacia abajo, desactivarse con su interruptor o eliminarse.

Varios flujos pueden ejecutarse en el mismo disparador. Se ejecutan en el orden de su campo Order y, luego, por nombre. Un flujo que rechaza detiene los flujos posteriores.

Disparadores​

DisparadorCuándo se ejecutaQué puede hacer un flujo
Before sign-upEl formulario de registro está completado, pero el usuario aún no se ha guardado.Rechazar el registro, establecer campos del nuevo usuario, añadir el usuario a un grupo, llamar a un endpoint HTTP.
After sign-upEl usuario ha sido añadido. Se ejecuta en segundo plano.Establecer campos, cambiar grupos y roles, llamar a un endpoint HTTP, enviar un correo electrónico.
Before sign-inLas credenciales han sido verificadas, antes de la MFA y antes de crear la sesión. Ve el resultado del riesgo adaptativo.Rechazar el inicio de sesión, solicitar MFA, establecer campos, cambiar grupos y roles, llamar a un endpoint HTTP, enviar un correo electrónico.
After sign-inEl usuario ha iniciado sesión. Se ejecuta en segundo plano.Establecer campos, cambiar grupos y roles, llamar a un endpoint HTTP, enviar un correo electrónico.
Before a token is issuedUn token de acceso y un token de ID están a punto de emitirse a una aplicación.Rechazar el token, añadir reclamaciones, llamar a un endpoint HTTP.

Los disparadores de registro cubren la página de registro y el primer inicio de sesión con un proveedor de identidad de terceros que crea la cuenta.

Condiciones​

Una condición compara un campo con un valor. El texto se compara sin distinguir mayúsculas y minúsculas.

CampoDescripción
user.name, user.displayName, user.email, user.phoneEl nombre, nombre para mostrar, correo electrónico y teléfono del usuario.
user.emailDomainLa parte del correo electrónico después de @, en minúsculas.
user.emailVerified, user.isAdmin, user.isMfaEnabledSi el correo electrónico está verificado, si el usuario es administrador de la organización y si el usuario tiene configurada la MFA.
user.type, user.tag, user.region, user.affiliation, user.title, user.countryCodeCampos del usuario.
user.groups, user.rolesLos nombres de los grupos y roles del usuario, como una lista.
user.signupApplication, user.createdTime, user.accountAgeDaysDónde y cuándo se registró el usuario, y cuántos días hace.
user.properties.<key>Una propiedad personalizada del usuario.
application.nameLa aplicación a la que el usuario se registra o inicia sesión.
request.ip, request.country, request.userAgentLa dirección IP del cliente, su país según la base de datos de IP y su agente de usuario.
request.hour, request.weekdayLa hora (de 0 a 23) y el día de la semana (monday a sunday) en el servidor de Casdoor.
risk.score, risk.signals, risk.decisionLa puntuación, las señales y la decisión (Allow, MFA o Deny) del riesgo adaptativo. Solo Before sign-in.
claims.<name>A claim added by an earlier step. Before a token is issued only.
OperadorSe cumple cuando
is, is notEl campo es igual al valor, o no lo es.
contains, doesn't containEl texto contiene el valor. Para una lista, la lista tiene el valor.
starts with, ends withEl texto comienza o termina con el valor.
is one of, is none ofEl campo es uno de los valores separados por comas. Para una lista, la lista tiene cualquiera de ellos.
matches the regexEl texto coincide con la expresión regular.
is greater than, is less thanEl campo y el valor son números y se comparan así.
is set (or true), is empty (or false)El campo no está vacío, no es false ni 0, o sí lo es.
is in the networks, is not in the networksLa dirección IP está en una de las direcciones IP y rangos CIDR separados por comas, o no lo está.

Acciones​

AcciónDescripción
RefuseRechaza el registro, el inicio de sesión o el token con Message.
Ask for MFAEl usuario debe pasar la autenticación multifactor (MFA). Un dispositivo que recuerda la MFA no la omite, y un usuario sin MFA verifica el correo electrónico o el teléfono de la cuenta.
Add a token claimAñade una reclamación al token de acceso y al token de identificación. Value type JSON analiza el valor, como {"beta": true}. Las reclamaciones establecidas por Casdoor, como sub, iss y aud, no pueden modificarse.
Set a user fieldSets displayName, firstName, lastName, avatar, tag, region, location, affiliation, title, homepage, bio, language, gender, education, or a custom property properties.<key>.
Add to group, Remove from groupCambia los grupos del usuario. El grupo debe existir.
Grant role, Revoke roleAñade al usuario a un rol o elimina al usuario de él.
Call an HTTP endpointLlama a su servicio, consulte Llamar a su propio servicio.
Send an emailEnvía un correo electrónico mediante el proveedor de correo de la organización. To es el correo electrónico del usuario cuando está vacío.
End the flowTermina el flujo.

El texto de un parámetro puede contener campos entre llaves dobles, como {{user.email}}, {{user.properties.department}} o {{request.ip}}.

Probar un flujo​

Debajo del editor, seleccione un usuario en Test, opcionalmente una aplicación, una IP de cliente, una puntuación de riesgo y señales de riesgo, y haga clic en Run test. El flujo se ejecuta tal como está en el editor, guardado o no, y no se cambia nada: las acciones solo indican lo que harían, no se envía ningún correo electrónico, y los endpoints HTTP se llaman solo si su opción Call it in tests está activada. El resultado de cada paso se muestra debajo del paso.

Recent runs enumera las últimas ejecuciones del flujo guardado, con el usuario, el resultado y el resultado de cada paso.

Llamar a su propio servicio​

La acción Call an HTTP endpoint envía el usuario, la solicitud y el riesgo a su servicio como JSON, y su servicio puede cambiar el resultado con su respuesta. Úselo para comprobaciones que Casdoor no tiene, como una búsqueda en su CRM o sistema de RR. HH.

ParameterDescripción
URLEl endpoint y el método: POST (predeterminado), PUT o GET.
Signing secretCuando se establece, el cuerpo se firma con HMAC-SHA256 en el encabezado X-Casdoor-Signature.
HeadersMás encabezados de solicitud, uno por línea, como Name: value.
Timeout (seconds)5 por defecto, máximo 30.
When the call failsEnd the flow with an error (predeterminado), Ignore and continue, o Refuse. Una llamada falla cuando no puede conectarse, excede el tiempo de espera o devuelve un estado distinto de 2xx.
Call it in testsLlama al endpoint cuando se prueba el flujo.

POST /casdoor/pre-signin HTTP/1.1
Content-Type: application/json
User-Agent: Casdoor-Flow
X-Casdoor-Signature: sha256=5859636c8247daf287b9e32b39ead07422324245882167794f69d80654981bc6
{
  "application": "app-built-in",
  "request": {
    "country": "",
    "ip": "::1",
    "userAgent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/141.0"
  },
  "risk": {
    "score": 0,
    "signals": [],
    "decision": "Allow",
    "location": "intranet"
  },
  "time": "2026-11-23T22:53:04+08:00",
  "trigger": "pre-signin",
  "user": {
    "createdTime": "2026-11-23T22:35:50+08:00",
    "displayName": "Admin",
    "email": "admin@example.com",
    "groups": null,
    "id": "70ec365e-6dfd-40b2-98ae-aa31109b6f1a",
    "name": "admin",
    "owner": "built-in",
    "phone": "12345678910",
    "properties": {},
    "tag": "staff",
    "type": "normal-user"
  }
}

risk está presente en el disparador Before sign-in cuando el riesgo adaptativo está activado. En el disparador Before a token is issued, el cuerpo tiene claims con las reclamaciones añadidas hasta el momento.

Responda con HTTP 200 y un objeto JSON, todos los campos opcionales. Un cuerpo vacío o no JSON no cambia nada.

{
  "deny": "Your account is locked in the CRM",
  "requireMfa": true,
  "claims": {"crm_tier": "gold"},
  "user": {"title": "Sales manager", "properties.region": "EMEA"},
  "stop": true
}
CampoEfecto
denyRechaza, con este mensaje. Donde el disparador permite Refuse.
requireMfaSolicita MFA. Solo Before sign-in.
claimsAñade estas reclamaciones. Solo Before a token is issued.
userEstablece estos campos de usuario, los mismos campos que Set a user field. Donde el disparador permite Set a user field.
stopTermina el flujo después de este paso.

Verifique la firma antes de confiar en la solicitud. En Node.js, con el cuerpo sin procesar:

const crypto = require("crypto");

function isFromCasdoor(rawBody, signature, secret) {
  const expected = "sha256=" + crypto.createHmac("sha256", secret).update(rawBody).digest("hex");
  return signature.length === expected.length && crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expected));
}
nota

Los flujos de una organización distinta de built-in solo pueden llamar a direcciones de Internet, como sus webhooks y proveedores, a menos que un administrador global la convierta en una organización de confianza.
