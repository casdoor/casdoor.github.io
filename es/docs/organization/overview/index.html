Organizaciones

Una organización es la unidad en la que Casdoor gestiona usuarios y aplicaciones. Un usuario que ha iniciado sesión en una organización puede abrir todas las aplicaciones de esa organización sin volver a iniciar sesión.

La organización que seleccione para una aplicación o un proveedor determina qué usuarios pueden iniciar sesión en la aplicación y dónde está disponible el proveedor.

Edita una organización en la consola de administración de Casdoor bajo User Management > Organizations. La página de edición tiene las pestañas Basic, Password type, Account items y Advanced. Esta página describe la configuración general. Otras páginas de esta sección cubren la página de cuenta, la complejidad de la contraseña, el ofuscador de contraseña, el tema, los elementos MFA, los grupos y los registros del registro de auditoría. También configura LDAP por organización. Consulte LDAP.

Página de inicio de sesión de una organización​

Los usuarios normalmente inician sesión a través de una aplicación. También pueden iniciar sesión en la página de inicio de sesión de su organización, en /login/<organization-name>. En el sitio demo, por ejemplo: https://door.casdoor.com/login/casbin.

Cuando un usuario inicia sesión a través de esta URL, Casdoor recuerda la organización. Cuando la sesión expira, Casdoor envía al usuario de vuelta a la página de inicio de sesión de la misma organización.

Nombres de organizaciones​

El nombre de una organización no puede ser admin ni app, porque Casdoor usa estos nombres internamente. Crear o renombrar una organización a uno de ellos falla con the organization name: <name> is reserved.

Logo en tema oscuro​

En la pestaña Basic, active Enable dark logo para establecer Logo dark, un logo para el tema oscuro. La página muestra una vista previa sobre un fondo negro. Casdoor muestra este logo en la barra lateral de la consola de administración de Casdoor cuando la consola usa el tema oscuro. Si Logo dark está vacío, Casdoor muestra Logo. Desactivar Enable dark logo borra Logo dark.

Las páginas de inicio de sesión y registro no usan el logo de la organización. Muestran los logos de la aplicación, consulte Terminología de la aplicación.

Almacenamiento de contraseñas​

Password type establece el algoritmo con el que Casdoor almacena las contraseñas de los usuarios de la organización. Las nuevas organizaciones usan bcrypt.

NombreAlgoritmoDescripciónTypical use
plain—Passwords stored in cleartext. Not recommended for production.—
saltSHA-256SHA-256 is a cryptographic hash function that produces a 256-bit value.—
md5-saltMD5MD5 is a widely used but cryptographically weak hash (128-bit).Discuz!
bcryptbcryptbcrypt hashes and salts passwords securely. Default for new organizations.Spring Boot, WordPress
pbkdf2-saltSHA-256 and PBKDF2PBKDF2 is a key derivation function resistant to dictionary and rainbow-table attacks. Use when importing users via the Keycloak syncer.Keycloak
sha512-saltSHA-512SHA-512 of the password and the salt, stored as a hexadecimal string.—
argon2idArgon2idArgon2id with the default parameters of the alexedwards/argon2id library. The hash carries its own salt. To check an imported hash, Casdoor also accepts a hash of the password followed by the salt of the user or the organization, as some systems add a pepper this way.—
pbkdf2-djangoPBKDF2 with SHA-256The Django format pbkdf2_sha256$<iterations>$<salt>$<hash>. Casdoor hashes new passwords with 260000 iterations and reads the iterations and the salt from the stored hash.Django

Sal de contraseña​

Los algoritmos salt, sha512-salt, md5-salt, pbkdf2-salt y pbkdf2-django usan una sal. Password salt controla de dónde proviene la sal:

Password saltSaltUse it when
SetAll users of the organization share this saltYou need hashes that are compatible with another system
EmptyCasdoor generates a random salt for each user and stores it with the password hashYou set up a new organization. This is the recommended setting, because it limits the use of precomputed hash tables

Avatares permanentes​

Cuando un usuario inicia sesión a través de un proveedor OAuth, como GitHub o Google, Casdoor almacena la URL del avatar en el proveedor. Si el proveedor cambia o elimina esa URL más tarde, el avatar se rompe.

Active Use permanent avatar para hacer que Casdoor descargue el avatar y lo suba a su propio proveedor de almacenamiento. La URL permanece estable entonces. Casdoor sube un avatar solo cuando es nuevo o ha cambiado.

Email como nombre de usuario​

Active Use Email as username para registrar usuarios sin un nombre de usuario separado. Entonces:

  • En el registro, si el campo de nombre de usuario está oculto, la dirección de email se convierte en el nombre de usuario.
  • Cuando un usuario cambia la dirección de email, el nombre de usuario cambia con ella.

Eliminación suave​

Por defecto, eliminar un usuario elimina al usuario de la base de datos.

Con Soft deletion activado, eliminar un usuario solo marca al usuario como eliminado:

  • El usuario permanece en la lista de usuarios, con Is deleted seleccionado y una Deleted time.
  • El usuario ya no puede iniciar sesión y Casdoor revoca inmediatamente los tokens y las sesiones del usuario.
  • Para restaurar al usuario, desmarque Is deleted en la página de edición del usuario.
  • Para eliminar definitivamente al usuario, elimine el usuario por segunda vez.

Cuando Casdoor revoca los tokens de un usuario​

Casdoor caduca todos los tokens de un usuario en todas las aplicaciones cuando:

  • El usuario es eliminado o borrado suavemente (soft-deleted).
  • Un administrador activa Is forbidden para el usuario. Casdoor también finaliza las sesiones del usuario; consulte Prohibir o eliminar un usuario.
  • La contraseña del usuario cambia mediante POST /api/set-password. Esto cubre la página de cuenta, la página de edición del usuario y la página de recuperación de contraseña.

Las aplicaciones del usuario deberán volver a iniciar sesión para dicho usuario.

Inicio de sesión entre aplicaciones​

En la pestaña Basic, Enable exclusive signin across applications limita el número de sesiones de navegador que un usuario de la organización mantiene sobre todas las aplicaciones. Max sessions aparece cuando el interruptor está activado y establece ese número. Vacío o 1 mantiene solo la sesión actual. Casdoor aplica la configuración de la propia organización del usuario, incluso cuando el usuario inicia sesión a través de una aplicación compartida de otra organización. Consulte Exclusive sign-in.

Desactivar la consola de administración​

Active Disable console en la pestaña Basic para usar Casdoor únicamente como proveedor de identidad para los usuarios regulares de la organización. Cuando un usuario regular inicia sesión en la consola de administración de Casdoor, Casdoor muestra una página con HTTP 403, el título Unauthorized, el texto "The Casdoor console is disabled for the regular users of this organization" y un botón Logout.

La configuración no afecta a:

  • Las páginas de inicio de sesión y los flujos OAuth 2.0 y OpenID Connect (OIDC) de las aplicaciones. Los usuarios inician sesión en sus aplicaciones como antes.
  • Administradores de organización y administradores globales. Pueden usar la consola.
  • La página de configuración de MFA (/mfa/setup), para que los usuarios aún puedan configurar un método MFA requerido.
precaución

Solo el frontend de la consola aplica Disable console. La API de Casdoor sigue disponible para los usuarios con sus propios permisos.

Valores predeterminados para nuevas aplicaciones​

Dos configuraciones en la pestaña Advanced completan la configuración de tokens de las aplicaciones creadas posteriormente en la organización. Las aplicaciones existentes no cambian.

SettingDescription
Default token format (defaultTokenFormat)JWT, JWT-Empty, JWT-Custom, or JWT-Standard. Casdoor uses it for a new application that has no Token format. Empty means JWT
Default token fields (defaultTokenFields)Claims para una nueva aplicación que no tiene Token fields. Las opciones son las mismas que para Token fields de una aplicación, y puede escribir otros valores. Vacío significa sin campos

El formulario de nueva aplicación de la consola deja vacíos ambos campos de la aplicación, por lo que usa estos valores predeterminados. Las aplicaciones creadas mediante Dynamic Client Registration también los obtienen. Consulte Tokens para los formatos de token.

Retención de tokens y registros​

Dos configuraciones en la pestaña Advanced controlan cuánto tiempo Casdoor conserva los datos de la organización. Un trabajo de limpieza los aplica al iniciarse y luego cada día a las 00:00 hora del servidor.

SettingDescription
Token retention days (tokenRetentionDays)Casdoor deletes an expired token of the organization once it has been expired for longer than this number of days. 0 or empty means 30 days
Record retention days (recordRetentionDays)Casdoor elimina los registros (entradas de registro de auditoría) de la organización que son más antiguos que este número de días. 0 o vacío conserva los registros indefinidamente, que es el valor predeterminado

Los Record retention days de la organización built-in también se aplican a registros antiguos que no tienen organización o cuyo propietario es anonymous.

Hosts de base de datos confiables​

Los sincronizadores de base de datos y los adaptadores de Casbin de una organización distinta de built-in solo pueden conectarse a bases de datos en direcciones de Internet, y un sincronizador no puede conectarse al servidor de base de datos de Casdoor mismo. Trusted database hosts (trustedDbHosts) en la pestaña Advanced levanta estos límites para los hosts que enumera.

Ingrese una lista separada por comas de entradas host o host:port, por ejemplo 10.0.0.5,db.internal:3306. Una entrada sin puerto coincide con cualquier puerto. Casdoor compara los nombres de host sin distinguir mayúsculas y minúsculas e ignora los corchetes alrededor de las direcciones IPv6.

Solo un administrador global puede cambiar Trusted database hosts. Casdoor ignora los cambios realizados por cualquier otra persona. Un sincronizador nunca puede usar la base de datos de Casdoor misma, incluso en un host confiable.

Contraseñas LDAP y RADIUS​

Dos interruptores en la pestaña Advanced habilitan funciones de los servidores integrados para los usuarios de la organización. Solo un administrador global puede cambiarlos y ambos están desactivados por defecto.

SettingDescription
Enable LDAP password (enableLdapPassword)El servidor LDAP integrado devuelve los atributos de contraseña userPassword y sambaNTPassword de los usuarios, por ejemplo para Samba. Cuando está desactivado, el servidor nunca los devuelve, incluso si LDAP attributes los enumera. Activarlo solicita una confirmación: el servidor expone entonces los hashes de contraseña, o las contraseñas en texto plano si la organización las almacena en texto plano, y un hash NT es suficiente para iniciar sesión (pass-the-hash)
Enable RADIUS (enableRadius)The built-in RADIUS server accepts authentication and accounting requests for the users of the organization. When it is off, the server rejects Access-Request packets and doesn't answer Accounting-Request packets. After an upgrade, turn it on for organizations that already use RADIUS

Navegación de la consola de administración​

Dos configuraciones controlan qué páginas ven los miembros de la organización en la navegación de la consola de administración de Casdoor:

SettingApplies toDefault
Admin navbar items (navItems)AdministratorsAll pages
User navbar items (userNavItems)Regular usersNo pages. Regular users see only their own account pages

Seleccione las páginas en cada árbol, por ejemplo Applications, Providers, Resources, Keys, Products, Orders y Webhooks.

Cuando un usuario regular abre la página principal de Casdoor (/), Casdoor redirige al usuario a la primera de las siguientes páginas que el usuario puede ver:

  1. Apps (/apps)
  2. Shortcuts (/shortcuts)
  3. La página de cuenta (/account)

Nombre del emisor en las aplicaciones de autenticación​

Casdoor utiliza el nombre visible de la organización, o su nombre si no tiene uno visible, como emisor de las contraseñas de un solo uso basadas en tiempo (TOTP). Los usuarios que tienen varias entradas en una aplicación de autenticación reconocen la cuenta por este nombre.
