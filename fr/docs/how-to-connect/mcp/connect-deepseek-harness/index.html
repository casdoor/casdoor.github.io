Connecter DeepSeek Harness à Casdoor

Ce guide explique comment connecter DeepSeek Harness (dsh), le harnais agent open-source de DeepSeek, à Casdoor. dsh se connecte à Casdoor en tant qu'agent IA, et les serveurs MCP de votre organisation dans Casdoor deviennent des outils de dsh. Chaque appel d'outil passe par la passerelle MCP de Casdoor en tant qu'agent agissant pour l'utilisateur connecté, afin que Casdoor décide quels outils dsh peut appeler et enregistre chaque appel.

Tout est configuré depuis les pages web : le Marketplace de Casdoor d'un côté, la page du plugin et une page Casdoor dans dsh de l'autre. Vous ne modifiez pas cordis.patch.yml ni aucun autre fichier de configuration.

Édition commerciale

DeepSeek Harness est une intégration payante du Marketplace. Elle nécessite une licence Casdoor Commercial ou Enterprise edition : sans cela, Casdoor ne l'installe pas et ne fournit pas le plugin, la passerelle MCP ne sert pas les outils, et le plugin retire les serveurs MCP Casdoor de dsh. Voir tarifs.

Objectifs d'apprentissage​

  • Installez DeepSeek Harness depuis le Marketplace, ce qui crée son application et son agent dans Casdoor.
  • Installez le plugin Casdoor depuis la page des plugins de dsh.
  • Connectez dsh à Casdoor et choisissez les serveurs MCP qu'il peut utiliser.
  • Définissez les outils que dsh peut appeler, et retrouvez chaque appel dans Casdoor.

Prérequis​

  • Une instance Casdoor avec une licence Commercial ou Enterprise edition. Utilisez HTTPS en production.
  • Un administrateur de l'organisation dont les utilisateurs utilisent dsh.
  • Au moins un serveur MCP dans LLM AI > MCP Servers de cette organisation, avec ses outils synchronisés. Voir Placer les serveurs MCP derrière la passerelle MCP de Casdoor.
  • DeepSeek Harness 0.2, démarré avec dsh web (ou npx @deepseek-ai/dsh web), dans un navigateur sur le même ordinateur.

Comment ça fonctionne​

ÉtapeOùCe qui se passe
InstallationCasdoor MarketplaceCasdoor crée une application pour dsh avec le callback /casdoor/callback, et un agent du même nom dont le client OAuth est cette application.
PluginPage Plugins de dshLe plugin ajoute une page Casdoor à dsh à l'adresse /casdoor/.
ConnexionPage Casdoor de dshdsh connecte l'utilisateur à Casdoor via le flux code d'autorisation avec PKCE. Les jetons de l'application portent l'agent, donc Casdoor traite chaque appel comme celui de l'agent agissant pour l'utilisateur. Le jeton est renouvelé automatiquement avant son expiration.
OutilsPage Casdoor de dshLe plugin liste les serveurs MCP de l'organisation de l'utilisateur via la passerelle, et chaque serveur activé rejoint dsh, avec des outils nommés mcp__casdoor-<server>__<tool>.
AppelsPasserelle MCP de CasdoorLa passerelle vérifie les autorisations d'outils de l'utilisateur et de l'agent, enregistre l'appel avec un ID de trace, et peut envoyer un jeton d'identité de l'utilisateur et de l'agent au serveur MCP.

Installer DeepSeek Harness dans Casdoor​

  1. Dans la console d'administration de Casdoor, allez dans Identity > Marketplace et recherchez DeepSeek Harness. La carte est marquée Commercial edition.

  2. Cliquez sur Install et remplissez le formulaire :

    • Organization : l'organisation des utilisateurs qui utilisent dsh.
    • Name : le nom de l'application et de l'agent, deepseek-harness par défaut.
    • DeepSeek Harness address : l'adresse à laquelle vous ouvrez dsh, sans barre oblique finale. Un dsh web local est http://127.0.0.1:3080 ; tout port de 127.0.0.1 ou localhost fonctionne avec lui, donc un dsh démarré avec un autre --port se connectera aussi.

  3. Cliquez sur Install. Casdoor ouvre l'intégration installée sous Identity > Integrations, avec l'application, l'agent, l'ID client et l'URL de redirection <address>/casdoor/callback.

  4. Sous Downloads, téléchargez le plugin, casdoor-dsh-plugin-1.0.1.tgz. Il est destiné à vos déploiements personnels ; ne le partagez pas.

Installer le plugin dans DeepSeek Harness​

  1. Dans dsh, ouvrez Plugins dans la barre latérale et cliquez sur Add plugin.

  2. Entrez le chemin complet du fichier téléchargé, par exemple C:\Users\me\Downloads\casdoor-dsh-plugin-1.0.1.tgz ou /home/me/Downloads/casdoor-dsh-plugin-1.0.1.tgz, puis cliquez sur Install.

  3. Cliquez sur Enable now. Casdoor apparaît sous Installed plugins et est activé.

Sans la page web, installez-le depuis un terminal et redémarrez dsh web :

dsh plugin --profile web add /home/me/Downloads/casdoor-dsh-plugin-1.0.1.tgz

Connecter dsh à Casdoor​

  1. De retour sur l'intégration installée dans Casdoor, faites défiler jusqu'à Open the connection link. Cette étape liste l'adresse Casdoor, l'ID client et le secret client, ainsi qu'un lien contenant ces trois éléments.

  2. Copiez le lien et ouvrez-le dans le navigateur où dsh est ouvert. Si dsh tourne sur un port différent de celui avec lequel vous avez installé, changez le port au début du lien. La page Casdoor de dsh s'ouvre avec les champs préremplis. Vous pouvez également ouvrir /casdoor/ de dsh et les saisir manuellement.

  3. Cliquez sur Save and sign in, puis connectez-vous à Casdoor avec votre compte. Casdoor vous renvoie vers dsh.

  4. La page affiche l'édition de la licence, le compte connecté et les serveurs MCP de votre organisation avec leurs outils autorisés. Un serveur activé indique Connected une fois que dsh a ses outils ; désactivez un serveur pour retirer ses outils de dsh.

Utiliser les outils​

Demandez à dsh quelque chose qu'un des outils peut faire. L'agent appelle l'outil via la passerelle MCP de Casdoor, et l'appel s'affiche sous Called tools avec son nom, tel que mcp__casdoor-factory-erp__get_order.

Gouverner les appels dans Casdoor​

Déterminer quels outils dsh peut appeler​

Sur la page de modification d'un serveur MCP, l'option Is allowed d'un outil le bloque pour tous les clients. Pour un contrôle plus fin, activez Tool permissions du serveur : chaque appel nécessite alors une autorisation dont le Resource type est MCP tool.

  1. Accédez à Authorization > Permissions et ajoutez une autorisation.
  2. Définissez Resource type sur MCP tool, et Resources sur <server>/<tool>, <server>/* ou *.
  3. Ajoutez les utilisateurs, groupes ou rôles qui peuvent appeler les outils, et ajoutez l'agent DeepSeek Harness sous Agents.

Lorsque dsh agit pour un utilisateur, l'utilisateur et l'agent ont tous deux besoin d'une autorisation pour l'outil, afin que dsh ne dépasse jamais les droits de l'utilisateur pour lequel il agit. Une autorisation Deny a la priorité. dsh affiche un appel refusé comme une erreur d'outil, par exemple the user: built-in/admin has no permission to call the tool: whoami.

Retrouver chaque appel​

Activez Record MCP tool calls dans l'onglet Security de l'organisation. Chaque appel apparaît alors sous Tool calls en bas de la page de modification du serveur MCP, avec l'utilisateur, l'agent, l'outil, les arguments, le résultat et un ID de trace. Recherchez par ID de trace pour retrouver un appel spécifique.

Définissez l'Identity header du serveur MCP, tel que X-Casdoor-Identity, pour envoyer au serveur MCP un JWT à durée de vie courte identifiant l'utilisateur, ses groupes et rôles, l'agent et l'ID de trace. Le serveur MCP le vérifie avec la JWKS de Casdoor.

Arrêter dsh​

Accédez à LLM AI > Agents, ouvrez DeepSeek Harness et activez Is forbidden. La passerelle refuse le prochain appel de l'agent. Pour arrêter un seul utilisateur, interdisez l'utilisateur ou supprimez ses jetons dans Auditing > Tokens.

Où le plugin conserve ses données​

Le plugin conserve la connexion (adresse Casdoor, client ID, client secret), la session (jetons d'accès et de rafraîchissement et utilisateur connecté) et les serveurs désactivés dans le fichier d'identifiants de dsh, .credentials.yaml dans le répertoire principal de dsh (~/.dsh par défaut). Rien n'est ajouté à la configuration de dsh. Disconnect sur la page Casdoor supprime la connexion et la session.

Le plugin demande à Casdoor sa licence et la liste des serveurs MCP toutes les 10 minutes, et renouvelle le jeton avec le jeton de rafraîchissement avant son expiration.

Désinstaller​

  • Dans dsh, désactivez ou supprimez le plugin Casdoor sur la page Plugins. Ses serveurs MCP quittent dsh.
  • Dans Casdoor, désinstallez l'intégration dans Identity > Integrations. Casdoor supprime l'application et l'agent. Pour révoquer les jetons déjà détenus par dsh, supprimez-les dans Auditing > Tokens.

Dépannage​

La licence indique Community​

Le Casdoor auquel dsh se connecte ne possède pas de licence édition Commercial ou Enterprise, ou la licence a expiré. Ajoutez une licence à Casdoor, puis cliquez sur Refresh sur la page Casdoor de dsh.

Casdoor indique que l'URI de redirection n'est pas autorisée​

dsh s'exécute sur une adresse non listée par l'application, par exemple derrière un proxy inverse ou sur un autre nom d'hôte. Ajoutez <that address>/casdoor/callback aux Redirect URLs de l'application deepseek-harness. Les adresses de bouclage (127.0.0.1, localhost) sur tout port ne nécessitent aucune modification.

La page Casdoor de dsh répond 401​

Le navigateur n'a pas encore été connecté à dsh. Ouvrez dsh avec l'adresse affichée par dsh web, y compris la partie ?token=, puis rouvrez la page Casdoor.

Un serveur reste en état Connecting​

dsh n'a pas pu lister les outils via la passerelle. Vérifiez que le serveur dispose d'outils dont Is allowed est activé, et que Casdoor peut atteindre le serveur MCP en amont. La passerelle n'accède qu'aux adresses publiques sauf si mcpGatewayAllowIntranet = true est défini dans conf/app.conf d'un déploiement privé.
