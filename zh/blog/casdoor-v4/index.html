Casdoor v4：全新控制台、应用市场以及面向 MCP 服务器的 OAuth

2026年10月30日 · 阅读时间：一分钟
Yang Luo
Casdoor Maintainer

Casdoor v4.0 于 9 月 1 日发布。两个月内发布了 25 个版本，目前我们已到达 v4.25，因此这是一个回顾变更内容的好时机。简而言之：管理控制台经过重构，自托管部署变得更加简单，现在有了用于集成和登录主题的应用市场（Marketplace），并且 Casdoor 可以作为 MCP 服务器和 AI 代理的授权服务器。

如果您尚未使用过它：Casdoor 是一个用 Go 编写的开源身份与访问管理（IAM）平台。它是一个完整的身份提供商，而不是库或登录代理。用户信息存储在 Casdoor 中，由 Casdoor 签发令牌，您的应用通过 OAuth 2.0、OpenID Connect、SAML 2.0、CAS、LDAP 或 SCIM 与其通信。授权处理由 Apache Casbin 负责，因此 ACL、RBAC 和 ABAC 模型均可正常工作。它采用 Apache-2.0 许可证，并收录在 CNCF Landscape 中。

重构后的控制台和登录页面​

v4.0 使用基于 shadcn/ui、Tailwind 和 Vite（现支持 React 19）的新控制台替换了原有的 Ant Design 管理控制台。新控制台包含命令面板、批量行选择、内联表单验证、双列表单以及可隐藏列的表格。切换语言不再需要重新加载页面。

登录、注册和密码重置页面也进行了重新设计。深色模式运行正常，且页面在手机端也可正常使用。

如果您正从 v3 升级，请先阅读 README 中链接的升级指南。主要需要检查的是，如果您通过 CDN 或反向代理提供静态文件，前端构建的路径是否发生变化。

更简单的自托管体验​

v4 版本的许多工作都源于自行运行 Casdoor 的用户在问题和论坛帖子中提出的需求：

  • 无默认密码。 首次访问时，Casdoor 会要求您设置 admin 密码，或者您可以通过 initAdminPassword 进行设置。
  • 子路径部署。 设置 basePath 即可将 Casdoor 部署在 https://example.com/auth/ 下，而不是独立的域名主机。
  • Forward Auth。 Casdoor 提供了适用于 Traefik、Caddy 和 Nginx 的 Forward Auth 端点，因此您可以将没有自带登录功能的应用置于其后，并配置公共路径和站点规则。
  • Docker 标签。 镜像现在也带有 X、X.Y 和 X.Y.Z 标签，因此您可以跟随主版本或次版本更新。
  • Helm。 Chart 已移入主仓库，并在每次发布时推送到 GHCR 和 Artifact Hub，支持将组织、应用和用户作为配置保存。请参阅 在 Kubernetes 上运行 Casdoor。
  • Windows 服务。 二进制文件可以作为 Windows 服务运行。
  • 升级。 系统信息页面显示最新发行版，并可一键升级官方二进制文件。
  • 运维。 容器健康检查、用于记录登录成功和失败的 Prometheus 计数器、转发到 Syslog 的审计日志，以及对 Redis Cluster 的支持。

集成市场​

新的 应用市场 (Marketplace) 允许管理员直接在 Casdoor 内部安装集成项：应用模板、身份提供商和登录主题。安装过程会自动填充配置，卸载时会恢复之前的状态。

目前已有超过 20 种登录主题。您可以在安装前在自己的登录页面上预览主题。组织管理员还可以使用自己的字体、图片和 HTML 自定义登录页面，但需在阻止表单和脚本的白名单范围内操作。如果您想查看这些主题，可以访问只读演示站 door.casdoor.com，它会循环展示各个主题。

面向 MCP 服务器和 AI 代理的 OAuth​

MCP 规范要求远程 MCP 服务器使用 OAuth，而 MCP 客户端通常无法预先知道它将遇到哪个授权服务器。Casdoor 现已涵盖所需的关键部分：

  • 带 PKCE 的 OAuth 2.1 授权码流程，以及允许用户仅授予部分请求范围的同意页面
  • 动态客户端注册 (RFC 7591) 和客户端管理 (RFC 7592)
  • 客户端 ID 元数据文档：MCP 客户端可以使用 URL 作为其 client_id，而无需事先注册
  • 针对动态注册客户端的 private_key_jwt 客户端认证
  • 资源指示器 (RFC 8707) 和保护资源元数据 (RFC 9728)
  • 令牌交换 (RFC 8693)，包括用于企业托管授权的 ID-JAGs，以便组织的 IdP 决定哪些代理可以访问哪些 MCP 服务器

将您的 MCP 服务器的保护资源元数据指向 Casdoor，登录、同意、令牌签发和验证都将由 Casdoor 为您处理。Casdoor 还运行自己的 MCP 服务器，因此 Claude Code 或 Cursor 等助手可以通过它来管理用户、应用和权限。

其他协议相关工作​

  • SAML 单点登出和 IdP 发起的 SSO
  • OIDC prompt=none，改进混合流、prompt 和 max_age 的一致性，以及 RFC 9207 iss 参数
  • 令牌撤销 (RFC 7009)、DPoP 和设备授权流程
  • 魔法链接登录、密码历史记录检查，以及在兄弟子域间共享的 Passkeys
  • 独占登录，限制每个用户的最大会话数

试一试​

快速上手体验的方式：

docker run -p 8000:8000 casbin/casdoor-all-in-one

然后打开 http://localhost:8000。该镜像包含 SQLite 和示例数据，仅适用于试用，不适用于生产环境。安装指南涵盖了实际部署场景。

有两个在线演示：demo.casdoor.com 是可写的，每五分钟重置一次；door.casdoor.com 是只读的。

如果您不想自己运行，Casdoor Cloud 为您提供专属的托管实例，价格固定且无按用户收费。新账户可获得 $10 额度以进行试用。
