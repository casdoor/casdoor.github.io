Descripción general

Los certificados en Casdoor contienen claves criptográficas utilizadas para firmar y verificar tokens (p. ej., JWT) y para asegurar integraciones (SAML, proveedores de pagos).

Propiedades del certificado​

Cada certificado tiene:

  • Owner: La organización que posee el certificado
  • Name: El nombre único del certificado
  • CreatedTime: Cuándo se creó el certificado
  • DisplayName: Un nombre legible para humanos del certificado
  • Scope: El ámbito del certificado (p. ej., JWT, SAML, Payment)
  • Type: El tipo de certificado (p. ej., x509, Payment)
  • CryptoAlgorithm: El algoritmo criptográfico utilizado (p. ej., RS256 para RSA, ES256 para ECDSA)
  • BitSize: El tamaño de la clave en bits (p. ej., 2048, 4096)
  • ExpireInYears: El período de expiración del certificado en años
  • Certificate: El contenido del certificado público
  • PrivateKey: El contenido de la clave privada (almacenada de forma segura)

Campos del certificado SSL​

Los certificados con Type: SSL tienen campos adicionales para la renovación automática basada en ACME:

CampoDescripción
ExpireTimeExpiry timestamp of the current certificate (read-only, populated automatically)
DomainExpireTimeExpiry timestamp of the domain registration (read-only, from WHOIS lookup)
ProviderDNS provider used for DNS-01 ACME challenge: Aliyun or GoDaddy
AccountACME account email address
AccessKeyDNS provider API key / access key ID
AccessSecretDNS provider API secret

Cuando haces clic en Renew en un certificado SSL, Casdoor contacta al servicio ACME, completa el desafío DNS-01 a través del proveedor DNS configurado y almacena automáticamente el certificado emitido y la clave privada.

Ámbitos de los certificados​

Los certificados se utilizan de manera diferente según su ámbito:

Certificados JWT​

Los certificados JWT firman y verifican JSON Web Tokens. Cuando un usuario inicia sesión, el token de acceso se firma con la clave privada del certificado JWT.

Casdoor admite tanto algoritmos de firma RSA como ECDSA para tokens JWT. Aunque RSA (RS256, RS384, RS512) ha sido la opción tradicional, los algoritmos ECDSA (ES256, ES384, ES512) ofrecen tamaños de firma más pequeños y una verificación de firma más rápida con niveles de seguridad equivalentes. Esto ayuda a reducir el tamaño del token en dispositivos móviles o mejorar el rendimiento en escenarios de alta capacidad de procesamiento.

Para los certificados JWT, elige RSA o ECDSA según la seguridad y compatibilidad. Al configurar el SDK de Casdoor, usa la clave pública desde la página de edición del certificado (copiar o descargar).

Después de crear un certificado JWT, selecciónalo en la configuración de tu aplicación:

Certificados SAML​

Los certificados SAML firman y cifran las aserciones SAML en integraciones SSO.

Casos de uso:

  • Integraciones SSO basadas en SAML
  • Firma de respuestas SAML
  • Cifrado de aserciones SAML para seguridad

Para SAML, crea certificados tanto para el Proveedor de Identidad (IdP) como para el Proveedor de Servicio (SP) para asegurar la comunicación.

Para más información sobre la configuración de SAML, consulta la documentación de SAML.

Certificados de pago​

Los certificados de pago aseguran la comunicación con proveedores de pagos (por ejemplo, Alipay, WeChat Pay).

Casos de uso:

  • Asegurar comunicaciones API con pasarelas de pago
  • Firmar solicitudes de pago
  • Verificar devoluciones de llamadas de pago

Por ejemplo, para Alipay crea certificados para:

  • App Cert: Contiene el certificado público y la clave privada de la aplicación
  • Root Cert: Contiene los certificados del proveedor de pagos

Consulta Alipay y WeChat Pay para más detalles.

El certificado integrado​

cert-built-in (organización admin) es el certificado que Casdoor crea con una nueva base de datos. app-built-in lo utiliza, y Casdoor también lo usa para firmar solicitudes de autenticación SAML cuando un proveedor SAML tiene Sign request activado. En una instalación nueva, Casdoor genera un par de claves RS256 aleatorio para él, con una clave de 4096 bits y una validez de 20 años, por lo que cada instalación tiene su propia clave. Obtén el certificado para tu SDK o proveedor de servicio desde la página Certs, no desde el código fuente de Casdoor.

Las instalaciones creadas por versiones anteriores de Casdoor pueden seguir usando el par de claves que se publicó en el repositorio de Casdoor. Cualquiera puede falsificar tokens firmados con esa clave. Al iniciar, Casdoor lo detecta e imprime:

WARNING: the cert: admin/cert-built-in signs tokens with the private key published in the Casdoor repository, anyone can forge its tokens, please generate a new key pair for it

Para reemplazar el par de claves:

  1. En la consola de administración de Casdoor, ve a Certs y edita cert-built-in.
  2. Borra los campos Certificate y Private key.
  3. Haz clic en Save. Casdoor genera un nuevo par de claves a partir de los campos Crypto algorithm, Bit size y Expire in years.
  4. Proporciona el nuevo certificado a cada aplicación, SDK y proveedor de servicios SAML que verifique tokens o solicitudes firmados por cert-built-in.
precaución

Los tokens firmados con la clave antigua fallarán la verificación después del cambio, por lo que los usuarios de estas aplicaciones deberán iniciar sesión nuevamente.

Crear un certificado​

Para añadir un certificado:

  1. Navega a la página Certs en la consola de administración de Casdoor
  2. Haz clic en el botón Add para crear un nuevo certificado
  3. Rellena los campos obligatorios:
    • Name: Un identificador único para el certificado
    • Display Name: Un nombre legible para humanos
    • Scope: Selecciona el ámbito apropiado (JWT, SAML, Payment)
    • Type: Selecciona el tipo de certificado
    • Crypto Algorithm: Elige el algoritmo criptográfico (por ejemplo, RS256 para RSA, ES256 para ECDSA). Para los certificados JWT, se admiten ambos algoritmos RSA y ECDSA
    • Bit Size: Establece el tamaño de la clave (típicamente 2048 o 4096 bits)
    • Expire In Years: Establece el periodo de expiración
  4. O bien:
    • Generar un nuevo certificado automáticamente al guardar el formulario
    • Subir un certificado y una clave privada existentes

Uso de certificados​

En aplicaciones​

Después de crear un certificado JWT, asócialo con tu aplicación:

  1. Ve a la página Applications
  2. Edita tu aplicación
  3. En el campo Cert, selecciona el certificado que creaste
  4. Guarda la aplicación

El certificado se utilizará ahora para firmar todos los tokens emitidos por esa aplicación.

En la configuración del SDK​

Al configurar el SDK de Casdoor en tu backend, proporciona la clave pública del certificado JWT:

var CasdoorEndpoint = "https://door.casdoor.com"
var ClientId = "541738959670d221d59d"
var ClientSecret = "66863369a64a5863827cf949bab70ed560ba24bf"
var CasdoorOrganization = "casbin"
var CasdoorApplication = "app-casnode"

//go:embed token_jwt_key.pem
var JwtPublicKey string

func init() {
    auth.InitConfig(CasdoorEndpoint, ClientId, ClientSecret, JwtPublicKey, CasdoorOrganization, CasdoorApplication)
}

Descarga la clave pública desde la página de edición del certificado en Casdoor.

Para más información sobre la configuración del SDK, consulta la documentación del SDK.

En proveedores de pago​

Al configurar proveedores de pago, configura los certificados adecuados:

  1. Crea los certificados requeridos (por ejemplo, App Cert y Root Cert para Alipay)
  2. Ve a la página Providers
  3. Edita o crea tu proveedor de pago
  4. En el campo Cert, selecciona el certificado que creaste
  5. Guarda el proveedor

Mejores prácticas​

  • Tamaño de clave: Usa claves de al menos 2048 bits para RSA; 4096 bits para mayor seguridad.
  • Expiración: Establece una vida útil razonable (por ejemplo, 1–5 años en producción).
  • Seguridad: Nunca expongas claves privadas en código cliente o repositorios públicos.
  • Rotación: Rota los certificados antes de que expiren.
  • Copia de seguridad: Guarda copias de seguridad seguras de los certificados y las claves privadas.
  • Separación: Usa certificados separados para JWT, SAML y pagos para limitar el radio de impacto si una clave es comprometida.

Gestión de certificados​

Gestiona los certificados mediante:

  • Interfaz web: La consola de administración de Casdoor ofrece una interfaz fácil de usar para la gestión de certificados
  • API: Utiliza la API REST de Casdoor para gestionar certificados programáticamente
  • Inicialización de datos: Los certificados pueden incluirse en archivos de inicialización para despliegues automatizados

Para más información sobre la inicialización de datos, consulta la documentación de inicialización de datos.
