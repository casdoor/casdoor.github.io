Casdoor comme fournisseur d'identité (IdP) SAML 2.0 open source

Casdoor est un fournisseur d'identité (IdP) SAML 2.0. Cette page explique ce que vous configurez dans le fournisseur de services (SP) et dans Casdoor, ainsi que les données utilisateur transportées par la réponse SAML. Pour des guides étape par étape pour des fournisseurs de services spécifiques, consultez les autres pages de cette section.

Configurer le fournisseur de services​

Un fournisseur de services demande généralement trois valeurs : l'URL d'authentification unique (SSO), l'émetteur et le certificat public de l'IdP. La plupart des fournisseurs de services lisent ces trois valeurs à partir des métadonnées SAML de l'IdP, via une URL ou depuis un fichier téléversé.

L'URL des métadonnées d'une application Casdoor est :

<casdoor-host>/api/saml/metadata?application=admin/<application-name>

Par exemple, pour Casdoor à https://door.casdoor.com et l'application app-built-in :

https://door.casdoor.com/api/saml/metadata?application=admin/app-built-in

Pour obtenir l'URL dans la console d'administration Casdoor, ouvrez la page d'édition de l'application, allez dans l'onglet SAML et cliquez sur Copy SAML metadata URL. Pour télécharger les métadonnées sous forme de fichier XML, ouvrez l'URL dans un navigateur.

Configurer l'application Casdoor​

Sur la page d'édition de l'application, définissez deux champs :

FieldValeur
Redirect URLsThe identifier of the service provider, which the SP calls the audience or the entity ID. Enter exactly the same value as in the SP
SAML reply URLL'URL du service consommateur d'assertions (ACS) du SP, qui reçoit et vérifie la réponse SAML. Laissez vide pour utiliser la liaison de redirection

Type de liaison de réponse​

Casdoor peut envoyer le SAMLResponse avec une requête HTTP POST ou une requête HTTP GET. Choisissez ce que votre fournisseur de services prend en charge :

SAML reply URLBindingWhere Casdoor sends the response
SetPOSTTo the reply URL. The reply URL overrides the AssertionConsumerServiceURL of the SAMLRequest
EmptyGETTo the AssertionConsumerServiceURL that Casdoor reads from the SAMLRequest
remarque

Lorsque Casdoor authentifie lui-même les utilisateurs auprès d'un IdP SAML externe, tel qu'Azure AD, cet IdP externe poste sa réponse SAML vers le point de terminaison /api/acs de Casdoor. Ce point de terminaison accepte les requêtes POST inter-origines, afin qu'un IdP sur un autre domaine puisse envoyer la réponse.

Démarrer la connexion depuis Casdoor (SSO initié par l'IdP)​

Dans le SSO initié par l'IdP, l'utilisateur commence sur Casdoor au lieu de commencer sur le fournisseur de services. Casdoor envoie au SP une réponse SAML qui n'a pas été demandée par un AuthnRequest. Utilisez-le pour les liens de portail et les favoris.

  1. Dans l'onglet SAML de l'application, définissez SAML reply URL sur l'URL ACS du SP. Sans cela, la connexion échoue avec the SAML reply URL should not be empty for IdP-initiated SSO.

  2. Assurez-vous que la première entrée de Redirect URLs est l'ID d'entité du SP. Casdoor l'utilise comme audience de l'assertion.

  3. Enregistrez l'application. L'onglet SAML affiche alors l'IdP-initiated SSO URL :

    <casdoor-host>/login/saml/authorize/admin/<application-name>

  4. Cliquez sur Copy IdP-initiated SSO URL et donnez l'URL à vos utilisateurs.

Un utilisateur qui ouvre l'URL se connecte à Casdoor, et Casdoor poste la réponse SAML vers l'URL de réponse avec la liaison HTTP-POST. La réponse n'a pas d'attribut InResponseTo, car aucune requête ne l'a précédée. Pour transmettre un RelayState au SP, ajoutez-le à l'URL en tant que paramètre de requête, par exemple ?RelayState=/dashboard.

Déconnecter les utilisateurs du SP (déconnexion unique)​

Casdoor prend en charge la déconnexion unique SAML (SLO) dans les deux sens. Pour l'activer, définissez SAML single logout URL dans l'onglet SAML de l'application sur l'URL SingleLogoutService du SP.

Les métadonnées de l'application annoncent le SingleLogoutService de Casdoor, avec les liaisons HTTP-Redirect et HTTP-POST, à :

<casdoor-backend-host>/api/saml/logout/admin/<application-name>

Chaque assertion porte un SessionIndex dans son AuthnStatement, qui identifie la session Casdoor de la connexion.

Déconnexion initiée par le SP​

Lorsqu'un utilisateur se déconnecte sur le SP, celui-ci envoie une LogoutRequest au SingleLogoutService de Casdoor, via GET ou POST, dans le paramètre SAMLRequest et un RelayState facultatif :

  1. Casdoor vérifie la requête. Son Issuer doit figurer dans Redirect URLs, elle doit contenir un NameID, et l'application doit avoir une SAML single logout URL.
  2. Casdoor termine les sessions Casdoor nommées par les valeurs SessionIndex de la requête. Sans SessionIndex, il ne termine que la session du navigateur ayant envoyé la requête, et uniquement si le NameID appartient à son utilisateur.
  3. Casdoor déconnecte l'utilisateur des autres applications de ces sessions, via la déconnexion back-channel OIDC et les demandes de déconnexion SAML.
  4. Casdoor répond avec une LogoutResponse signée via la liaison de la requête : une redirection vers la SAML single logout URL pour GET, ou un formulaire que le navigateur poste là-bas pour POST.

Déconnexion initiée par l'IdP​

Lorsqu'un utilisateur se déconnecte de Casdoor, via /api/logout ou via /api/sso-logout, Casdoor envoie une LogoutRequest signée à la SAML single logout URL de chaque application SAML à laquelle l'utilisateur s'est connecté dans les sessions terminées. Il en va de même lorsque Casdoor termine des sessions pour d'autres raisons, par exemple lorsqu'un utilisateur est interdit de connexion, ou lorsqu'une nouvelle connexion dépasse la limite de sessions. Casdoor poste ces demandes depuis le serveur, comme avec la déconnexion back-channel OIDC, et non via le navigateur. Lorsque le SP envoie sa LogoutResponse au même point de terminaison SingleLogoutService, Casdoor vérifie que son Issuer figure dans Redirect URLs et que son statut est Success.

Profil de l'utilisateur dans la réponse​

Par défaut, le SAMLResponse contient trois attributs de l'utilisateur :

Nom d'attribut XMLChamp utilisateur
Emailcourriel
Nom d'affichagedisplayName
Nomname

Si le fournisseur de services a uniquement besoin du NameID et d'aucun attribut, activez Disable SAML attributes sur l'application. Casdoor exclut alors les attributs de la réponse. Cela évite les problèmes d'espace de noms XML avec les fournisseurs de services qui valident strictement la réponse.

Ajouter des attributs SAML​

Si le fournisseur de services nécessite d'autres attributs, ajoutez-les au tableau SAML attributes de l'application. Une valeur peut contenir les variables suivantes : $user.owner, $user.name, $user.displayName, $user.email, $user.id, $user.phone, $user.roles, $user.permissions et $user.groups.

Par exemple, les deux lignes suivantes :

NomFormat du nomValue
https://www.aliyun.com/SAML-Role/Attributes/RoleSessionNameNon spécifié$user.name
https://www.aliyun.com/SAML-Role/Attributes/RoleNon spécifiéacs:ram::1879818006829152:role/$user.roles,acs:ram::1879818006829152:saml-provider/testa

Produisent ces attributs dans la réponse :

<saml:Attribute Name="https://www.aliyun.com/SAML-Role/Attributes/RoleSessionName" NameFormat="urn:oasis:names:tc:SAML:2.0:attrname-format:unspecified">
    <saml:AttributeValue xsi:type="xs:string">admi122n@outlook.com</saml:AttributeValue>
</saml:Attribute>
<saml:Attribute Name="https://www.aliyun.com/SAML-Role/Attributes/Role" NameFormat="urn:oasis:names:tc:SAML:2.0:attrname-format:unspecified">
    <saml:AttributeValue xsi:type="xs:string"> acs:ram::1879818006829152:role/role1,acs:ram::1879818006829152:saml-provider/testa</saml:AttributeValue>
    <saml:AttributeValue xsi:type="xs:string"> acs:ram::1879818006829152:role/role2,acs:ram::1879818006829152:saml-provider/testa</saml:AttributeValue>
</saml:Attribute>

Contrôler la signature de l'assertion​

Casdoor signe toujours la réponse SAML. Pour signer également l'assertion à l'intérieur de la réponse, activez Enable SAML assertion signature sur l'application. Cette option est désactivée par défaut.

Les versions 2.81.0 à 2.247.x signaient toujours l'assertion. Certains fournisseurs de services, tels que Sentry, rejettent les réponses avec une assertion signée ; depuis la version 2.248.0, Casdoor ne signe que l'enveloppe de la réponse sauf si cette option est activée. La réponse signée garantit également l'authenticité de l'assertion.

Testez avec un fournisseur de services Go​

gosaml2 est une implémentation SAML 2.0 pour les fournisseurs de services en Go. Le programme suivant l'utilise pour tester Casdoor en tant qu'IdP.

L'exemple suppose que Casdoor tourne sur http://localhost:7001/ et utilise l'application app-built-in de l'organisation built-in.

  1. Ajoutez http://localhost:6900/acs/example et http://localhost:6900/saml/acs/example aux Redirect URLs de app-built-in.

  2. Exécutez le programme :

    import (
        "crypto/x509"
        "fmt"
        "net/http"

        "io/ioutil"

        "encoding/base64"
        "encoding/xml"

        saml2 "github.com/russellhaering/gosaml2"
        "github.com/russellhaering/gosaml2/types"
        dsig "github.com/russellhaering/goxmldsig"
    )

    func main() {
        res, err := http.Get("http://localhost:7001/api/saml/metadata?application=admin/app-built-in")
        if err != nil {
            panic(err)
        }

        rawMetadata, err := ioutil.ReadAll(res.Body)
        if err != nil {
            panic(err)
        }

        metadata := &types.EntityDescriptor{}
        err = xml.Unmarshal(rawMetadata, metadata)
        if err != nil {
            panic(err)
        }

        certStore := dsig.MemoryX509CertificateStore{
            Roots: []*x509.Certificate{},
        }

        for _, kd := range metadata.IDPSSODescriptor.KeyDescriptors {
            for idx, xcert := range kd.KeyInfo.X509Data.X509Certificates {
                if xcert.Data == "" {
                    panic(fmt.Errorf("metadata certificate(%d) must not be empty", idx))
                }
                certData, err := base64.StdEncoding.DecodeString(xcert.Data)
                if err != nil {
                    panic(err)
                }

                idpCert, err := x509.ParseCertificate(certData)
                if err != nil {
                    panic(err)
                }

                certStore.Roots = append(certStore.Roots, idpCert)
            }
        }

        randomKeyStore := dsig.RandomKeyStoreForTest()

        sp := &saml2.SAMLServiceProvider{
            IdentityProviderSSOURL:      metadata.IDPSSODescriptor.SingleSignOnServices[0].Location,
            IdentityProviderIssuer:      metadata.EntityID,
            ServiceProviderIssuer:       "http://localhost:6900/acs/example",
            AssertionConsumerServiceURL: "http://localhost:6900/v1/_saml_callback",
            SignAuthnRequests:           true,
            AudienceURI:                 "http://localhost:6900/saml/acs/example",
            IDPCertificateStore:         &certStore,
            SPKeyStore:                  randomKeyStore,
        }

        http.HandleFunc("/v1/_saml_callback", func(rw http.ResponseWriter, req *http.Request) {
            err := req.ParseForm()
            if err != nil {
                rw.WriteHeader(http.StatusBadRequest)
                return
            }
            samlReponse := req.URL.Query().Get("SAMLResponse")
            assertionInfo, err := sp.RetrieveAssertionInfo(samlReponse)
            if err != nil {
                fmt.Println(err)
                rw.WriteHeader(http.StatusForbidden)
                return
            }
            fmt.Println(assertionInfo)
            if assertionInfo.WarningInfo.InvalidTime {
                fmt.Println("here12:", assertionInfo.WarningInfo.InvalidTime)
                rw.WriteHeader(http.StatusForbidden)
                return
            }

            if assertionInfo.WarningInfo.NotInAudience {
                fmt.Println(assertionInfo)
                fmt.Println("here13:", assertionInfo.WarningInfo.NotInAudience)
                rw.WriteHeader(http.StatusForbidden)
                return
            }

            fmt.Fprintf(rw, "NameID: %s\n", assertionInfo.NameID)

            fmt.Fprintf(rw, "Assertions:\n")

            for key, val := range assertionInfo.Values {
                fmt.Fprintf(rw, "  %s: %+v\n", key, val)
            }
            fmt.Println(assertionInfo.Values.Get("FirstName"))
            fmt.Fprintf(rw, "\n")

            fmt.Fprintf(rw, "Warnings:\n")
            fmt.Fprintf(rw, "%+v\n", assertionInfo.WarningInfo)
        })

        println("Visit this URL To Authenticate:")
        authURL, err := sp.BuildAuthURL("")
        if err != nil {
            panic(err)
        }

        println(authURL)

        println("Supply:")
        fmt.Printf("  SP ACS URL      : %s\n", sp.AssertionConsumerServiceURL)

        err = http.ListenAndServe(":6900", nil)
        if err != nil {
            panic(err)
        }
    }

    La console affiche :

    Visit this URL To Authenticate:
    http://localhost:7001/login/saml/authorize/admin/app-built-in?SAMLRequest=lFVbk6K8Fv0rFvNo2QR...
    Supply:
      SP ACS URL      : http://localhost:6900/v1/_saml_callback

  3. Ouvrez l'URL. La page de connexion Casdoor s'affiche.

  4. Connectez-vous. Le programme affiche la réponse SAML.
