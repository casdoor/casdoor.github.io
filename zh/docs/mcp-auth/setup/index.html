MCP 认证配置

本指南把 Casdoor 配置为 MCP 服务器的授权服务器：先在 Casdoor 中配置应用、scope 和同意页，再在 MCP 服务器上实现受保护资源元数据和令牌校验。

先决条件​

  • 一个运行中的 Casdoor 实例（服务器安装 或 Casdoor Cloud）
  • Casdoor 管理员权限
  • MCP 服务器的公网地址（例如 https://your-mcp-server.com）

第一部分：Casdoor 配置​

步骤 1：创建一个应用​

  1. 进入 Applications → Add Application
  2. 填写基本信息：
    • Name：取一个有描述性的名字（例如 "My Files MCP Server"）
    • Organization：选择拥有这个应用的组织
    • Category：选择 Agent（会开启 MCP 专属功能）
    • Type：选择 MCP（Category 为 Agent 时自动设置）

Agent 类别加 MCP 类型会针对程序化访问优化应用，并启用自定义 scope 配置。

参考：Agent 与 Default 应用的区别见 应用类别。

第 2 步：配置 Redirect URI​

Redirect URI 是授权后 Casdoor 把用户送回的地址。对于 MCP 服务器，开发和生产环境的 URI 都要添加。

  1. 在应用设置中找到 Redirect URIs
  2. 添加本地测试用的开发 URI：
    • http://localhost:* (wildcard for any local port)
    • http://127.0.0.1:*
  3. 添加部署用的生产 URI：
    • https://your-mcp-server.com/oauth/callback
    • 服务器用到的其他回调地址

配置示例：

http://localhost:*
http://127.0.0.1:*
https://mcp.example.com/oauth/callback

安全提示：通配符 URI（*）开发时方便，但生产环境应当收紧。生产部署建议使用精确地址。

第 3 步：设置授权类型​

配置应用支持哪些 OAuth 授权类型。

  1. 找到 Grant types 设置
  2. 启用这些授权类型：
    • ✅ authorization_code：MCP 的主要 OAuth 流程
    • ✅ refresh_token：无需重新认证即可长期访问

不要启用：

  • ❌ implicit：已弃用，用于 MCP 不安全
  • ❌ password：与 MCP 的授权流程不兼容

第 4 步：定义自定义 Scope​

自定义 scope 代表 MCP 服务器中工具所需的权限。每个 scope 应对应一项逻辑能力。

  1. 滚动到 Custom Scopes 部分
  2. 为每个要定义的权限点击 Add Scope
  3. 每个 scope 需要填写：
    • Name：使用 resource:action 格式（例如 files:read、db:query）
    • Display Name：简短易懂的名称（例如 "Read Files"）
    • Description：说明这个 scope 允许做什么（例如 "View and download files from your storage"）

文件管理类 MCP 服务器的 scope 示例：

Name显示名称描述
files:read读取文件查看和下载存储中的文件
files:write写文件在您的存储中创建、修改和删除文件
files:list列出文件查看目录中的文件名和元数据

数据库类 MCP 服务器的 scope 示例：

Name显示名称描述
db:query查询数据库执行只读数据库查询
db:modify修改数据库创建、更新和删除数据库记录
db:admin数据库管理管理表结构、数据表和数据库设置

最佳实践：

  • scope 要细，让用户可以只授予部分权限
  • 命名保持一致（例如 resource:action 模式）
  • 描述写清楚，用户授权时会看到
  • 先少定义几个 scope，随工具演进再增加

参考：详细说明见 自定义 Scope。

第 5 步：配置同意策略​

同意页会向用户展示他们要授予的权限。

  1. 找到 Consent Policy 设置
  2. 选择其中之一：
    • Always：每次授权都显示同意页（敏感数据推荐）
    • Once：只在首次授权时显示（频繁访问时体验更好）
    • Never：跳过同意页（仅用于可信的自有应用）

对于工具能力较强（文件访问、修改数据库）的 MCP 服务器，建议选 Always 或 Once，确保用户清楚自己在授权什么。

第 6 步：启用动态客户端注册（可选）​

如果你的 MCP 服务器会分发给需要自行注册客户端的最终用户：

  1. 进入 Organization Settings（不是应用设置）
  2. 找到 Enable Dynamic Client Registration
  3. 切换为 Enabled

启用后，任何人都可以通过 /api/oauth/register 注册新的 OAuth 客户端，无需管理员介入。对于 Claude Desktop 这类首次使用时自动注册的 MCP 客户端，这是必需的。

参考：实现细节见 动态客户端注册。

第 7 步：记下发现地址​

MCP 服务器校验令牌时需要这些 Casdoor 地址：

  • 授权服务器元数据：https://your-casdoor.com/.well-known/oauth-authorization-server
  • OIDC 发现：https://your-casdoor.com/.well-known/openid-configuration
  • JWKS 接口：https://your-casdoor.com/.well-known/jwks

验证这些接口：

# Check OAuth metadata
curl https://your-casdoor.com/.well-known/oauth-authorization-server

# Check OIDC discovery
curl https://your-casdoor.com/.well-known/openid-configuration

# Check JWKS (JSON Web Key Set for token validation)
curl https://your-casdoor.com/.well-known/jwks

第二部分：MCP 服务器配置​

接下来把 MCP 服务器配置为使用 Casdoor 认证。

第 1 步：实现受保护资源元数据接口​

MCP 服务器必须在 /.well-known/oauth-protected-resource 提供一个 JSON 文档，告诉客户端去哪里找授权服务器。

接口：GET /.well-known/oauth-protected-resource

响应：

{
  "resource": "https://your-mcp-server.com",
  "authorization_servers": ["https://your-casdoor.com"],
  "scopes_supported": [
    "files:read",
    "files:write",
    "files:list"
  ],
  "bearer_methods_supported": ["header"]
}

字段说明：

  • resource：MCP 服务器的公网地址（作为令牌中的 aud 声明）
  • authorization_servers：OAuth 服务器数组（只填 Casdoor 的地址）
  • scopes_supported：第 4 步中定义的自定义 scope
  • bearer_methods_supported：MCP 固定为 ["header"]（令牌放在 Authorization 请求头中）

实现示例：

Python (Flask)​

from flask import Flask, jsonify

app = Flask(__name__)

@app.route('/.well-known/oauth-protected-resource')
def protected_resource_metadata():
    return jsonify({
        "resource": "https://your-mcp-server.com",
        "authorization_servers": ["https://your-casdoor.com"],
        "scopes_supported": ["files:read", "files:write", "files:list"],
        "bearer_methods_supported": ["header"]
    })

Node.js (Express)​

const express = require('express');
const app = express();

app.get('/.well-known/oauth-protected-resource', (req, res) => {
  res.json({
    resource: 'https://your-mcp-server.com',
    authorization_servers: ['https://your-casdoor.com'],
    scopes_supported: ['files:read', 'files:write', 'files:list'],
    bearer_methods_supported: ['header']
  });
});

Go (net/http)​

package main

import (
    "encoding/json"
    "net/http"
)

type ProtectedResourceMetadata struct {
    Resource                 string   `json:"resource"`
    AuthorizationServers     []string `json:"authorization_servers"`
    ScopesSupported          []string `json:"scopes_supported"`
    BearerMethodsSupported   []string `json:"bearer_methods_supported"`
}

func protectedResourceHandler(w http.ResponseWriter, r *http.Request) {
    metadata := ProtectedResourceMetadata{
        Resource:                 "https://your-mcp-server.com",
        AuthorizationServers:     []string{"https://your-casdoor.com"},
        ScopesSupported:          []string{"files:read", "files:write", "files:list"},
        BearerMethodsSupported:   []string{"header"},
    }
    
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(metadata)
}

func main() {
    http.HandleFunc("/.well-known/oauth-protected-resource", protectedResourceHandler)
    http.ListenAndServe(":8080", nil)
}

第 2 步：对未授权请求返回 401 质询​

MCP 客户端不带有效令牌连接时，服务器必须返回 401 响应，并带上 WWW-Authenticate 响应头。

响应头：

HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="MCP Server", resource_metadata="https://your-mcp-server.com/.well-known/oauth-protected-resource"
Content-Type: application/json

响应体：

{
  "error": "unauthorized",
  "message": "Authentication required. Use OAuth 2.0 with the authorization server listed in the Protected Resource Metadata."
}

WWW-Authenticate 响应头中的 resource_metadata 参数告诉客户端去哪里找受保护资源元数据接口。

第 3 步：校验 JWT 令牌​

客户端带 Bearer 令牌发起请求时，服务器必须用 Casdoor 的 JWKS 接口校验它。

令牌校验步骤：

  1. 从 Authorization: Bearer <token> 请求头中 取出令牌
  2. 从 https://your-casdoor.com/.well-known/jwks 获取 JWKS
  3. 用 JWKS 中的公钥 校验签名
  4. 检查 aud 声明 是否与服务器的资源 URI（https://your-mcp-server.com）一致
  5. 检查 exp 声明，确保令牌没有过期
  6. 从 scope 声明（空格分隔的字符串）中 取出 scope

Python、Node.js 和 Go 的完整代码示例见 第三方集成。

第 4 步：在工具处理程序中检查 scope​

每个 MCP 工具都应检查令牌是否包含所需的 scope。

示例：read_file 工具需要 files:read scope：

def read_file(token_scopes, file_path):
    if "files:read" not in token_scopes:
        raise PermissionError("Missing required scope: files:read")
    
    # Proceed with file reading
    with open(file_path, 'r') as f:
        return f.read()

最佳实践：

  • 执行任何特权操作前先检查 scope
  • 缺少 scope 时返回清晰的错误信息
  • 记录授权失败，便于安全审计

测试配置​

测试受保护资源元数据​

curl https://your-mcp-server.com/.well-known/oauth-protected-resource

预期输出:

{
  "resource": "https://your-mcp-server.com",
  "authorization_servers": ["https://your-casdoor.com"],
  "scopes_supported": ["files:read", "files:write"],
  "bearer_methods_supported": ["header"]
}

测试 401 质询​

curl -i https://your-mcp-server.com/api/mcp

预期响应：

HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="MCP Server", resource_metadata="https://your-mcp-server.com/.well-known/oauth-protected-resource"

用 Claude Desktop（或其他 MCP 客户端）测试​

  1. 把 MCP 客户端配置为连接 https://your-mcp-server.com
  2. 客户端应当能通过受保护资源元数据自动发现 Casdoor
  3. 客户端会把你跳转到 Casdoor 的授权页
  4. 同意后，客户端拿到令牌，就可以调用你的工具了

故障排除​

"Invalid redirect URI" 错误​

问题：Casdoor 拒绝授权请求，报 redirect URI 无效。

解决：确认客户端的 redirect URI 已列在第 2 步（Redirect URIs）中。 Claude Desktop 可能需要 http://localhost:*。

"Token signature verification failed"​

问题：服务器无法校验 Casdoor 的 JWT 令牌。

解决方案：

  • 确认使用的是正确的 JWKS 接口：https://your-casdoor.com/.well-known/jwks
  • 检查服务器系统时钟是否同步（JWT 过期时间对时间敏感）
  • 确认令牌是有效的 JWT（可以用 jwt.io 查看）

"Audience mismatch" 错误​

问题：令牌的 aud 声明与服务器的资源 URI 不一致。

解决：确保受保护资源元数据中的 resource 字段与服务器的公网地址完全一致，包括协议（https://），并且末尾不带斜杠。

同意页没有显示​

问题：用户授权时看不到同意页。

解决：检查第 5 步中的同意策略。如果设为 "Never"，会跳过同意页。改成 "Once" 或 "Always"。
