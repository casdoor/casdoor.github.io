Benutzer aus allen Anwendungen abmelden

Dieser Leitfaden erklärt, wie Sie einen Benutzer mit einer einzigen Anfrage aus allen Anwendungen einer Organisation abmelden und wie Ihre Anwendungen über die Abmeldung informiert werden, damit sie ihre eigenen Sitzungen beenden können.

Lernziele​

  • Rufen Sie den SSO-Logout-Endpunkt für alle Sitzungen oder nur für die aktuelle Sitzung auf.
  • Empfangen und überprüfen Sie Abmeldebenachrichtigungen in Ihren Anwendungen.
  • Empfangen Sie OpenID Connect (OIDC) Back-Channel-Logout-Token.
  • Finden Sie die Ursache heraus, wenn ein Benutzer angemeldet bleibt.

Voraussetzungen​

  • Anwendungen, die Benutzer mit Casdoor anmelden. Siehe Single Sign-On einrichten.
  • Eine Möglichkeit, sich als Benutzer bei der Casdoor-API zu authentifizieren: das Access Token oder das Session-Cookie
  • Zum Empfangen von Benachrichtigungen: ein Benachrichtigungsanbieter auf der Anwendung

Über Single Sign-Out​

Single Sign-Out beendet die Sitzungen eines Benutzers in Casdoor und weist Ihre Anwendungen an, dies ebenfalls zu tun. Typische Anwendungsfälle sind:

  • Sicherheitsvorfälle: Beenden Sie alle Sitzungen eines Kontos gleichzeitig.
  • Organisationsrichtlinien: Melden Sie Benutzer überall ab, wenn sie die Organisation verlassen oder ihre Rollen ändern.
  • Compliance: Stellen Sie sicher, dass ein Benutzer aus allen Systemen abgemeldet ist.
  • Benutzeranfrage: Lassen Sie Benutzer sich mit einer einzigen Aktion aus allen Anwendungen abmelden.

Der Parameter logoutAll wählt einen von zwei Modi:

Full sign-out: logoutAll=true (default)Current session only: logoutAll=false
SessionsDeletes all sessions of the user across all applications of the organizationDeletes the current session
Access tokensExpires all access tokens issued to the userExpires the tokens that were issued in the current session
NotificationContains all session IDs and the hashes of all tokens of the userContains the current session ID and the hashes of all tokens of the user

Verwenden Sie logoutAll=false, wenn sich ein Benutzer auf einem Gerät oder Browser abmeldet und auf den anderen angemeldet bleibt.

Dieser Endpunkt unterscheidet sich vom RP-initiated logout, dem standardmäßigen OIDC-Endsession-Endpunkt, den ein einzelner Client für seine eigene Sitzung aufruft.

Den SSO-Logout-Endpunkt aufrufen​

GET or POST /api/sso-logout?logoutAll=<true|false>
ParameterRequiredDescription
logoutAllNotrue, 1, or omitted: sign out of all sessions. Any other value, such as false or 0: sign out of the current session only

Authentifizieren Sie die Anfrage als Benutzer, entweder mit dem Access Token im Authorization-Header oder mit dem Session-Cookie. Siehe Authentifizierungsmethode wählen.

Aus allen Sitzungen abmelden:

curl -X POST https://door.casdoor.com/api/sso-logout \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"

# Or explicitly specify logoutAll=true
curl -X POST "https://door.casdoor.com/api/sso-logout?logoutAll=true" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"

Nur aus der aktuellen Sitzung abmelden:

curl -X POST "https://door.casdoor.com/api/sso-logout?logoutAll=false" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"

Mit dem Session-Cookie authentifizieren:

curl -X POST https://door.casdoor.com/api/sso-logout \
  --cookie "casdoor_session_id=abc123def456"

Eine erfolgreiche Anfrage gibt Folgendes zurück:

{
  "status": "ok",
  "msg": "",
  "data": ""
}
FieldDescription
status"ok" on success, "error" on failure
msgError message on failure, otherwise empty
dataEmpty for this endpoint

Den Endpunkt von Ihrer Anwendung aus aufrufen​

Im Browser mit fetch:

// Logout from all sessions
fetch('https://door.casdoor.com/api/sso-logout', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${accessToken}`
  },
  credentials: 'include'
})
  .then(response => response.json())
  .then(data => {
    console.log('Logout successful:', data);
    window.location.href = '/login';
  })
  .catch(error => {
    console.error('Logout failed:', error);
  });

// Logout from current session only
fetch('https://door.casdoor.com/api/sso-logout?logoutAll=false', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${accessToken}`
  },
  credentials: 'include'
})
  .then(response => response.json())
  .then(data => {
    console.log('Logged out from current session:', data);
    window.location.href = '/login';
  });

Mit dem Go SDK:

import "github.com/casdoor/casdoor-go-sdk/casdoorsdk"

func logout(w http.ResponseWriter, r *http.Request) {
    // Get the access token from the session or request
    token := getAccessTokenFromSession(r)
    
    // Call the SSO logout endpoint
    err := casdoorsdk.Logout(token)
    if err != nil {
        http.Error(w, "Logout failed", http.StatusInternalServerError)
        return
    }
    
    // Clear local session
    clearSession(w, r)
    
    // Redirect to login page
    http.Redirect(w, r, "/login", http.StatusFound)
}

Mit dem JavaScript SDK:

import Sdk from "casdoor-js-sdk";

const CasdoorSDK = new Sdk({
  serverUrl: "https://door.casdoor.com",
  clientId: "YOUR_CLIENT_ID",
  appName: "YOUR_APP_NAME",
  organizationName: "YOUR_ORG_NAME",
});

async function handleLogout() {
  try {
    // Call the SSO logout endpoint
    await CasdoorSDK.logout();
    
    // Clear local state
    localStorage.removeItem('casdoor_token');
    sessionStorage.clear();
    
    // Redirect to login page
    window.location.href = '/login';
  } catch (error) {
    console.error('Logout failed:', error);
  }
}

Mit dem Python SDK:

from casdoor import CasdoorSDK

sdk = CasdoorSDK(
    endpoint="https://door.casdoor.com",
    client_id="YOUR_CLIENT_ID",
    client_secret="YOUR_CLIENT_SECRET",
    certificate="YOUR_CERT",
    org_name="YOUR_ORG_NAME",
    app_name="YOUR_APP_NAME",
)

def logout(access_token):
    try:
        # Call the SSO logout endpoint
        result = sdk.logout(access_token)
        
        if result['status'] == 'ok':
            # Clear local session
            clear_session()
            return True
        else:
            print(f"Logout failed: {result['msg']}")
            return False
    except Exception as e:
        print(f"Logout error: {e}")
        return False

Unabhängig vom Ergebnis der Anfrage sollten Sie anschließend den lokalen Zustand Ihrer Anwendung löschen: gespeicherte Tokens, zwischengespeicherte Benutzerdaten und lokale Session-Cookies. Ein Benutzer, der sich zum Abmelden entschieden hat, muss als abgemeldet erscheinen, auch wenn die Anfrage an Casdoor fehlgeschlagen ist.

async function logout() {
  try {
    await callSSOLogout();
  } catch (error) {
    console.error('SSO logout failed, clearing local state anyway:', error);
  } finally {
    // Always clear local state
    clearLocalAuthenticationState();
    redirectToLogin();
  }
}

Abmeldebenachrichtigungen empfangen​

Beim Abmelden sendet Casdoor eine Benachrichtigung an jeden Benachrichtigungsanbieter der Anwendung, mit der sich der Benutzer angemeldet hat. Ihre Anwendungen nutzen diese Benachrichtigung, um ihre eigenen Sitzungen für diesen Benutzer zu beenden.

Benachrichtigungsanbieter konfigurieren​

  1. Fügen Sie in der Casdoor-Administratorkonsole einen Benachrichtigungsanbieter hinzu, z. B. vom Typ Custom HTTP, und fügen Sie ihn zur Anwendung hinzu.

  2. Legen Sie für einen Custom-HTTP-Anbieter die folgenden Felder fest:

    FieldValue
    EndpointEndpoint of your application that receives the notification, for example https://app.example.com/api/logout-webhook
    MethodPOST
    Parametercontent. This is the name of the form field that carries the JSON payload

Benachrichtigung lesen​

Casdoor sendet eine POST-Anfrage mit der folgenden Nutzdatenstruktur:

{
  "owner": "org-name",
  "name": "username",
  "displayName": "John Doe",
  "email": "user@example.com",
  "phone": "+1234567890",
  "id": "user-id",
  "event": "sso-logout",
  "sessionIds": ["session-123", "session-456"],
  "accessTokenHashes": ["hash-abc", "hash-def"],
  "nonce": "random-nonce-xyz",
  "timestamp": 1699900000,
  "signature": "hmac-sha256-signature"
}
FieldDescription
sessionIdsIDs of the sessions that were ended
accessTokenHashesSHA-256-Hashes der Zugriffstoken des Benutzers, in beiden Modi, einschließlich bereits abgelaufener Token. Bei logoutAll=false enthält die Liste auch Token anderer Sitzungen, die gültig bleiben, daher sollten Sie zuerst auf sessionIds prüfen. Vergleichen Sie die Hashes mit den Hashes der Token, die Ihre Anwendung verwaltet, um die zu beendenden Sitzungen zu finden
nonceRandom value that protects against replay
timestampUnix time at which Casdoor created the notification
signatureHMAC-SHA256 signature, computed with the client secret of the application

Benachrichtigung überprüfen​

Jeder, der Ihren Endpunkt erreichen kann, kann eine Anfrage daran senden. Bevor Sie auf eine Benachrichtigung reagieren:

  1. Überprüfen Sie die Signatur. In Go:

    // Example verification in Go
    func verifyLogoutNotification(notification *SsoLogoutNotification, clientSecret string) bool {
        data := fmt.Sprintf("%s|%s|%s|%d|%s|%s",
            notification.Owner,
            notification.Name,
            notification.Nonce,
            notification.Timestamp,
            strings.Join(notification.SessionIds, ","),
            strings.Join(notification.AccessTokenHashes, ","))
        
        expectedSignature := hmacSHA256(clientSecret, data)
        return notification.Signature == expectedSignature
    }

    In JavaScript:

    // Example verification in JavaScript
    const crypto = require('crypto');

    function verifyLogoutNotification(notification, clientSecret) {
      const data = `${notification.owner}|${notification.name}|${notification.nonce}|${notification.timestamp}|${notification.sessionIds.join(',')}|${notification.accessTokenHashes.join(',')}`;
      
      const expectedSignature = crypto
        .createHmac('sha256', clientSecret)
        .update(data)
        .digest('hex');
      
      return notification.signature === expectedSignature;
    }

  2. Lehnen Sie Benachrichtigungen ab, die zu alt sind, zum Beispiel älter als fünf Minuten:

    function isNotificationValid(notification) {
      const maxAge = 5 * 60 * 1000; // 5 minutes in milliseconds
      const now = Date.now();
      const notificationTime = notification.timestamp * 1000; // Convert to milliseconds
      
      if (now - notificationTime > maxAge) {
        console.error('Notification is too old, possible replay attack');
        return false;
      }
      
      return verifyLogoutNotification(notification, clientSecret);
    }

  3. Beenden Sie in Ihrer Anwendung die Sitzungen, die mit sessionIds oder accessTokenHashes übereinstimmen.

Vorsicht

Das Client-Secret signiert die Benachrichtigungen. Bewahren Sie es auf dem Server auf, zum Beispiel in einer Umgebungsvariable oder einem Secret Manager, und versenden Sie es niemals im clientseitigen Code.

OIDC Back-Channel-Logout-Token empfangen​

Casdoor unterstützt OpenID Connect Back-Channel Logout 1.0. Wenn sich ein Benutzer über RP-initiated logout abmeldet, sendet Casdoor ein signiertes Logout-Token an jede Anwendung, die eine aktive Sitzung für den Benutzer hat. Jede Anwendung beendet dann ihre eigene Sitzung, von Server zu Server.

  1. Öffnen Sie in der Casdoor-Admin-Konsole die Bearbeitungsseite der Anwendung.
  2. Legen Sie Backchannel logout URL (backchannelLogoutUri) auf den Endpunkt Ihrer Anwendung fest, der das Logout-Token empfängt.

Casdoor sendet eine HTTP-POST-Anfrage mit einem logout_token-Parameter an diese URI. Das Token ist ein JSON Web Token (JWT) mit den Ansprüchen sub und sid sowie dem Ereignis http://schemas.openid.net/event/backchannel-logout. Casdoor überspringt Anwendungen, die keine Back-Channel-Logout-URL haben.

SAML-Anwendungen abmelden​

Für Anwendungen, die Benutzer mit SAML anmelden, sendet Casdoor eine signierte SAML-LogoutRequest an die SAML single logout URL der Anwendung, wenn sich der Benutzer abmeldet, sowohl bei /api/sso-logout als auch bei /api/logout. Ein SAML-Diensteanbieter kann die Abmeldung auch bei Casdoor initiieren. Siehe Single logout.

Fehlerbehebung​

Der Benutzer bleibt bei einigen Anwendungen angemeldet​

  • Prüfen Sie, ob alle Anwendungen Benutzer über Casdoor anmelden und derselben Organisation angehören.
  • Prüfen Sie, ob jede Anwendung das Token bei jeder Anfrage validiert oder auf die Abmelde-Benachrichtigung reagiert. Eine Anwendung, die sich nur auf ihre eigene lokale Sitzung verlässt, bemerkt die Abmeldung nicht.

Ein Token funktioniert nach der Abmeldung weiterhin​

  • Prüfen Sie, ob die Anfrage an /api/sso-logout ging und als der Benutzer authentifiziert wurde.
  • Prüfen Sie, dass Ihre Anwendungen das Ergebnis der Token-Validierung nicht cachen.

Nach einer Abmeldung bleiben die Token-Datensätze in der Datenbank mit ExpiresIn auf 0 gesetzt. Der Introspection-Endpunkt für Tokens und der Refresh-Token-Endpunkt lehnen sie ab. Ein Client, der ein solches Refresh-Token verwendet, erhält den Fehler invalid_grant mit der Meldung "refresh token is expired". Ein Refresh-Token, das Casdoor nicht kennt, zum Beispiel eines, das durch Refresh Token Rotation ersetzt wurde, schlägt mit "refresh token is invalid or revoked" fehl.

Der Endpunkt gibt einen Fehler zurück​

StatusCauseWhat to do
HTTP 401The access token is invalid or expiredClear the local state and send the user to the sign-in page
HTTP 403The user isn't allowed to sign out. This points to a configuration problemCheck the configuration of the application
HTTP 500Error on the serverLog the error and clear the local state anyway
async function logout() {
  try {
    // Replace with your actual Casdoor server URL
    const response = await fetch('https://door.casdoor.com/api/sso-logout', {
      method: 'POST',
      headers: { 'Authorization': `Bearer ${token}` }
    });
    
    if (!response.ok) {
      console.error(`Logout failed with status: ${response.status}`);
      // Clear local state anyway
    }
  } catch (error) {
    console.error('Logout error:', error);
  } finally {
    clearLocalAuthenticationState();
    redirectToLogin();
  }
}
