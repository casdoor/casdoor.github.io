Casdoor 与 Auth0 对比

Auth0 现在属于 Okta，是一项托管的身份服务。 Casdoor 是开源的身份服务器，可以自己部署，也可以使用托管服务。两者支持的协议几乎完全相同，选择哪个主要看由谁来运维、数据放在哪里，以及成本如何随用户量增长。

摘要​

CasdoorAuth0
源代码开源，Apache-2.0闭源商业软件
DeploymentSelf-hosted anywhere, or hostedAuth0 云；企业版提供私有云
计费依据自托管免费；托管版和企业版按固定价格收费按月活跃用户数计费，功能按套餐开放
数据位置你自己的数据库，任意地区或本地机房Auth0 管理的地区
OAuth 2.0、OIDC、SAML是是
CAS、LDAP 服务器、RADIUS 服务器内置不提供
登录页定制在管理后台按应用编辑，支持自定义 HTML 和 CSSUniversal Login 模板和 Actions
自定义逻辑REST API 和 webhookActions（托管的 JavaScript）
AI 智能体和 MCP内置 MCP 服务器；为 MCP 提供 OAuth 2.1 授权服务器单独的附加产品

成本​

Auth0 按月活跃用户计费。做原型时很便宜，但费用可能涨得很快：面向消费者、有大量偶尔使用的用户的产品，每个用户都要付钱；而企业连接、MFA 选项、组织等功能取决于套餐。

自托管 Casdoor 不按用户收费。你只需要为服务器和数据库付费。 If you would rather not run it, the hosted plans are priced per instance, not per user.

控制权与数据驻留​

使用 Auth0 时，用户数据存放在 Auth0 的基础设施中、你所选的地区。

使用 Casdoor 时，用户就是你自己数据库里的行：支持 MySQL、PostgreSQL、SQL Server、Oracle、SQLite 等。因此很容易把身份数据留在特定国家、私有网络内，或者完全隔离的内网部署中，也可以用你平常的工具查询和备份数据。

Auth0 没有的功能​

  • 传统协议。 Casdoor 本身就是 CAS 服务器、LDAP 服务器 和 RADIUS 服务器，老应用、VPN 和 Wi-Fi 控制器都能用同一个用户目录。
  • 本地化的登录提供商。 微信、钉钉、飞书、支付宝、QQ 等都在 70 多个内置 OAuth 提供商 之列。
  • 支付。 商品、支付和订阅 是 Casdoor 的一部分，对于要向同一批用户出售套餐的 SaaS 产品很方便。
  • Casbin 授权。 权限 使用 Casbin 模型（ACL、RBAC、ABAC），你也可以在自己的服务中执行这些模型。

Auth0 更强的地方​

  • 什么都不用运维。 升级、扩容和可用性由 Auth0 负责，并有 SLA 保障。
  • 攻击防护。 机器人检测、泄露密码检测和自适应 MFA 都是成熟的托管功能。 Casdoor 提供人机验证提供商、IP 白名单和 MFA，其余部分需要你自己组合。
  • 生态。 Auth0 有庞大的应用市场、大量快速入门和第三方教程。
  • 合规资质。 如果你的客户要求供应商具备特定认证，大型托管服务商通常已经具备。

AI 智能体和 MCP​

Casdoor 为自己的管理 API 内置了 MCP 服务器，同时也是 你自建 MCP 服务器的 OAuth 2.1 授权服务器：动态客户端注册、PKCE、同意页、资源指示符和基于 JWKS 的令牌校验都开箱即用，不单独收费。

从 Auth0 迁移到 Casdoor​

  1. 从 Auth0 导出用户，再通过管理后台的用户导入或 REST API 导入 Casdoor。
  2. 过渡期间，把 Auth0 作为 OAuth 提供商 加到 Casdoor，这样密码还没迁移过来的用户仍能通过 Auth0 登录。
  3. 把每个应用指向 Casdoor 的 OIDC 发现地址。使用标准 OIDC 库的应用，通常只需要修改 issuer、客户端 ID 和客户端密钥。见 标准 OIDC 客户端。

如何选择​

如果你想要有 SLA 的全托管服务，并且能接受按用量计费，选 Auth0。

如果你想要开源、随规模增长成本可预期、自己掌控身份数据的存放位置、支持传统协议，或者内置 MCP 授权，选 Casdoor。

另见 对比概览。
