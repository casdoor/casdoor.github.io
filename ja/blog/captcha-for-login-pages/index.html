ログインページのCAPTCHAプロバイダー比較: CasdoorにおけるreCAPTCHA、hCaptcha、Turnstile、GeeTest、Alibaba Cloud

2026年11月2日 · 1分読む
Yang Luo
Casdoor Maintainer

グローバルインターネット上のほとんどのサインインおよびサインアップページでは、Cloudflare Turnstileが最も簡単な選択です。無料プランにはチャレンジ回数の上限がなく、デフォルトモードではリスクのある訪問者にのみチェックボックスが表示されます。ユーザーの多くが中国本土にいる場合は、CloudflareはTurnstileが同地域でサポートされていないと述べているため、代わりにAlibaba Cloud CaptchaまたはGeeTestを使用してください。外部サービスなしでcaptchaを動作させる必要がある場合は、Casdoorの組み込み画像captchaを使用してください。Casdoorはこれらのすべてに加え、Google reCAPTCHA (v2およびv3) と hCaptcha を captcha providers としてサポートしており、アプリケーションごとにcaptchaを表示するタイミングを選択できます。

どれを選ぶべきか​

グローバルSaaS​

Cloudflare Turnstile から始めましょう。無料プランではチャレンジ回数が計量されず、Managedモードによりほとんどのユーザーはクリック操作を行う必要がありません。また、サイトをCloudflare経由にする必要もありません。すでにGoogle Cloud上で運用しており、reCAPTCHAのリスクシグナルを活用したい場合は、reCAPTCHA も適していますが、10,000件の無料アセスメント制限に注意してください。繁忙なサインインページやSMSポンピング攻撃により、この制限を1日で超過する可能性があります。hCaptcha も一般的な選択肢ですが、無料プランでは常にチャレンジが表示され、パッシブモードは有料です。

中国本土にユーザーがいるアプリ​

Cloudflareの公式ドキュメントによると、Turnstileは使用できません。reCAPTCHAについては、Googleは www.google.com に到達できない場合の代替ドメインとして www.recaptcha.net を記載しており、Casdoorもこれを使用していますが、依存する前にユーザーのネットワーク環境からテストすべきです。hCaptchaは中国に関する声明を公表していないため、同じアドバイスが適用されます。

安全な選択肢は Alibaba Cloud Captcha と GeeTest です。Alibaba Cloudは1回あたりの料金を公開しており、従量課金で開始できます。そのtracelessモード(Casdoorでは Popup サブタイプを使用)は、Turnstileのような非表示体験に近いものです。GeeTestは30日間のトライアル後に営業チームを通じて販売されます。1つのCasdoorインスタンスで中国とその他の地域両方にサービスを提供する場合、アプリケーションには1つのcaptchaプロバイダーしか設定できないため、異なるcaptchaが必要な場合はオーディエンスを2つのアプリケーションに分割してください。

EUのプライバシー重視のユーザー​

すべてのホスト型CAPTCHAは、訪問者のブラウザに関するデータをベンダーに送信します。法的チームがサインイン経路に第三者を一切含めたくない場合、CasdoorのデフォルトCAPTCHAは、すべてを自社のサーバー内に留める唯一の選択肢です。ホスト型のうち、TurnstileとhCaptchaはいずれもプライバシーを製品の一部として説明しています（それぞれ、チェックに必要なデータに限定する、GDPRおよびEU-米国のData Privacy Frameworkに従う）。reCAPTCHAは_GRECAPTCHACookieを設定します。Googleは、www.recaptcha.netから配信することで、www.google.comが設定する可能性のある他のCookieを回避できると明記しています。どれを選択する場合でも、プライバシーポリシーに記載してください。

セルフホスト、イントラネット、またはオフライン環境​

デフォルトのCAPTCHAを使用してください。キーや外部ネットワークアクセスが必要ないため、エアギャップ環境でも動作します。オフィスネットワーク上のユーザーには表示されず、パブリックインターネットからのリクエストには表示されるように、以下のInternet-Onlyルールと組み合わせて使用してください。

デフォルトのCAPTCHAは、歪んだ数字の画像のみであるため、自動化されたソルバーに対してはこのグループ中最も脆弱です。公開されておりトラフィックが多いサインインページでは、多要素認証と組み合わせるか、ユーザーをパスワードレスサインインに移行して、CAPTCHAが遅延させることを目的としているパスワード推測を排除してください。

CasdoorにおけるCAPTCHAの仕組み​

CategoryをCaptchaに設定し、次のいずれかのタイプを持つプロバイダーを追加します： Default, reCAPTCHA, reCAPTCHA v2, reCAPTCHA v3, hCaptcha, Cloudflare Turnstile, GEETEST, または Aliyun Captcha。その後、Providersタブでアプリケーションに追加します。アプリケーションにはCAPTCHAプロバイダーを1つだけ保持できます。Casdoorは2つ目の保存を拒否します。各ベンダーの設定手順はCAPTCHAプロバイダードキュメントにあります。

CasdoorがCAPTCHAを要求する場所​

同じプロバイダーが複数のアクションを保護し、Casdoorはブラウザだけでなくサーバー側でもトークンを確認します：

  • パスワードによるサインイン。
  • サインアップフォームの送信。
  • メールまたはSMSによる確認コードの送信。これは、サインアップ時のコードステップ、パスワード再設定ページ、コードベースのサインインをカバーします。これは、SMS予算を消費するボットに対する保護です。

CasdoorがCAPTCHAを要求するタイミング​

アプリケーション内のCAPTCHAプロバイダーのRuleによって、表示されるタイミングが決まります：

RuleBehavior
None常に無効。CAPTCHAはオフです
Dynamicユーザーのサインイン失敗回数がアプリケーションのFailed signin limitに達した場合のみ
Always毎回
Internet-OnlyパブリックIPアドレスからのリクエストに対して有効。プライベート、ループバック、その他の非パブリックアドレスからは表示されません

Dynamicはサインインにおいて最も優しい設定です。正当なユーザーはチャレンジを見ることがなく、パスワードを推測している人は数回の失敗後にチャレンジが表示されます。ただし、これは既存のアカウントにのみ適用されます。サインアップ時や、まだアカウントが存在しないアドレスへのコード送信ではトリガーされません。サインアップ時のSMSまたはメールの悪用が懸念される場合は、AlwaysまたはInternet-Onlyを使用してください。

ページ上の表示位置​

アプリケーションのサインイン項目において、Captcha項目には独自のルールがあります： Pop upは必要に応じてダイアログでCAPTCHAを表示し、Inlineはページ上に直接配置します。Change the captchaを参照してください。Alibaba Cloud Captchaには追加のSub typeがあります： EmbedはCasdoorのダイアログ内に表示し、PopupはAlibaba Cloud自身のポップアップに制御を渡します。これはtracelessシーンで必要とされるものです。

ルールを有効にする前に、プロバイダーページのPreviewボタンを使用してキーを確認してください。
