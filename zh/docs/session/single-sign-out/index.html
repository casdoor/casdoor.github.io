单点注销（SSO 登出）

概述​

**单点注销（SSO注销）**可一次性将用户从组织中的每个应用程序注销。当他们从一个应用中注销时，同一单点登录设置中的所有其他应用也会同时注销。

适用场景：

  • 安全事件：检测到安全漏洞时，立即终止所有活动会话
  • 组织范围内的注销策略：当用户离开组织或变更角色时，强制所有服务同时注销
  • 合规要求：确保用户在法规要求时从所有系统彻底注销
  • 用户主动注销：允许用户通过一次操作从所有应用中注销

工作原理​

logoutAll 参数选择模式：

完整单点登录注销（默认，logoutAll=true 或省略）：

  1. 删除所有活动会话：该用户在组织内所有应用程序中的所有活动会话均被终止
  2. 使所有访问令牌失效：向该用户颁发的所有访问令牌将立即失效
  3. 清除当前会话：用户的当前会话和身份验证状态将被清除
  4. 发送注销通知：通知提供商将收到包含所有会话 ID 和令牌哈希的注销事件

这可确保用户已从所有集成的应用程序中完全注销，且在未重新进行身份验证的情况下无法访问任何资源。

仅会话注销 (logoutAll=false):

  1. 删除当前会话：仅终止当前会话
  2. 清除当前身份验证状态：清除用户的当前会话和令牌
  3. 发送定向通知：通知提供商将收到带有当前会话ID和相关访问令牌哈希值的注销事件

发送定向通知：通知提供商将收到带有当前会话ID和相关访问令牌哈希值的注销事件当用户在多个设备上共享账户，或有需要单独管理的并发会话时，这非常有用。

会话级注销通知中包含的访问令牌哈希值可让您的子系统准确识别出哪些令牌需要被失效。当用户从特定浏览器或设备注销时，将令牌哈希值与活动会话进行匹配，并执行针对性的失效处理，而不会影响用户仍保持登录状态的其他设备。

注销通知​

在SSO注销时，Casdoor会向为用户注册的应用程序所配置的每个通知提供商发送请求。通知中包含会话ID、访问令牌哈希值以及加密签名，以实现所有集成系统间安全、同步的注销。

每个通知提供商都会收到一个带有以下有效载荷的POST请求：

{
  "owner": "org-name",
  "name": "username",
  "displayName": "John Doe",
  "email": "user@example.com",
  "phone": "+1234567890",
  "id": "user-id",
  "event": "sso-logout",
  "sessionIds": ["session-123", "session-456"],
  "accessTokenHashes": ["hash-abc", "hash-def"],
  "nonce": "random-nonce-xyz",
  "timestamp": 1699900000,
  "signature": "hmac-sha256-signature"
}

通知字段：

  • sessionIds: 会话ID列表，用于注销登录（支持定向会话失效）
  • accessTokenHashes: 被失效的访问令牌的SHA-256哈希值。现在，完整 SSO 注销和会话级注销均包含这些哈希值，使您的子系统能够将其与活动令牌进行匹配，并执行同步注销
  • nonce：用于防范重放攻击的随机值
  • timestamp：生成通知时的Unix时间戳
  • signature：使用应用程序的客户端密钥计算的HMAC-SHA256签名

验证注销通知​

为防止恶意注销请求，您应验证传入注销通知的签名：

// Example verification in Go
func verifyLogoutNotification(notification *SsoLogoutNotification, clientSecret string) bool {
    data := fmt.Sprintf("%s|%s|%s|%d|%s|%s",
        notification.Owner,
        notification.Name,
        notification.Nonce,
        notification.Timestamp,
        strings.Join(notification.SessionIds, ","),
        strings.Join(notification.AccessTokenHashes, ","))
    
    expectedSignature := hmacSHA256(clientSecret, data)
    return notification.Signature == expectedSignature
}
// Example verification in JavaScript
const crypto = require('crypto');

function verifyLogoutNotification(notification, clientSecret) {
  const data = `${notification.owner}|${notification.name}|${notification.nonce}|${notification.timestamp}|${notification.sessionIds.join(',')}|${notification.accessTokenHashes.join(',')}`;
  
  const expectedSignature = crypto
    .createHmac('sha256', clientSecret)
    .update(data)
    .digest('hex');
  
  return notification.signature === expectedSignature;
}

配置​

要接收注销通知，请在 Casdoor 应用程序的通知提供商设置中配置一个通知提供商（例如自定义 HTTP、Telegram 或 Slack）。对于自定义HTTP提供商：

  • 将接收器设置为您的应用程序的Webhook端点（例如：https://app.example.com/api/logout-webhook）
  • 将方法设置为POST
  • 将标题设置为content（JSON有效负载的参数名称）将标题设置为content（JSON有效负载的参数名称）

您的应用程序随后可以验证签名，检查时间戳以防止重放攻击，并使用会话ID和令牌哈希执行有针对性的注销操作。有关配置通知提供商的更多详细信息，请参阅通知提供商文档。

OIDC 后端通道登出​

Casdoor 支持 OpenID Connect Back-Channel Logout 1.0。用户登出时（RP 发起的登出），Casdoor 会向每个与该用户有活跃会话的应用发送一个签名的 登出令牌，让各应用在服务器之间结束自己的会话。

要启用它，把应用的 Backchannel logout URI（backchannelLogoutUri）设为接收登出令牌的接口。 Casdoor 会向这个地址发送 HTTP POST，带上 logout_token（一个包含 sub、sid 和 http://schemas.openid.net/event/backchannel-logout 事件的 JWT）。没有设置后端通道登出地址的应用会被跳过。

SSO 注销 API​

端点​

GET or POST /api/sso-logout?logoutAll=<true|false>

SSO注销端点同时支持GET和POST请求，使其能够灵活适应不同的集成场景。

参数​

  • logoutAll（可选）：控制登出范围。接受 true、1 或空字符串（默认值：为向后兼容而设为 true）
    • true 或 1 或空：
    • 任何其他值（例如 false、0）：仅从当前会话注销

身份验证​

此端点要求用户已通过身份验证。使用 Casdoor 支持的任何身份验证方法：

  • 访问令牌：将访问令牌包含在Authorization标头中
  • 会话Cookie：使用登录时设置的会话Cookie
  • 客户端凭据：在机器对机器场景中，使用应用程序的客户端 ID 和密钥

有关身份验证方法的更多详情，请参阅Casdoor 公共 API 文档。

请求示例​

从所有会话注销（默认）​

curl -X POST https://door.casdoor.com/api/sso-logout \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"

# Or explicitly specify logoutAll=true
curl -X POST "https://door.casdoor.com/api/sso-logout?logoutAll=true" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"

仅登出当前会话​

curl -X POST "https://door.casdoor.com/api/sso-logout?logoutAll=false" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"

使用会话 Cookie​

curl -X POST https://door.casdoor.com/api/sso-logout \
  --cookie "casdoor_session_id=abc123def456"

使用 JavaScript Fetch API​

// Logout from all sessions
fetch('https://door.casdoor.com/api/sso-logout', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${accessToken}`
  },
  credentials: 'include'
})
  .then(response => response.json())
  .then(data => {
    console.log('Logout successful:', data);
    window.location.href = '/login';
  })
  .catch(error => {
    console.error('Logout failed:', error);
  });

// Logout from current session only
fetch('https://door.casdoor.com/api/sso-logout?logoutAll=false', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${accessToken}`
  },
  credentials: 'include'
})
  .then(response => response.json())
  .then(data => {
    console.log('Logged out from current session:', data);
    window.location.href = '/login';
  });

响应​

API 返回标准 Casdoor 响应：

{
  "status": "ok",
  "msg": "",
  "data": ""
}

响应字段：

  • status：表示操作是成功("ok")还是失败("error")
  • msg：如果操作失败，则包含错误信息；否则为空
  • data：API 返回的附加数据，通常在注销操作中为空

在您的应用中实现 SSO 注销​

使用 Casdoor SDK​

大多数 Casdoor SDK 都提供了对 SSO 注销的内置支持。以下是不同平台的示例：

Go SDK​

import "github.com/casdoor/casdoor-go-sdk/casdoorsdk"

func logout(w http.ResponseWriter, r *http.Request) {
    // Get the access token from the session or request
    token := getAccessTokenFromSession(r)
    
    // Call the SSO logout endpoint
    err := casdoorsdk.Logout(token)
    if err != nil {
        http.Error(w, "Logout failed", http.StatusInternalServerError)
        return
    }
    
    // Clear local session
    clearSession(w, r)
    
    // Redirect to login page
    http.Redirect(w, r, "/login", http.StatusFound)
}

JavaScript SDK​

import Sdk from "casdoor-js-sdk";

const CasdoorSDK = new Sdk({

async function handleLogout() {

from casdoor import CasdoorSDK

sdk = CasdoorSDK(

手动实现​

如果没有Casdoor SDK，请通过调用注销端点实现SSO注销：

async function logout() {
  const accessToken = localStorage.getItem('access_token');
  
  try {
    // Use the full Casdoor server URL in your application
    const response = await fetch('https://door.casdoor.com/api/sso-logout', {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${accessToken}`,
        'Content-Type': 'application/json'
      },
      credentials: 'include'
    });
    
    const result = await response.json();
    
    if (result.status === 'ok') {
      // Clear local storage
      localStorage.removeItem('access_token');
      localStorage.removeItem('user_info');
      sessionStorage.clear();
      
      // Redirect to login page
      window.location.href = '/login';
    } else {
      console.error('Logout failed:', result.msg);
    }
  } catch (error) {
    console.error('Logout error:', error);
  }
}

最佳实践​

1. 清除本地状态​

调用SSO注销端点后，务必清除所有本地认证状态：

  • 从本地存储或会话存储中移除访问令牌
  • 清除任何缓存的用户信息
  • 使任何本地会话Cookie失效
  • 将应用状态重置为已注销状态

. 优雅地处理注销错误​

即使单点登录注销端点失败，你也仍应清除本地身份验证状态，以确保用户在你的应用中显示为已注销：

async function logout() {
  try {
    await callSSOLogout();
  } catch (error) {
    console.error('SSO logout failed, clearing local state anyway:', error);
  } finally {
    // Always clear local state
    clearLocalAuthenticationState();
    redirectToLogin();
  }
}

3. 提供用户反馈​

向用户清晰地反馈注销流程：

async function logout() {
  // Show loading indicator
  showLoadingIndicator('Logging out...');
  
  try {
    await callSSOLogout();
    showSuccessMessage('Logged out successfully');
  } catch (error) {
    showErrorMessage('Logout failed, but you have been logged out locally');
  } finally {
    clearLocalAuthenticationState();
    // Redirect after a short delay to allow users to see the message
    setTimeout(() => redirectToLogin(), 1000);
  }
}

4. 实现注销超时​

为注销请求设置合理的超时时间，防止用户无限期等待：

async function logout() {
  const timeout = 5000; // 5 seconds
  
  try {
    await Promise.race([
      callSSOLogout(),
      new Promise((_, reject) => 
        setTimeout(() => reject(new Error('Logout timeout')), timeout)
      )
    ]);
  } catch (error) {
    console.error('Logout error:', error);
  } finally {
    clearLocalAuthenticationState();
    redirectToLogin();
  }
}

安全注意事项​

1. 验证注销通知签名​

始终验证注销通知的HMAC-SHA256签名，以防止恶意注销请求。签名是使用您的应用程序的客户端密钥计算得出的，并包含所有关键字段（所有者、名称、随机数、时间戳、会话ID、访问令牌哈希值）。拒绝任何签名无效的通知。

. 检查通知时间戳​

实施时间戳验证，以防止重放攻击。拒绝过时的通知（例如，超过5分钟）：

function isNotificationValid(notification) {
  const maxAge = 5 * 60 * 1000; // 5 minutes in milliseconds
  const now = Date.now();
  const notificationTime = notification.timestamp * 1000; // Convert to milliseconds
  
  if (now - notificationTime > maxAge) {
    console.error('Notification is too old, possible replay attack');
    return false;
  }
  
  return verifyLogoutNotification(notification, clientSecret);
}

3. 安全通信​

调用SSO注销端点时始终使用HTTPS，以防止令牌被拦截：

// ✅ Good: Uses HTTPS
const logoutUrl = 'https://door.casdoor.com/api/sso-logout';

// ❌ Bad: Uses HTTP (insecure)
const logoutUrl = 'http://door.casdoor.com/api/sso-logout';

4. 令牌验证​

Casdoor 在处理注销请求前会验证访问令牌。在发出注销调用之前，请确保您的令牌有效且未过期。

5. CSRF保护​

使用会话Cookie进行身份验证时，请确保启用CSRF保护，以防止未经授权的注销请求：

// Include CSRF token in the request headers
// Replace with your actual Casdoor server URL
fetch('https://door.casdoor.com/api/sso-logout', {
  method: 'POST',
  headers: {
    'X-CSRF-Token': getCsrfToken()
  },
  credentials: 'include'
});

6. 保护客户端密钥​

请妥善保管您应用的客户端密钥。它用于对注销通知进行签名，因此一旦泄露，攻击者可能伪造有效的注销请求。请将其安全存储（例如，存储在环境变量或密钥管理系统中），切勿在客户端代码中暴露。

7. 审计日志记录​

请考虑记录登出事件，以用于安全审计和合规性：

func logout(userID string, token string) error {
    // Call SSO logout
    err := casdoorsdk.Logout(token)
    
    // Log the logout event
    auditLog.Info(map[string]interface{}{
        "event": "sso_logout",
        "user_id": userID,
        "timestamp": time.Now(),
        "success": err == nil,
    })
    
    return err
}

故障排除​

所有应用程序中登出均无法正常工作​

如果用户在单点登录注销后仍保持某些应用程序的登录状态：

  1. 验证应用程序集成：确保所有应用程序均已正确集成至Casdoor，并使用相同的组织
  2. 检查令牌验证：确保所有应用程序在每次请求时都对令牌进行验证
  3. 审查会话管理：应用程序不应仅依赖本地会话；必须使用Casdoor对令牌进行验证

注销后令牌仍有效​

如果访问令牌或刷新令牌在注销后仍有效：

  1. 验证注销端点：确保您调用的是正确的端点（/api/sso-logout）
  2. 检查身份验证：确保您在注销请求中发送了有效的身份验证凭据
  3. 审查令牌缓存：确保应用程序不会缓存令牌验证结果

单点登录注销后，访问令牌和刷新令牌均会失效。令牌记录仍保留在数据库中，且ExpiresIn设置为0，但Casdoor的令牌内省和刷新令牌端点将拒绝这些令牌。当客户端在注销后尝试使用刷新令牌时，将收到一条“refresh token 无效、已过期或已被撤销”的invalid_grant错误消息。这可确保会话完全终止，即使令牌尚未达到其原始过期时间，也能防止令牌被重复使用。

注销端点返回错误​

常见错误场景：

  • 401 未授权: 访问令牌无效或已过期。清除本地状态并重定向至登录。
  • 403 禁止访问: 用户没有注销权限。这种情况很少见，可能表明存在配置问题。
  • 500 内部服务器错误：服务器端错误。记录错误并无论如何都清除本地状态。
async function logout() {
  try {
    // Replace with your actual Casdoor server URL
    const response = await fetch('https://door.casdoor.com/api/sso-logout', {
      method: 'POST',
      headers: { 'Authorization': `Bearer ${token}` }
    });
    
    if (!response.ok) {
      console.error(`Logout failed with status: ${response.status}`);
      // Clear local state anyway
    }
  } catch (error) {
    console.error('Logout error:', error);
  } finally {
    clearLocalAuthenticationState();
    redirectToLogin();
  }
}
