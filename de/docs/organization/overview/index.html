Organisationen

Eine Organisation ist die Einheit, in der Casdoor Benutzer und Anwendungen verwaltet. Ein Benutzer, der sich bei einer Organisation angemeldet hat, kann alle Anwendungen dieser Organisation öffnen, ohne sich erneut anmelden zu müssen.

Die Organisation, die Sie für eine Anwendung oder einen Provider auswählen, bestimmt, welche Benutzer sich bei der Anwendung anmelden können und wo der Provider verfügbar ist.

Sie bearbeiten eine Organisation in der Casdoor Admin-Konsole unter User Management > Organizations. Die Bearbeitungsseite enthält die Tabs Basic, Password type, Account items und Advanced. Diese Seite beschreibt die allgemeinen Einstellungen. Andere Seiten dieses Abschnitts behandeln die Kontoseite, die Passwortkomplexität, den Passwort-Obfuskator, das Theme, MFA-Einträge, Gruppen und die Einträge des Audit-Logs. LDAP wird ebenfalls pro Organisation konfiguriert. Siehe LDAP.

Anmeldeseite einer Organisation​

Benutzer melden sich normalerweise über eine Anwendung an. Sie können sich auch auf der Anmeldeseite ihrer Organisation anmelden, unter /login/<organization-name>. Auf der Demo-Seite beispielsweise: https://door.casdoor.com/login/casbin.

Wenn sich ein Benutzer über diese URL anmeldet, merkt sich Casdoor die Organisation. Wenn die Sitzung abläuft, leitet Casdoor den Benutzer zurück zur Anmeldeseite derselben Organisation.

Organisationsnamen​

Der Name einer Organisation darf nicht admin oder app sein, da Casdoor diese Namen intern verwendet. Das Erstellen oder Umbenennen einer Organisation in einen dieser Namen schlägt mit the organization name: <name> is reserved fehl.

Logo im dunklen Theme​

Aktivieren Sie auf dem Tab Basic Enable dark logo, um Logo dark festzulegen, ein Logo für das dunkle Theme. Die Seite zeigt eine Vorschau auf schwarzem Hintergrund. Casdoor zeigt dieses Logo in der Seitenleiste der Casdoor Admin-Konsole an, wenn die Konsole das dunkle Theme verwendet. Wenn Logo dark leer ist, zeigt Casdoor Logo an. Wenn Sie Enable dark logo deaktivieren, wird Logo dark gelöscht.

Die Anmelde- und Registrierungsseiten verwenden nicht das Logo der Organisation. Sie zeigen die Logos der Anwendung, siehe Terminologie der Anwendung.

Passwort-Speicherung​

Password type legt den Algorithmus fest, mit dem Casdoor die Passwörter der Benutzer der Organisation speichert. Neue Organisationen verwenden bcrypt.

saltSHA-256SHA-256 is a cryptographic hash function that produces a 256-bit value.—
md5-saltMD5MD5 is a widely used but cryptographically weak hash (128-bit).Discuz!
bcryptbcryptbcrypt hashes and salts passwords securely. Default for new organizations.Spring Boot, WordPress
pbkdf2-saltSHA-256 and PBKDF2PBKDF2 is a key derivation function resistant to dictionary and rainbow-table attacks. Use when importing users via the Keycloak syncer.Keycloak
sha512-saltSHA-512SHA-512 of the password and the salt, stored as a hexadecimal string.—

Passwort-Salt​

Die Algorithmen salt, sha512-salt, md5-salt, pbkdf2-salt und pbkdf2-django verwenden einen Salt. Password salt steuert, woher der Salt kommt:

Password saltSaltUse it when
SetAll users of the organization share this saltYou need hashes that are compatible with another system
EmptyCasdoor generates a random salt for each user and stores it with the password hashYou set up a new organization. This is the recommended setting, because it limits the use of precomputed hash tables

Permanente Avatare​

Wenn sich ein Benutzer über einen OAuth-Provider wie GitHub oder Google anmeldet, speichert Casdoor die URL des Avatars beim Provider. Wenn der Provider diese URL später ändert oder entfernt, wird der Avatar ungültig.

Aktivieren Sie Use permanent avatar, damit Casdoor den Avatar herunterlädt und in seinen eigenen Storage-Provider hochlädt. Die URL bleibt dann stabil. Casdoor lädt einen Avatar nur hoch, wenn er neu ist oder sich geändert hat.

E-Mail als Benutzername​

Aktivieren Sie Use Email as username, um Benutzer ohne separaten Benutzernamen zu registrieren. Dann gilt:

  • Bei der Registrierung wird die E-Mail-Adresse zum Benutzernamen, wenn das Feld für den Benutzernamen ausgeblendet ist.
  • Wenn ein Benutzer die E-Mail-Adresse ändert, ändert sich der Benutzername mit ihr.

Softe Löschung​

Standardmäßig wird ein gelöschter Benutzer aus der Datenbank entfernt.

Mit aktivierter Soft deletion wird ein gelöschter Benutzer nur als gelöscht markiert:

  • Der Benutzer bleibt in der Benutzerliste, mit ausgewähltem Is deleted und einem Deleted time.
  • Der Benutzer kann sich nicht mehr anmelden, und Casdoor widerruft die Tokens und Sitzungen des Benutzers sofort.
  • Um den Benutzer wiederherzustellen, deaktivieren Sie Is deleted auf der Bearbeitungsseite des Benutzers.
  • Um den Benutzer endgültig zu entfernen, löschen Sie den Benutzer ein zweites Mal.

Wann Casdoor die Tokens eines Benutzers widerruft​

Casdoor lässt alle Tokens eines Benutzers in jeder Anwendung ablaufen, wenn:

  • Der Benutzer gelöscht oder soft-gelöscht wird.
  • Ein Administrator Is forbidden für den Benutzer aktiviert. Casdoor beendet auch die Sitzungen des Benutzers, siehe Benutzer sperren oder löschen.
  • Das Passwort des Benutzers über POST /api/set-password geändert wird. Dies umfasst die Kontoseite, die Bearbeitungsseite des Benutzers und die Seite zum Zurücksetzen des Passworts.

Die Anwendungen des Benutzers müssen den Benutzer dann erneut anmelden.

Anmeldung über mehrere Anwendungen hinweg​

Auf dem Tab Basic begrenzt Enable exclusive signin across applications die Anzahl der Browser-Sitzungen, die ein Benutzer der Organisation über alle Anwendungen hinweg behält. Max sessions erscheint, wenn der Schalter aktiviert ist, und legt diese Anzahl fest. Leer oder 1 behält nur die aktuelle Sitzung bei. Casdoor wendet die Einstellung der eigenen Organisation des Benutzers an, auch wenn sich der Benutzer über eine freigegebene Anwendung einer anderen Organisation anmeldet. Siehe Exklusive Anmeldung.

Admin-Konsole deaktivieren​

Aktivieren Sie Disable console auf der Registerkarte Basic, um Casdoor nur als Identitätsanbieter für die regulären Benutzer der Organisation zu verwenden. Wenn sich ein regulärer Benutzer beim Casdoor-Admin-Konsol anmeldet, zeigt Casdoor eine Seite mit HTTP 403, dem Titel Unauthorized, dem Text "The Casdoor console is disabled for the regular users of this organization" und einer Logout-Schaltfläche an.

Die Einstellung wirkt sich nicht aus auf:

  • Die Anmelde-Seiten sowie die OAuth 2.0- und OpenID Connect (OIDC)-Flows von Anwendungen. Benutzer melden sich wie gewohnt bei Ihren Anwendungen an.
  • Organisationsadministratoren und globale Administratoren. Diese können die Konsole nutzen.
  • Die MFA-Einrichtungsseite (/mfa/setup), sodass Benutzer weiterhin eine erforderliche MFA-Methode einrichten können.
Vorsicht

Nur das Frontend der Konsole erzwingt Disable console. Die Casdoor-API bleibt für Benutzer entsprechend ihren eigenen Berechtigungen verfügbar.

Standardeinstellungen für neue Anwendungen​

Zwei Einstellungen auf der Registerkarte Advanced füllen die Token-Einstellungen von Anwendungen, die später in der Organisation erstellt werden. Vorhandene Anwendungen bleiben unverändert.

SettingDescription
Default token format (defaultTokenFormat)JWT, JWT-Empty, JWT-Custom, or JWT-Standard. Casdoor uses it for a new application that has no Token format. Empty means JWT
Default token fields (defaultTokenFields)Claims für eine neue Anwendung, die keine Token fields hat. Die Optionen sind dieselben wie für Token fields einer Anwendung, und Sie können andere Werte eingeben. Leer bedeutet keine Felder

Das Formular für neue Anwendungen in der Konsole lässt beide Felder der Anwendung leer, sodass diese Standardwerte verwendet werden. Anwendungen, die über Dynamic Client Registration erstellt werden, erhalten sie ebenfalls. Weitere Informationen zu den Token-Formaten finden Sie unter Tokens.

Aufbewahrung von Tokens und Protokolleinträgen​

Zwei Einstellungen auf der Registerkarte Advanced steuern, wie lange Casdoor die Daten der Organisation speichert. Ein Bereinigungsauftrag wendet sie beim Start und anschließend täglich um 00:00 Uhr Serverzeit an.

SettingDescription
Token retention days (tokenRetentionDays)Casdoor deletes an expired token of the organization once it has been expired for longer than this number of days. 0 or empty means 30 days
Record retention days (recordRetentionDays)Casdoor löscht die Protokolleinträge (Audit-Log-Einträge) der Organisation, die älter sind als diese Anzahl von Tagen. 0 oder leer behält die Protokolleinträge dauerhaft bei, was der Standardwert ist

Die Record retention days der built-in-Organisation gelten auch für alte Protokolleinträge, die keiner Organisation zugeordnet sind oder den Besitzer anonymous haben.

Vertrauenswürdige Datenbank-Hosts​

Datenbanksynchronisierer und Casbin-Adapter einer anderen Organisation als built-in dürfen möglicherweise nur Verbindungen zu Datenbanken im Internet herstellen, und ein Synchronisierer darf sich nicht mit dem Datenbankserver von Casdoor selbst verbinden. Trusted database hosts (trustedDbHosts) auf der Registerkarte Advanced hebt diese Beschränkungen für die dort aufgeführten Hosts auf.

Geben Sie eine durch Kommas getrennte Liste von host- oder host:port-Einträgen ein, zum Beispiel 10.0.0.5,db.internal:3306. Ein Eintrag ohne Port entspricht jedem Port. Casdoor vergleicht Hostnamen unabhängig von Groß-/Kleinschreibung und ignoriert Klammern um IPv6-Adressen.

Nur ein globaler Administrator kann Trusted database hosts ändern. Änderungen durch andere Personen werden von Casdoor ignoriert. Ein Synchronisierer kann niemals die Datenbank von Casdoor selbst verwenden, auch nicht auf einem vertrauenswürdigen Host.

LDAP-Passwörter und RADIUS​

Zwei Schalter auf der Registerkarte Advanced aktivieren Funktionen der integrierten Server für die Benutzer der Organisation. Nur ein globaler Administrator kann sie ändern, und beide sind standardmäßig deaktiviert.

SettingDescription
Enable LDAP password (enableLdapPassword)Der integrierte LDAP-Server gibt die Passwortattribute userPassword und sambaNTPassword der Benutzer zurück, beispielsweise für Samba. Wenn er deaktiviert ist, gibt der Server diese niemals zurück, selbst wenn LDAP attributes sie auflistet. Das Aktivieren erfordert eine Bestätigung: Der Server legt dann die Passwort-Hashes offen, oder die Klartext-Passwörter, wenn die Organisation diese im Klartext speichert, und ein NT-Hash reicht für die Anmeldung aus (Pass-the-Hash)
Enable RADIUS (enableRadius)The built-in RADIUS server accepts authentication and accounting requests for the users of the organization. When it is off, the server rejects Access-Request packets and doesn't answer Accounting-Request packets. After an upgrade, turn it on for organizations that already use RADIUS

Navigation der Admin-Konsole​

Zwei Einstellungen steuern, welche Seiten Mitglieder der Organisation in der Navigation der Casdoor-Admin-Konsole sehen:

SettingApplies toDefault
Admin navbar items (navItems)AdministratorsAll pages
User navbar items (userNavItems)Regular usersNo pages. Regular users see only their own account pages

Wählen Sie die Seiten in jeder Baumstruktur aus, zum Beispiel Applications, Providers, Resources, Keys, Products, Orders und Webhooks.

Wenn ein regulärer Benutzer die Casdoor-Startseite (/) öffnet, leitet Casdoor den Benutzer zur ersten der folgenden Seiten weiter, die der Benutzer sehen darf:

  1. Apps (/apps)
  2. Shortcuts (/shortcuts)
  3. Die Kontoseite (/account)

Issuer-Name in Authenticator-Apps​

Casdoor verwendet den Anzeigenamen der Organisation oder, falls kein Anzeigename vorhanden ist, deren Namen als Issuer für zeitbasierte einmalige Passwörter (TOTP). Benutzer, die mehrere Einträge in einer Authenticator-App haben, erkennen das Konto daran.
