Den Casdoor Server installieren

Dieser Leitfaden erklärt, wie Sie den Casdoor Server auf Ihrem eigenen Rechner installieren, ihn mit einer Datenbank verbinden und sich zum ersten Mal anmelden.

Lernziele​

  • Erhalten Sie Casdoor aus einer vorab erstellten Binary oder bauen Sie es aus dem Quellcode.
  • Verbinden Sie Casdoor mit einer Datenbank.
  • Führen Sie Casdoor im Entwicklungsmodus und im Produktionsmodus aus.
  • Melden Sie sich bei der Casdoor Admin Console an.

Voraussetzungen​

  • Ein Rechner, auf dem Windows, Linux oder macOS läuft
  • Eine unterstützte Datenbank, die Casdoor erreichen kann
  • Zum Bauen aus dem Quellcode: Go 1.21+, Node.js LTS (20) und Yarn 1.x
Möchten Sie es nicht selbst betreiben?

Casdoor Cloud bietet Ihnen eine dedizierte Casdoor-Instanz, die wir hosten und für Sie aktuell halten, ab $29/Monat ohne Gebühren pro Benutzer. Neue Konten erhalten $20 Guthaben zur Testnutzung.

Über den Casdoor Server​

Casdoor ist ein einzelnes Repository, casdoor/casdoor, mit zwei Teilen:

PartBeschreibungStack
FrontendAdmin Console und Login-SeitenTypeScript, React, Vite
BackendREST API and protocol endpointsGo, Beego, XORM

In der Produktion stellt das Backend das gebaute Frontend bereit, sodass Sie einen einzelnen Prozess auf einem einzelnen Port ausführen.

Unterstützte Datenbanken​

Casdoor verwendet XORM für die Kommunikation mit der Datenbank und unterstützt die Datenbanken, für die ein XORM-Treiber vorhanden ist:

  • MySQL
  • MariaDB
  • PostgreSQL
  • CockroachDB
  • SQL Server
  • Oracle
  • SQLite 3
  • TiDB

Casdoor beziehen​

Wählen Sie eine der beiden Optionen.

Vorgebaute Binärdatei herunterladen​

  1. Laden Sie das Archiv für Ihre Plattform von GitHub Releases herunter. Binärdateien sind für Linux, macOS und Windows verfügbar, jeweils für x86_64 und arm64.

  2. Entpacken Sie das Archiv. Es enthält die casdoor-Binärdatei, das kompilierte Frontend und eine Beispiel-conf/app.conf.

    # Linux and macOS
    tar -xzf casdoor_Linux_x86_64.tar.gz
    cd casdoor_Linux_x86_64

  3. Konfigurieren Sie die Datenbank.

  4. Führen Sie die Binärdatei aus:

    ./casdoor

  5. Melden Sie sich bei der Admin-Konsole unter http://localhost:8000 an.

A binary from GitHub Releases can later upgrade itself from the System Info page. See Upgrade Casdoor.

Aus dem Quellcode erstellen​

  1. Klonen Sie das Repository. Casdoor verwendet Go-Module, daher können Sie es überall klonen.

    cd path/to/folder
    git clone https://github.com/casdoor/casdoor

  2. Konfigurieren Sie die Datenbank.

  3. Führen Sie Casdoor im Entwicklungsmodus oder Produktionsmodus aus.

Vorsicht

Verwenden Sie Yarn 1.x, um das Frontend zu erstellen. npm kann zu Stilproblemen in der Benutzeroberfläche führen. Siehe casdoor#294.

Wenn Go keine Abhängigkeiten herunterladen kann, setzen Sie die Umgebungsvariable GOPROXY, beispielsweise auf https://goproxy.cn/.

Datenbank konfigurieren​

Casdoor liest seine Einstellungen aus conf/app.conf. Die Standardeinstellungen verwenden MySQL. Für ein minimales Setup legen Sie driverName, dataSourceName und dbName fest. Weitere Optionen finden Sie unter Konfiguration.

MySQL​

  1. Erstellen Sie eine Datenbank namens casdoor.

  2. Legen Sie die Verbindung in conf/app.conf fest:

    driverName = mysql
    dataSourceName = root:123456@tcp(localhost:3306)/
    dbName = casdoor

PostgreSQL​

  1. Erstellen Sie eine Datenbank, beispielsweise casdoor. XORM benötigt, dass die Datenbank existiert, bevor Casdoor startet.

  2. Legen Sie die Verbindung in conf/app.conf fest:

    driverName = postgres
    dataSourceName = user=postgres password=postgres host=localhost port=5432 sslmode=disable dbname=casdoor
    dbName = casdoor
Info

Bei PostgreSQL erscheint der Datenbankname zweimal: in dbName und als dbname innerhalb von dataSourceName. Beide müssen gesetzt sein. Siehe casdoor#2127.

CockroachDB​

CockroachDB verwendet den PostgreSQL-Treiber und dieselben Einstellungen wie PostgreSQL, mit einem zusätzlichen Parameter:

driverName = postgres
dataSourceName = user=postgres password=postgres host=localhost port=5432 sslmode=disable dbname=casdoor serial_normalization=virtual_sequence
dbName = casdoor
Vorsicht

Fügen Sie serial_normalization=virtual_sequence vor der Erstellung der Datenbank zu dataSourceName hinzu. Ohne diesen Parameter meldet Casdoor jedes Mal beim Start einen Fehler bezüglich einer vorhandenen Datenbank.

SQLite 3​

Legen Sie die Verbindung in conf/app.conf fest:

driverName = sqlite
dataSourceName = file:casdoor.db?cache=shared
dbName = casdoor

Casdoor aus dem Quellcode ausführen​

Im Entwicklungsmodus ausführen​

Im Entwicklungsmodus laufen das Backend und das Frontend als zwei Prozesse. Das Frontend wird neu geladen, wenn Sie seinen Code ändern.

  1. Starten Sie im Stammverzeichnis des Repositoriums das Backend. Es lauscht auf Port 8000.

    go run main.go

  2. Starten Sie in einem zweiten Terminal das Frontend. Es ist ein Vite-Projekt und lauscht auf Port 7001.

    cd web
    yarn install
    yarn start

  3. Melden Sie sich bei der Admin-Konsole an unter http://localhost:7001.

Im Produktionsmodus ausführen​

Im Produktionsmodus bauen Sie das Frontend in statische Dateien, und das Backend stellt diese auf Port 8000 bereit.

  1. Frontend bauen:

    cd web
    yarn install
    yarn build

  2. Bauen und starten Sie im Stammverzeichnis des Repositorys das Backend.

    Unter Linux und macOS:

    go build
    ./casdoor

    Unter Windows:

    go build
    casdoor.exe

  3. Melden Sie sich bei der Admin-Konsole an unter http://localhost:8000.

Um auf einem anderen Port zu lauschen, setzen Sie httpport in conf/app.conf und starten Sie das Backend neu.

Um die Konfiguration von einem anderen Speicherort zu laden, übergeben Sie den Flag --config. Das Flag akzeptiert einen absoluten oder relativen Pfad und ersetzt die standardmäßige Suche nach conf/app.conf.

./casdoor --config /etc/casdoor/app.conf

Bei der Admin-Konsole anmelden​

  1. Öffnen Sie die Casdoor-URL in einem Browser: http://localhost:7001 im Entwicklungsmodus oder http://localhost:8000 im Produktionsmodus sowie für die vorgefertigte Binärdatei.
  2. Bei einer neuen Datenbank öffnet Casdoor die Seite Welcome to Casdoor unter /init-admin. Geben Sie ein Passwort für den Administrator admin in New Password und Re-enter New ein und klicken Sie anschließend auf Set Password. Das Passwort muss den Optionen zur Komplexität der Organisation built-in entsprechen. Casdoor zeigt dann die Anmelde-Seite an.
  3. Melden Sie sich mit der Organisation built-in, dem Benutzernamen admin und dem von Ihnen festgelegten Passwort an.

Wenn Casdoor die Datenbank erstellt, zeigt das Serverprotokoll The password of built-in/admin is not set, open Casdoor in the browser to set it, or set initAdminPassword before the first start. Um die Willkommensseite zu überspringen, setzen Sie initAdminPassword vor dem ersten Start.

Gefahr

Legen Sie das Passwort für built-in/admin direkt nach dem ersten Start fest. Solange es nicht festgelegt ist, kann jeder, der die Casdoor-URL zuerst öffnet, dieses wählen.

Wählen Sie die URL, die Ihre Anwendungen verwenden​

Anwendungen, die Benutzer mit Casdoor anmelden, benötigen die URL der Casdoor-Anmeldeseite:

ModeCasdoor URL for your applications
Developmenthttp://localhost:7001
Productionhttps://<your-casdoor-domain>, or the URL of your reverse proxy

Zum Beispiel meldet Casnode Benutzer mit Casdoor an. Dessen serverUrl ist im Entwicklungsmodus http://localhost:7001 und im Produktionsmodus https://door.casdoor.com.

Nächste Schritte​

  • Konfiguration: Überprüfen Sie alle Backend- und Frontend-Optionen.
  • Eine Anwendung mit Casdoor verbinden: Melden Sie Benutzer in Ihrer eigenen Anwendung an.
  • Hinter Nginx bereitstellen: Stellen Sie Casdoor hinter einem Reverse-Proxy mit HTTPS bereit.
