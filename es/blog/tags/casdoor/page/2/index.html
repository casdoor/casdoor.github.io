Autenticación multifactor RADIUS para VPN y Wi-Fi: 2FA TOTP con el servidor RADIUS de Casdoor

2 de noviembre de 2026 · 11 min de lectura
Yang Luo
Casdoor Maintainer

Para poner autenticación multifactor delante de una VPN con RADIUS, la pasarela VPN envía el nombre de usuario y la contraseña al servidor RADIUS con PAP, el servidor verifica la contraseña y responde con un Access-Challenge, el cliente muestra un aviso y el usuario escribe el código 2FA de una aplicación de autenticador en una segunda solicitud. Casdoor incluye un servidor RADIUS que hace exactamente esto para usuarios que tienen configurado TOTP, por lo que una pasarela que pueda mostrar un aviso de Access-Challenge (FortiGate SSL VPN es una cuyo fabricante lo documenta) obtiene una contraseña más un código 2FA sin software adicional. Wi-Fi con WPA2/WPA3-Enterprise es diferente: 802.1X se ejecuta sobre EAP, que no tiene lugar para un código escrito, por lo que Casdoor tiene un interruptor para omitir el código para esos clientes.

SSO de Spring Boot con OpenID Connect: Spring Security, Resource Server y Spring Cloud Gateway con Casdoor

2 de noviembre de 2026 · 14 min de lectura
Yang Luo
Casdoor Maintainer

Para agregar inicio de sesión único a Spring Boot, registre cada aplicación como una aplicación en un proveedor de OpenID Connect como Casdoor, apunte Spring Security a la URL del emisor del proveedor y elija el módulo de Spring que coincida con la aplicación: oauth2Login() para una aplicación web renderizada en el servidor, oauth2ResourceServer().jwt() para una API REST que recibe tokens bearer, y Spring Cloud Gateway con el filtro TokenRelay cuando una puerta de enlace inicia sesión a los usuarios para un conjunto de microservicios. Los usuarios obtienen SSO porque todas las aplicaciones los envían al mismo Casdoor, que recuerda la sesión: la segunda aplicación redirige, Casdoor ya conoce al usuario y este vuelve directamente sin un formulario de inicio de sesión. Esta publicación configura las tres formas contra un solo Casdoor, cada una con un application.yml funcional y un SecurityFilterChain personalizado.

OAuth de Steam y OAuth de Telegram con Casdoor: Añadir inicios de sesión sociales no estándar a través de OIDC

2 de noviembre de 2026 · 11 min de lectura
Yang Luo
Casdoor Maintainer

No existe "OAuth de Steam": Steam inicia sesión a los usuarios con OpenID 2.0 y le proporciona un SteamID de 64 bits, nada más. El clásico Login Widget de Telegram tampoco es OAuth: entrega a su página un conjunto de campos de usuario más un hash HMAC-SHA256 que usted verifica con su token de bot. Telegram ahora también ejecuta un proveedor real de OpenID Connect en oauth.telegram.org. Si coloca Casdoor entre su aplicación y estos proveedores, Casdoor realiza las verificaciones específicas del protocolo y su aplicación solo habla OpenID Connect con Casdoor, de la misma manera que lo haría con Google o GitHub.

Pasarela de Pago Simulada para Pruebas: Proveedor Dummy de Casdoor, Modo de Prueba de Stripe y Sandbox de PayPal

2 de noviembre de 2026 · 11 min de lectura
Yang Luo
Casdoor Maintainer

Una pasarela de pago simulada es un proveedor de pagos que acepta cada proceso de compra como pagado sin contactar con un banco o una red de tarjetas, para que pueda probar pedidos, suscripciones y cumplimiento sin dinero y sin una cuenta de pasarela. Casdoor incluye una: el Proveedor de pago Dummy. Añádalo a un producto, compre el producto, y Casdoor registra el pago y el pedido como Paid, inicia la suscripción y escribe la transacción, todo sin salir de su servidor. Use Dummy en desarrollo, y cambie a un sandbox de proveedor (modo de prueba de Stripe, sandbox de PayPal, sandbox de Paddle) en staging, donde también necesita tarjetas rechazadas, 3-D Secure y redirecciones reales.

Casdoor v4: una nueva consola, un Marketplace y OAuth para servidores MCP

30 de octubre de 2026 · 6 min de lectura
Yang Luo
Casdoor Maintainer

Casdoor v4.0 se lanzó el 1 de septiembre. Dos meses y 25 versiones después estamos en la v4.25, por lo que es un buen momento para revisar los cambios. En resumen: la consola de administración fue reconstruida, el auto-hospedaje se volvió mucho menos tedioso, ahora existe un Marketplace para integraciones y temas de inicio de sesión, y Casdoor puede actuar como servidor de autorización para servidores MCP y agentes de IA.

Si no lo has usado antes: Casdoor es una plataforma open-source de gestión de identidad y acceso (IAM) escrita en Go. Es un proveedor de identidad completo, no una biblioteca ni un proxy de inicio de sesión. Los usuarios residen en Casdoor, Casdoor emite los tokens y tus aplicaciones se comunican con él mediante OAuth 2.0, OpenID Connect, SAML 2.0, CAS, LDAP o SCIM. La autorización es gestionada por Apache Casbin, por lo que los modelos ACL, RBAC y ABAC funcionan perfectamente. Está bajo licencia Apache-2.0 y aparece listado en el CNCF Landscape.
