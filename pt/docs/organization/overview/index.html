Organizações

Uma organização é a unidade na qual o Casdoor gerencia usuários e aplicações. Um usuário que fez login em uma organização pode abrir todas as aplicações dessa organização sem fazer login novamente.

A organização que você seleciona para uma application ou um provider determina quais usuários podem fazer login na aplicação e onde o provedor está disponível.

Você edita uma organização no console de administração do Casdoor em User Management > Organizations. A página de edição tem as abas Basic, Password type, Account items e Advanced. Esta página descreve as configurações gerais. Outras páginas desta seção cobrem a account page, a password complexity, o password obfuscator, o theme, os MFA items, os groups e os records do log de auditoria. Você também configura o LDAP por organização. Veja LDAP.

Página de login de uma organização​

Os usuários geralmente fazem login através de uma aplicação. Eles também podem fazer login na página de login de sua organização, em /login/<organization-name>. No site de demonstração, por exemplo: https://door.casdoor.com/login/casbin.

Quando um usuário faz login através desta URL, o Casdoor lembra a organização. Quando a sessão expira, o Casdoor envia o usuário de volta à página de login da mesma organização.

Nomes de organizações​

O nome de uma organização não pode ser admin ou app, porque o Casdoor usa esses nomes internamente. Criar ou renomear uma organização para um desses nomes falha com the organization name: <name> is reserved.

Logo no tema escuro​

Na aba Basic, ative Enable dark logo para definir Logo dark, um logo para o tema escuro. A página mostra uma pré-visualização sobre um fundo preto. O Casdoor mostra este logo na barra lateral do console de administração do Casdoor quando o console usa o tema escuro. Se Logo dark estiver vazio, o Casdoor mostra Logo. Desativar Enable dark logo limpa Logo dark.

As páginas de login e cadastro não usam o logo da organização. Elas mostram os logos da aplicação, veja Application terminology.

Armazenamento de senha​

Password type define o algoritmo com o qual o Casdoor armazena as senhas dos usuários da organização. Novas organizações usam bcrypt.

saltSHA-256SHA-256 is a cryptographic hash function that produces a 256-bit value.—
md5-saltMD5MD5 is a widely used but cryptographically weak hash (128-bit).Discuz!

pbkdf2-saltSHA-256 and PBKDF2PBKDF2 is a key derivation function resistant to dictionary and rainbow-table attacks. Use when importing users via the Keycloak syncer.Keycloak
sha512-saltSHA-512SHA-512 of the password and the salt, stored as a hexadecimal string.—

Salt de senha​

Os algoritmos salt, sha512-salt, md5-salt, pbkdf2-salt e pbkdf2-django usam um salt. Password salt controla a origem do salt:

Password saltSaltUse it when
SetAll users of the organization share this saltYou need hashes that are compatible with another system
EmptyCasdoor generates a random salt for each user and stores it with the password hashYou set up a new organization. This is the recommended setting, because it limits the use of precomputed hash tables

Avatares permanentes​

Quando um usuário faz login por meio de um provedor OAuth, como GitHub ou Google, o Casdoor armazena a URL do avatar no provedor. Se o provedor alterar ou remover essa URL posteriormente, o avatar ficará quebrado.

Ative Use permanent avatar para fazer com que o Casdoor baixe o avatar e o envie para seu próprio provedor de armazenamento. A URL permanece estável. O Casdoor envia um avatar somente quando ele é novo ou foi alterado.

E-mail como nome de usuário​

Ative Use Email as username para registrar usuários sem um nome de usuário separado. Então:

  • Na inscrição, se o campo de nome de usuário estiver oculto, o endereço de e-mail se torna o nome de usuário.
  • Quando um usuário altera o endereço de e-mail, o nome de usuário muda junto com ele.

Exclusão suave​

Por padrão, excluir um usuário remove o usuário do banco de dados.

Com Soft deletion ativada, excluir um usuário apenas marca o usuário como excluído:

  • O usuário permanece na lista de usuários, com Is deleted selecionado e um Deleted time.
  • O usuário não pode mais fazer login, e o Casdoor revoga imediatamente os tokens e sessões do usuário.
  • Para restaurar o usuário, desmarque Is deleted na página de edição do usuário.
  • Para remover o usuário definitivamente, exclua o usuário uma segunda vez.

Quando o Casdoor revoga os tokens de um usuário​

O Casdoor expira todos os tokens de um usuário em todas as aplicações quando:

  • O usuário é excluído ou excluído logicamente (soft-deleted).
  • Um administrador ativa Is forbidden para o usuário. O Casdoor também encerra as sessões do usuário, veja Proibir ou excluir um usuário.
  • A senha do usuário é alterada via POST /api/set-password. Isso cobre a página da conta, a página de edição do usuário e a página de recuperação de senha.

As aplicações do usuário então precisam fazer login novamente com esse usuário.

Login entre aplicações​

Na aba Basic, Enable exclusive signin across applications limita o número de sessões de navegador que um usuário da organização mantém em todas as aplicações. Max sessions aparece quando o interruptor está ativado e define esse número. Vazio ou 1 mantém apenas a sessão atual. O Casdoor aplica a configuração da própria organização do usuário, mesmo quando o usuário faz login através de uma aplicação compartilhada de outra organização. Veja Exclusive sign-in.

Desativar o console de administração​

Ative Disable console na aba Basic para usar o Casdoor apenas como provedor de identidade para os usuários regulares da organização. Quando um usuário regular faz login no console de administração do Casdoor, o Casdoor mostra uma página com HTTP 403, título Unauthorized, texto "The Casdoor console is disabled for the regular users of this organization" e um botão Logout.

A configuração não afeta:

  • As páginas de login e os fluxos OAuth 2.0 e OpenID Connect (OIDC) das aplicações. Os usuários fazem login nas suas aplicações como antes.
  • Administradores de organização e administradores globais. Eles podem usar o console.
  • A página de configuração MFA (/mfa/setup), para que os usuários ainda possam configurar um método MFA obrigatório.
cuidado

Somente o frontend do console impõe Disable console. A API do Casdoor permanece disponível para os usuários com suas próprias permissões.

Padrões para novas aplicações​

Duas configurações na aba Advanced preenchem as configurações de token das aplicações criadas posteriormente na organização. Aplicações existentes não são alteradas.

SettingDescription
Default token format (defaultTokenFormat)JWT, JWT-Empty, JWT-Custom, or JWT-Standard. Casdoor uses it for a new application that has no Token format. Empty means JWT
Default token fields (defaultTokenFields)Claims para uma nova aplicação que não possui Token fields. As opções são as mesmas dos Token fields de uma aplicação, e você pode digitar outros valores. Vazio significa nenhum campo

O formulário de nova aplicação do console deixa ambos os campos da aplicação vazios, portanto usa esses padrões. Aplicações criadas através do Dynamic Client Registration também os recebem. Veja Tokens para os formatos de token.

Retenção de tokens e registros​

Duas configurações na aba Advanced controlam por quanto tempo o Casdoor mantém os dados da organização. Um trabalho de limpeza as aplica na inicialização e depois diariamente às 00:00 hora do servidor.

SettingDescription
Token retention days (tokenRetentionDays)Casdoor deletes an expired token of the organization once it has been expired for longer than this number of days. 0 or empty means 30 days
Record retention days (recordRetentionDays)O Casdoor exclui os registros (entradas de log de auditoria) da organização que são mais antigos que este número de dias. 0 ou vazio mantém os registros para sempre, que é o padrão

O Record retention days da organização built-in também se aplica a registros antigos que não possuem organização ou têm o proprietário anonymous.

Hosts de banco de dados confiáveis​

Os sincronizadores de banco de dados e adaptadores Casbin de uma organização diferente de built-in podem conectar-se apenas a bancos de dados em endereços de Internet, e um sincronizador não pode conectar-se ao servidor de banco de dados do próprio Casdoor. Trusted database hosts (trustedDbHosts) na aba Advanced levanta essas limitações para os hosts listados.

Insira uma lista separada por vírgulas de entradas host ou host:port, por exemplo 10.0.0.5,db.internal:3306. Uma entrada sem porta corresponde a qualquer porta. O Casdoor compara nomes de host sem distinguir maiúsculas/minúsculas e ignora os colchetes em torno de endereços IPv6.

Somente um administrador global pode alterar Trusted database hosts. O Casdoor ignora alterações feitas por qualquer outra pessoa. Um sincronizador nunca pode usar o banco de dados do próprio Casdoor, mesmo em um host confiável.

Senhas LDAP e RADIUS​

Dois interruptores na aba Advanced habilitam recursos dos servidores integrados para os usuários da organização. Somente um administrador global pode alterá-los, e ambos estão desativados por padrão.

SettingDescription
Enable LDAP password (enableLdapPassword)O servidor LDAP integrado retorna os atributos de senha userPassword e sambaNTPassword dos usuários, por exemplo, para o Samba. Quando está desativado, o servidor nunca os retorna, mesmo que LDAP attributes os liste. Ativar isso solicita uma confirmação: o servidor então expõe os hashes de senha, ou as senhas em texto puro se a organização as armazena em texto puro, e um hash NT é suficiente para entrar (pass-the-hash)
Enable RADIUS (enableRadius)The built-in RADIUS server accepts authentication and accounting requests for the users of the organization. When it is off, the server rejects Access-Request packets and doesn't answer Accounting-Request packets. After an upgrade, turn it on for organizations that already use RADIUS

Navegação do console de administração​

Duas configurações controlam quais páginas os membros da organização veem na navegação do console de administração do Casdoor:

SettingApplies toDefault
Admin navbar items (navItems)AdministratorsAll pages
User navbar items (userNavItems)Regular usersNo pages. Regular users see only their own account pages

Selecione as páginas em cada árvore, por exemplo, Applications, Providers, Resources, Keys, Products, Orders e Webhooks.

Quando um usuário comum abre a página inicial do Casdoor (/), o Casdoor redireciona o usuário para a primeira das seguintes páginas que ele pode ver:

  1. Apps (/apps)
  2. Shortcuts (/shortcuts)
  3. A página da conta (/account)

Nome do emissor nos aplicativos autenticadores​

O Casdoor usa o nome de exibição da organização, ou seu nome se não houver nome de exibição, como emissor das senhas de uso único baseadas no tempo (TOTP). Usuários que possuem várias entradas em um aplicativo autenticador reconhecem a conta por esse nome.
