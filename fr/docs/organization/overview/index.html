Organisations

Une organisation est l'unité dans laquelle Casdoor gère les utilisateurs et les applications. Un utilisateur connecté à une organisation peut ouvrir toutes les applications de cette organisation sans se reconnecter.

L'organisation sélectionnée pour une application ou un provider détermine quels utilisateurs peuvent se connecter à l'application et où le provider est disponible.

Vous modifiez une organisation dans la console d'administration Casdoor sous User Management > Organizations. La page de modification contient les onglets Basic, Password type, Account items et Advanced. Cette page décrit les paramètres généraux. D'autres pages de cette section couvrent la page de compte, la complexité du mot de passe, l'obfuscateur de mot de passe, le thème, les éléments MFA, les groupes et les enregistrements du journal d'audit. Vous configurez également LDAP par organisation. Voir LDAP.

Page de connexion d'une organisation​

Les utilisateurs se connectent généralement via une application. Ils peuvent également se connecter sur la page de connexion de leur organisation, à /login/<organization-name>. Sur le site de démonstration, par exemple : https://door.casdoor.com/login/casbin.

Lorsqu'un utilisateur se connecte via cette URL, Casdoor mémorise l'organisation. Lorsque la session expire, Casdoor renvoie l'utilisateur vers la page de connexion de la même organisation.

Noms des organisations​

Le nom d'une organisation ne peut pas être admin ou app, car Casdoor utilise ces noms en interne. La création ou le renommage d'une organisation avec l'un de ces noms échoue avec the organization name: <name> is reserved.

Logo en thème sombre​

Sur l'onglet Basic, activez Enable dark logo pour définir Logo dark, un logo pour le thème sombre. La page affiche un aperçu sur fond noir. Casdoor affiche ce logo dans la barre latérale de la console d'administration Casdoor lorsque la console utilise le thème sombre. Si Logo dark est vide, Casdoor affiche Logo. Désactiver Enable dark logo efface Logo dark.

Les pages de connexion et d'inscription n'utilisent pas le logo de l'organisation. Elles affichent les logos de l'application, voir Terminologie de l'application.

Stockage des mots de passe​

Password type définit l'algorithme avec lequel Casdoor stocke les mots de passe des utilisateurs de l'organisation. Les nouvelles organisations utilisent bcrypt.

plain—Passwords stored in cleartext. Not recommended for production.—
saltSHA-256SHA-256 is a cryptographic hash function that produces a 256-bit value.—
md5-saltMD5MD5 is a widely used but cryptographically weak hash (128-bit).Discuz!
bcryptbcryptbcrypt hashes and salts passwords securely. Default for new organizations.Spring Boot, WordPress
pbkdf2-saltSHA-256 and PBKDF2PBKDF2 is a key derivation function resistant to dictionary and rainbow-table attacks. Use when importing users via the Keycloak syncer.Keycloak
sha512-saltSHA-512SHA-512 of the password and the salt, stored as a hexadecimal string.—

Sel de mot de passe​

Les algorithmes salt, sha512-salt, md5-salt, pbkdf2-salt et pbkdf2-django utilisent un sel. Password salt contrôle l'origine du sel :

Password saltSaltUse it when
SetAll users of the organization share this saltYou need hashes that are compatible with another system
EmptyCasdoor generates a random salt for each user and stores it with the password hashYou set up a new organization. This is the recommended setting, because it limits the use of precomputed hash tables

Avatars permanents​

Lorsqu'un utilisateur se connecte via un fournisseur OAuth, tel que GitHub ou Google, Casdoor stocke l'URL de l'avatar chez le fournisseur. Si le fournisseur change ou supprime ultérieurement cette URL, l'avatar ne s'affiche plus correctement.

Activez Use permanent avatar pour faire télécharger l'avatar par Casdoor et le téléverser vers son propre fournisseur de stockage. L'URL reste alors stable. Casdoor téléverse un avatar uniquement lorsqu'il est nouveau ou qu'il a changé.

Email comme nom d'utilisateur​

Activez Use Email as username pour inscrire des utilisateurs sans nom d'utilisateur distinct. Ensuite :

  • Lors de l'inscription, si le champ du nom d'utilisateur est masqué, l'adresse e-mail devient le nom d'utilisateur.
  • Lorsqu'un utilisateur modifie son adresse e-mail, le nom d'utilisateur change avec elle.

Suppression logique​

Par défaut, la suppression d'un utilisateur retire celui-ci de la base de données.

Avec Soft deletion activé, la suppression d'un utilisateur marque uniquement cet utilisateur comme supprimé :

  • L'utilisateur reste dans la liste des utilisateurs, avec Is deleted coché et une valeur dans Deleted time.
  • L'utilisateur ne peut plus se connecter, et Casdoor révoque immédiatement les jetons et les sessions de l'utilisateur.
  • Pour restaurer l'utilisateur, décochez Is deleted sur la page d'édition de l'utilisateur.
  • Pour supprimer définitivement l'utilisateur, supprimez-le une seconde fois.

Quand Casdoor révoque les jetons d'un utilisateur​

Casdoor fait expirer tous les jetons d'un utilisateur dans toutes les applications lorsque :

  • L'utilisateur est supprimé ou supprimé logiquement.
  • Un administrateur active Is forbidden pour l'utilisateur. Casdoor met également fin aux sessions de l'utilisateur, voir Interdire ou supprimer un utilisateur.
  • Le mot de passe de l'utilisateur est modifié via POST /api/set-password. Cela couvre la page du compte, la page d'édition de l'utilisateur et la page de récupération de mot de passe.

Les applications de l'utilisateur doivent alors reconnecter l'utilisateur.

Connexion entre applications​

Sur l'onglet Basic, Enable exclusive signin across applications limite le nombre de sessions navigateur qu'un utilisateur de l'organisation conserve sur l'ensemble des applications. Max sessions apparaît lorsque l'interrupteur est activé et définit ce nombre. Vide ou 1 ne conserve que la session actuelle. Casdoor applique le paramètre de la propre organisation de l'utilisateur, même lorsque l'utilisateur se connecte via une application partagée d'une autre organisation. Voir Connexion exclusive.

Désactiver la console d'administration​

Activez Disable console sur l'onglet Basic pour utiliser Casdoor uniquement comme fournisseur d'identité pour les utilisateurs réguliers de l'organisation. Lorsqu'un utilisateur régulier se connecte à la console d'administration de Casdoor, Casdoor affiche une page avec HTTP 403, le titre Unauthorized, le texte "The Casdoor console is disabled for the regular users of this organization", et un bouton Logout.

Ce paramètre n'affecte pas :

  • Les pages de connexion et les flux OAuth 2.0 et OpenID Connect (OIDC) des applications. Les utilisateurs se connectent à vos applications comme auparavant.
  • Les administrateurs d'organisation et les administrateurs globaux. Ils peuvent utiliser la console.
  • La page de configuration MFA (/mfa/setup), afin que les utilisateurs puissent toujours configurer une méthode MFA requise.
prudence

Seul le frontend de la console applique Disable console. L'API Casdoor reste disponible pour les utilisateurs selon leurs propres permissions.

Paramètres par défaut pour les nouvelles applications​

Deux paramètres sur l'onglet Advanced remplissent les paramètres de jeton des applications créées ultérieurement dans l'organisation. Les applications existantes ne changent pas.

SettingDescription
Default token format (defaultTokenFormat)JWT, JWT-Empty, JWT-Custom, or JWT-Standard. Casdoor uses it for a new application that has no Token format. Empty means JWT
Default token fields (defaultTokenFields)Revendications pour une nouvelle application qui n'a pas de Token fields. Les options sont les mêmes que pour les Token fields d'une application, et vous pouvez saisir d'autres valeurs. Vide signifie aucun champ

Le formulaire de nouvelle application de la console laisse les deux champs de l'application vides, il utilise donc ces valeurs par défaut. Les applications créées via Dynamic Client Registration les obtiennent également. Voir Jetons pour les formats de jeton.

Conservation des jetons et des enregistrements​

Deux paramètres sur l'onglet Advanced contrôlent la durée pendant laquelle Casdoor conserve les données de l'organisation. Un processus de nettoyage les applique au démarrage puis chaque jour à 00:00 heure serveur.

SettingDescription
Token retention days (tokenRetentionDays)Casdoor deletes an expired token of the organization once it has been expired for longer than this number of days. 0 or empty means 30 days
Record retention days (recordRetentionDays)Casdoor supprime les enregistrements (entrées de journal d'audit) de l'organisation qui sont plus anciens que ce nombre de jours. 0 ou vide conserve les enregistrements indéfiniment, ce qui est la valeur par défaut

Le paramètre Record retention days de l'organisation built-in s'applique également aux anciens enregistrements qui n'ont pas d'organisation ou dont le propriétaire est anonymous.

Hôtes de base de données fiables​

Les synchroniseurs de base de données et les adaptateurs Casbin d'une organisation autre que built-in ne peuvent se connecter qu'à des bases de données sur des adresses Internet, et un synchroniseur ne peut pas se connecter au serveur de base de données de Casdoor lui-même. Trusted database hosts (trustedDbHosts) sur l'onglet Advanced lève ces restrictions pour les hôtes listés.

Saisissez une liste séparée par des virgules d'entrées host ou host:port, par exemple 10.0.0.5,db.internal:3306. Une entrée sans port correspond à tous les ports. Casdoor compare les noms d'hôte sans tenir compte de la casse et ignore les crochets autour des adresses IPv6.

Seul un administrateur global peut modifier Trusted database hosts. Casdoor ignore les modifications effectuées par toute autre personne. Un synchroniseur ne peut jamais utiliser la base de données de Casdoor elle-même, même sur un hôte fiable.

Mots de passe LDAP et RADIUS​

Deux interrupteurs sur l'onglet Advanced activent les fonctionnalités des serveurs intégrés pour les utilisateurs de l'organisation. Seul un administrateur global peut les modifier, et les deux sont désactivés par défaut.

SettingDescription
Enable LDAP password (enableLdapPassword)Le serveur LDAP intégré renvoie les attributs de mot de passe userPassword et sambaNTPassword des utilisateurs, par exemple pour Samba. Lorsqu'il est désactivé, le serveur ne les renvoie jamais, même si LDAP attributes les liste. Son activation demande une confirmation : le serveur expose alors les hachages de mots de passe, ou les mots de passe en clair si l'organisation les stocke en clair, et un hash NT suffit pour se connecter (pass-the-hash)
Enable RADIUS (enableRadius)The built-in RADIUS server accepts authentication and accounting requests for the users of the organization. When it is off, the server rejects Access-Request packets and doesn't answer Accounting-Request packets. After an upgrade, turn it on for organizations that already use RADIUS

Navigation de la console d'administration​

Deux paramètres contrôlent quelles pages les membres de l'organisation voient dans la navigation de la console d'administration Casdoor :

SettingApplies toDefault
Admin navbar items (navItems)AdministratorsAll pages
User navbar items (userNavItems)Regular usersNo pages. Regular users see only their own account pages

Sélectionnez les pages dans chaque arborescence, par exemple Applications, Providers, Resources, Keys, Products, Orders et Webhooks.

Lorsqu'un utilisateur standard ouvre la page d'accueil de Casdoor (/), Casdoor redirige l'utilisateur vers la première des pages suivantes qu'il peut voir :

  1. Apps (/apps)
  2. Shortcuts (/shortcuts)
  3. La page du compte (/account)

Nom de l'émetteur dans les applications d'authentification​

Casdoor utilise le nom d'affichage de l'organisation, ou son nom si elle n'a pas de nom d'affichage, comme émetteur des mots de passe à usage unique basés sur le temps (TOTP). Les utilisateurs ayant plusieurs entrées dans une application d'authentification reconnaissent ainsi leur compte.
