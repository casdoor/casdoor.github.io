Casdoor v4: 新しいコンソール、マーケットプレイス、そして MCP サーバーのための OAuth

2026年10月30日 · 1分読む
Yang Luo
Casdoor Maintainer

Casdoor v4.0 は 9 月 1 日にリリースされました。その後 2 か月間で 25 リリースを重ね、現在は v4.25 となっています。このタイミングで、変更点を振り返ってみましょう。要点は次の通りです。管理コンソールの再構築、セルフホストの簡素化、統合やサインインテーマ用のマーケットプレイスの追加、そして Casdoor が MCP サーバーや AI エージェントの認可サーバーとして機能するようになった点です。

まだ使ったことがない方のために説明すると、Casdoor は Go で書かれたオープンソースの ID およびアクセス管理プラットフォームです。ライブラリやログインプロキシではなく、完全な ID プロバイダーです。ユーザーは Casdoor に存在し、Casdoor がトークンを発行します。アプリは OAuth 2.0、OpenID Connect、SAML 2.0、CAS、LDAP、SCIM を通じて Casdoor と通信します。認可は Apache Casbin によって処理されるため、ACL、RBAC、ABAC モデルすべてが動作します。ライセンスは Apache-2.0 であり、CNCF Landscape にも掲載されています。

再構築されたコンソールとサインインページ​

v4.0 では、Ant Design ベースの管理コンソールに代わって、shadcn/ui、Tailwind、Vite（現在は React 19）をベースにした新しいコンソールが導入されました。コマンドパレット、行の一括選択、インラインフォームバリデーション、2 カラム形式のフォーム、列を非表示にできるテーブルなどが利用可能です。言語切り替え時にページが再読み込みされなくなりました。

サインイン、サインアップ、パスワードリセットページも再設計されました。ダークモードが正しく動作し、スマートフォンでも使いやすいデザインになっています。

v3 からアップグレードする場合は、README にリンクされているアップグレードガイドをまずお読みください。確認すべき主な点は、CDN やリバースプロキシ経由で静的ファイルを配信している場合のフロントエンドビルドのパスです。

セルフホストがより簡単に​

v4 の多くの改善は、Casdoor を自分で運用している方々の Issue やフォーラムスレッドから生まれました:

  • デフォルトパスワードの廃止。 初回アクセス時に admin パスワードの設定を促すか、initAdminPassword で設定できるようになりました。
  • サブパスでのデプロイ。 basePath を設定することで、独自ホストではなく https://example.com/auth/ のようなサブパスで Casdoor を提供できます。
  • Forward Auth. Traefik、Caddy、Nginx 向けの Forward Auth エンドポイントを提供しており、独自ログインを持たないアプリを公開パスやサイト単位のルールとともにその背後に配置できます。
  • Docker タグ。 イメージには現在 X、X.Y、X.Y.Z のタグも付与されており、メジャーバージョンやマイナーバージョンを追従できます。
  • Helm。 チャートはメインリポジトリに移管され、各リリースごとに GHCR と Artifact Hub に公開されます。組織、アプリケーション、ユーザーを構成情報として保持することが可能です。Kubernetes での Casdoor の実行 を参照してください。
  • Windows サービス。 バイナリを Windows サービスとして実行できます。
  • アップグレード。 システム情報ページに最新リリースが表示され、公式バイナリであればワンクリックでアップグレードできます。
  • 運用性。 コンテナヘルスチェック、サインイン成功・失敗のプロメテウスカウンター、Syslog への監査ログ転送、Redis Cluster サポートなどが追加されました。

マーケットプレイス​

新しい Marketplace を使用すると、管理者は Casdoor 内から統合機能をインストールできます。これにはアプリケーションテンプレート、ID プロバイダー、サインインテーマが含まれます。インストールすると設定が自動入力され、アンインストールすると元の状態に戻ります。

現時点で 20 以上のサインインテーマがあります。インストール前に自分のサインインページでテーマをプレビューできます。組織管理者は、フォームやスクリプトをブロックする許可リストの範囲内で、独自のフォント、画像、HTML を用いてサインインページをカスタマイズすることも可能です。読み取り専用のデモである door.casdoor.com では、テーマが順次表示されるので、見てみたい方はそちらをご利用ください。

MCP サーバーと AI エージェントのための OAuth​

MCP 仕様ではリモート MCP サーバーによる OAuth の使用が求められており、MCP クライアントは通常、遭遇する認可サーバーを事前に知りません。Casdoor は現在、これに必要な要素をサポートしています:

  • PKCE を備えた OAuth 2.1 認可コードフロー、およびユーザーが要求されたスコープの一部のみを承認できる同意ページ
  • 動的クライアント登録 (RFC 7591) とクライアント管理 (RFC 7592)
  • Client ID Metadata Documents: MCP クライアントは事前登録なしで URL を client_id として使用できます
  • 動的に登録されたクライアント向けの private_key_jwt クライアント認証
  • リソースインジケーター (RFC 8707) と保護リソースメタデータ (RFC 9728)
  • トークン交換 (RFC 8693)、エンタープライズ管理認可向けの ID-JAGs を含む。これにより、組織の IdP がどのエージェントがどの MCP サーバーに到達できるかを決定できます

MCP サーバーの保護リソースメタデータを Casdoor に向けるだけで、サインイン、同意、トークン発行、検証が自動的に処理されます。Casdoor は独自の MCP サーバーも実行しているため、Claude Code や Cursor などのアシスタントを通じてユーザー、アプリケーション、権限を管理することができます。

その他のプロトコル対応​

  • SAML Single Logout と IdP 主導の SSO
  • OIDC の prompt=none、ハイブリッドフロー、prompt、max_age の適合性向上、RFC 9207 の iss パラメーター
  • トークン失効 (RFC 7009)、DPoP、デバイス認可フロー
  • マジックリンクサインイン、パスワード履歴チェック、兄弟サブドメイン間でのパスキー共有
  • ユーザーごとの最大セッション数を制限した排他的サインイン

試してみる​

手っ取り早く試してみる方法:

docker run -p 8000:8000 casbin/casdoor-all-in-one

http://localhost:8000 を開いてください。イメージには SQLite とサンプルデータが含まれているため、試用途向けであり、本番環境では使用しないでください。実際のデプロイについては インストールガイド を参照してください。

オンラインデモは 2 つあります。demo.casdoor.com は書き込み可能で 5 分ごとにリセットされ、door.casdoor.com は読み取り専用です。

自分で運用したくない場合は、Casdoor Cloud をご利用ください。ユーザー課金なしの定額料金で、専有かつマネージドなインスタンスを提供します。新規アカウントには試用用の $10 クレジットが付与されます。
