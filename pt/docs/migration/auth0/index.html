Migrar do Auth0

Mova os usuários, aplicações, organizações e roles de um tenant do Auth0 para uma organização no Casdoor com a ação Auth0 Migration do Marketplace.

Resultados da aprendizagem​

  • Conceda ao Casdoor acesso de leitura ao tenant do Auth0.
  • Pré-visualize e aplique a migração.
  • Altere as aplicações do Auth0 para o Casdoor.

O que você precisa​

  • Uma conta de administrador da organização no Casdoor para onde o tenant será movido. Não pode ser built-in.
  • Uma conta do Auth0 que possa criar aplicações no tenant.
  • Opcionalmente, a exportação de hash de senha do tenant fornecida pelo suporte do Auth0. O Auth0 fornece isso apenas em planos pagos, através de um ticket de suporte, e pode levar vários dias.

Sobre a migração do Auth0​

A ação lê o tenant por meio da Auth0 Management API e envia solicitações apenas para o domínio do tenant.

Auth0Casdoor
UserUm usuário. O ID de usuário do Casdoor é o user_id do Auth0, como auth0|64b1f…, então a claim sub permanece a mesma. O nome de usuário é o user_id sem a conexão: 64b1f… para um usuário de banco de dados, google-oauth2-1234… para um social. O username do Auth0 vai para a propriedade auth0_username.
Password hashO hash bcrypt da exportação de hash de senha, correspondido ao usuário pelo user_id ou por email.
Social identityO campo do tipo de provedor Casdoor correspondente, como google ou github. Identidades de outras conexões vão para a propriedade oauth_<connection>_id.
ApplicationUma aplicação com o mesmo Client ID, Client Secret, callback URLs e grant types, e o formato de token JWT-Standard. Aplicações globais e a aplicação usada pela migração para ler o Auth0 são ignoradas.
OrganizationUm grupo, com os membros da organização.
RoleUma role, com os usuários que a possuem.

Os usuários fazem login com seu email e senha como antes, porque o Casdoor aceita o email no campo de nome de usuário.

Criar uma aplicação machine-to-machine no Auth0​

  1. No dashboard do Auth0, vá para Applications > Applications e clique em Create Application.

  2. Escolha Machine to Machine Applications e autorize-a para a Auth0 Management API.

  3. Selecione estes escopos e clique em Authorize:

    read:users read:clients read:client_keys read:roles read:organizations read:organization_members

    Um escopo ausente não impede a migração: os tipos que não podem ser lidos são ignorados com um aviso no relatório.

  4. Na aba Settings da aplicação, copie o Domain, Client ID e Client Secret.

Instalar a ação​

  1. No console de administração do Casdoor, vá para Identity > Marketplace.
  2. Pesquise por Auth0 Migration e clique em Install.
  3. Escolha a organização para onde o tenant será movido e clique em Install.

Criar a migração​

  1. Vá para Admin > Migrations e clique em Add.

  2. Defina estes campos:

    CampoValor
    OrganizationA organização na qual você instalou a ação.
    NameUm nome, como auth0.
    ActionAuth0 Migration.
    HostO domínio do tenant, como your-tenant.us.auth0.com. Use o domínio próprio do tenant, não um domínio personalizado.
    Client IDO Client ID da aplicação machine-to-machine.
    Client secretO Client Secret da aplicação machine-to-machine.

  3. Se você tiver a exportação de hash de senha, escolha-a em Files. Escolha-a novamente antes de cada Preview e Apply, porque o Casdoor não a salva.

  4. Clique em Test connection.

    Um erro no Report nomeia a solicitação que falhou, como HTTP 401 para um client secret incorreto.

Pré-visualizar e aplicar​

  1. Clique em Preview e aguarde até que o Report mostre Previewed.
  2. Verifique os números e os Warnings. Avisos comuns:
    • Usuários de conexões de banco de dados que não possuem hash de senha. Sem a exportação, eles redefinem sua senha no Casdoor.
    • As conexões sociais com as quais os usuários fizeram login. Adicione os mesmos provedores às aplicações do Casdoor, para que esses usuários possam fazer login com eles.
    • Usuários inscritos na autenticação multifator (MFA) da Auth0. A Auth0 não exporta os fatores, então esses usuários se inscrevem novamente.
  3. Clique em Apply e confirme.

A Management API retorna no máximo 1.000 usuários por busca, então a ação busca pelo horário de criação e continua a partir do último usuário de cada busca. Um tenant com dezenas de milhares de usuários leva vários minutos, e mais tempo quando a Auth0 limita a taxa de solicitações.

Use um agente de IA em vez disso​

Com o Auth0 Migration instalado, um agente de IA conectado ao servidor MCP do Casdoor pode criar, pré-visualizar e aplicar a migração para você. Forneça o domínio, ID de cliente e segredo de cliente da aplicação máquina-a-máquina. Ele chama plan_migration, mostra o relatório e chama apply_migration após sua confirmação. Veja Ferramentas de migração. O hash de senha exportado não pode ser passado através do agente, e aplicar novamente depois não adiciona hashes a usuários que já existem. Para usar a exportação, deixe o agente apenas pré-visualizar a migração, então escolha o arquivo na página de migração do console de administração e clique em Apply lá.

Alterar as aplicações​

  1. Em cada aplicação, substitua o domínio da Auth0 pelo seu endereço do Casdoor como emissor OpenID Connect (OIDC), ou defina a URL de descoberta para https://<your-casdoor-host>/.well-known/openid-configuration. Mantenha o ID do cliente e o segredo do cliente. Veja Standard OIDC client.
  2. Nas APIs que verificam tokens de acesso, substitua o emissor e a URL do JSON Web Key Set (JWKS) da Auth0 pelos do Casdoor.
  3. Se Actions ou Rules da Auth0 adicionaram claims aos tokens, adicione-os no Casdoor com um flow que executa antes de um token ser emitido, ou com os token attributes da aplicação.

Logo antes da troca, clique em Apply novamente para trazer os usuários que se cadastraram na Auth0 desde a última execução.

Verificar o resultado​

  1. Faça login em uma das aplicações com o e-mail de um usuário migrado e a senha da Auth0.
  2. No token de ID, verifique se sub é o user_id da Auth0 do usuário.
  3. Vá para User Management > Users, abra o usuário e verifique os grupos e papéis do usuário.

Solução de problemas​

  • Um usuário não consegue fazer login com a senha: O usuário não tinha hash na exportação, ou a exportação tem outro e-mail para o usuário. Verifique os avisos e peça ao usuário para redefinir a senha.
  • HTTP 429 no relatório: A Auth0 limitou a taxa de solicitações por mais tempo do que a ação espera. Clique em Apply novamente: ele apenas adiciona o que ainda está faltando.

O que não é importado​

  • As chaves de assinatura. A Auth0 não as exporta, então os tokens emitidos pela Auth0 não são válidos no Casdoor, e os usuários fazem login novamente após a troca.
  • Fatores MFA, Actions, Rules, Hooks e as permissões das APIs da Auth0.
  • Conexões. Adicione os provedores de identidade ao Casdoor manualmente, como providers.
