ファイルによるデータの初期化と管理

このガイドでは、JSON または YAML ファイルから Casdoor にデータを読み込む方法、Casdoor がそのファイルとオブジェクトを同期し続けるようにする方法、および実行中のインスタンスのデータをエクスポートする方法について説明します。

学習目標​

  • Casdoor の起動時に組織、アプリケーション、ユーザーおよびその他のオブジェクトを読み込みます。
  • Casdoor のオブジェクトを Git 内のファイルで管理し、再起動なしで変更を適用します。
  • インスタンスのデータをエクスポートし、別のインスタンスに読み込みます。

必要なもの​

  • Casdoor インスタンスと、その conf/app.conf または環境変数へのアクセス
  • Kubernetes セクションの場合：クラスターへの kubectl アクセス、または Helm chart

初期化データファイルについて​

Casdoor を大規模な製品の一部として出荷する場合、組織、アプリケーション、ユーザーおよびその他のオブジェクトをプリロードすることで、手動セットアップなしで製品が動作するようにできます。Casdoor はこれらのオブジェクトを 1 つのファイル、すなわち初期化データファイルから読み込みます。

このファイルには 2 つの目的があります：

  • 初期化: Casdoor は起動時に一度だけこのファイルを読み込みます。
  • コードとしての設定: Casdoor はこのファイルを監視し、実行中にすべての変更を適用します。コードとしての設定管理を参照してください。

テンプレートは init_data.json.template で入手可能です。.yaml または .yml で終わるファイルは、同じ構造で YAML として読み込まれます。

起動時のデータ読み込み​

  1. init_data.json.template を Casdoor が実行されるディレクトリの init_data.json にコピーし、編集します。

    ファイルを別の場所に保存するには、conf/app.conf で initDataFile を設定します：

    initDataFile = /path/to/your/init_data.json

  2. 既存のオブジェクトに対する処理を選択します。conf/app.conf で以下のオプションのうち、最大で 1 つを設定してください:

    OptionObjects that already exist
    Neither option (default)Deleted and created again from the file at every start. Changes made in the admin console are lost on restart
    initDataNewOnly = trueLeft as they are. Casdoor only adds objects that don't exist yet
    initDataMerge = trueUpdated with only the fields that the file contains. See Manage configuration as code

  3. Casdoor を起動します。

Docker でファイルを読み込む​

ファイルをコンテナにマウントします:

docker run ... -v /path/to/init_data.json:/init_data.json

Kubernetes でファイルを読み込む​

Helm チャートを使用する場合、values ファイル内の initData.data にオブジェクトを配置し、initData.enabled: true を設定します。Manage configuration as code を参照してください。

チャートを使用しない場合:

  1. パスワードやクライアントシークレットが含まれることが多いため、ファイルを Secret に保存します。ConfigMap でも動作します。

    apiVersion: v1
    kind: Secret
    metadata:
      name: casdoor-init-data
    stringData:
      init_data.yaml: |
        organizations:
          - owner: admin
            name: acme
            displayName: Acme

  2. Secret をディレクトリとしてマウントし、その中のファイルを指すように initDataFile を設定します:

    apiVersion: apps/v1
    kind: Deployment
    ...
    spec:
      template:
        ...
        spec:
          containers:
          ...
            env:
            - name: initDataFile
              value: /init-data/init_data.yaml
            - name: initDataMerge
              value: "true"
            - name: initDataWatchInterval
              value: "30"
            volumeMounts:
            - mountPath: /init-data
              name: casdoor-init-data-volume
              readOnly: true
          volumes:
          - secret:
              secretName: casdoor-init-data
            name: casdoor-init-data-volume
注意

subPath を使用してファイルをマウントしないでください。Secret や ConfigMap が変更されても Kubernetes は subPath マウントを更新しないため、Casdoor は新しいコンテンツを認識できません。

Manage configuration as code​

組織、アプリケーション、ユーザー、プロバイダー、ロール、権限を Git で管理し、他の設定と同様に変更を展開するには、Casdoor にファイルを継続的に適用させます。

  1. conf/app.conf で以下のオプションを設定するか、同じ名前の環境変数として渡します:

    initDataFile = ./init_data.yaml
    initDataMerge = true
    initDataWatchInterval = 30

  2. ファイルにオブジェクトを記述します。例: init_data.yaml:

    organizations:
      - owner: admin
        name: acme
        displayName: Acme
        passwordType: bcrypt
    applications:
      - owner: admin
        name: app-acme
        organization: acme
        displayName: Acme Portal
        redirectUris:
          - https://portal.acme.example.com/callback
    users:
      - owner: acme
        name: alice
        displayName: Alice
        password: change-me
        signupApplication: app-acme
    roles:
      - owner: acme
        name: admins
        displayName: Admins
        users: [acme/alice]
        isEnabled: true

  3. Casdoor を起動します。以降、ファイルの内容が変更されると、Casdoor は常にファイルを再適用します。

Helm チャートを使用する場合は、同じオブジェクトを initData.data に配置します。チャートはこれらを Secret に保存し、デフォルトでマージとウォッチ機能を有効にします:

initData:
  enabled: true
  data:
    organizations:
      - owner: admin
        name: acme
        displayName: Acme

実行中の Pod は、initData.watchInterval 秒以内（および kubelet がマウントされた Secret を更新するために必要な約 1 分間）で、initData.data を変更する helm upgrade を適用します。

Casdoor によるファイルの適用方法​

BehaviorDescription
MergeCasdoor updates an existing object with only the fields that the file contains. The other fields keep their values. The file can therefore manage a few settings of an object, such as the redirect URLs of an application, while you edit the rest in the admin console
WatchCasdoor checks the file every initDataWatchInterval seconds and applies it again when the content has changed, without a restart
PasswordsCasdoor uses the password of a user only when it creates the user, so users can change their passwords afterward. Casdoor writes organization secrets, such as masterPassword, on every apply when the file contains them
Removed objectsCasdoor doesn't delete objects that you remove from the file
Runtime dataCasdoor skips records and sessions in merge mode
ErrorsIf an object fails to apply, Casdoor logs the error once and keeps running with the objects that it applied up to that point. It retries the file on every check until the file applies
ヒント

terraform plan、既存オブジェクトのインポート、ドリフト検出が優先される場合は、Terraform プロバイダーを使用してください。API 経由で同じオブジェクトを管理します。

データの書き出し​

バックアップまたはマイグレーションのために、Casdoor インスタンスのすべてのデータを JSON ファイルに書き出します。

バイナリでの書き出し​

-export フラグを使用して Casdoor を実行します。これが推奨される方法です。バイナリ、Docker、Kubernetes のいずれでも機能し、Go ツールチェーンは不要です。

# Export to default location (init_data_dump.json)
./casdoor -export

# Export to a custom path
./casdoor -export -exportPath /path/to/backup.json

Casdoor はデータベース接続を初期化し、ファイルを書き込み、終了します。

ソースからの書き出し​

Casdoor ソースツリーで以下を実行します:

go test ./object -v -run TestDumpToFile

コマンドは object ディレクトリに init_data_dump.json を作成します。

書き出したデータを別のインスタンスに読み込む​

  1. init_data_dump.json を init_data.json に名前を変更します。
  2. ファイルを、対象の Casdoor インスタンスが実行されるディレクトリに配置します。
  3. 対象インスタンスを起動します。起動時にデータが読み込まれます。
